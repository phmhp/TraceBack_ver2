# SCENARIO / BRANCH / QA — 사건 01 상세 실행 계약
**상태:** 기획용. 공식 모델 신호/가설 원인 검증 후 콘텐츠 데이터로 잠금.

## A. 장면별 대사·행동·공개 시점
| 비트 | 사용자에게 보이는 연출/대사(초안) | 의도한 조작 | 데이터 공개 조건 | 성공/오답·막힘 |
|---|---|---|---|---|
| 00 개조 차고 | 드라이버: "오늘은 경찰차보다 빨리 달릴 수 있지?" / 엔지니어: "달리기 전에, 이 차가 어떻게 움직이는지부터 보자." | 운전자 입력 토큰→SW 제어→모터/차량 출력 순서 조립 | 시작 즉시; 개조 완료 후 차량 test motion | 틀림 시 연결점 흔들림, 3회 뒤 안내선을 제공 |
| 01 첫 도주 | 드라이버: "출발! 항구까지 간다!" / 저택에서 보안 차량 출현 | 코너 2회·컨테이너 회피·브레이크 | 첫 20초는 정상차량 속도/페달 감각만 | 충돌→압박 증가, 같은 구간 재진입 가능 |
| 02 고장 cue | 드라이버: "분명 밟고 있는데… 차가 안 나가!" | 계속 운전하며 증상 느끼기 | incident trigger 후 페달 입력/차량 응답 차이 2초만 강조 | 못 봤으면 replay 자동 해금 |
| 03 첫 진단 | 엔지니어: "기록을 먼저 봐야 해. 원인을 결정하긴 일러." | 최근 4~8초 리플레이 3 지점 중 선택 | 정상/이상 비교 2조각 순서로 | 잘못 선택→유용한 시점 강조; 시간 만료→보관 |
| 04 기억 단서 | 엔지니어 기억: "경고가 원인이 아니라, 보호 반응일 수도…" | 흐릿한 정비 메모 퍼즐조각 선택 | 첫 관측 단서 2개 획득 시 | 메모 무시해도 추리 가능, 초심자 힌트 제공 |
| 05 HW/SW trace | 드라이버: "그러면 어디에서 힘을 줄인 거야?" | 실제 부품 토큰/ECU 판단 토큰 연결 | 선택한 부품에서 입력-판단-명령-동작 3열 | 포트 반대면 유형 피드백, 설명 1문장 |
| 06 증거 보드 | 엔지니어: "같은 증상이라도 원인은 다를 수 있어." | 관측→가설 지지/반박 연결 | 2개 기본 관측+기억 추가 단서 | 첫 실수는 관계 오류만 표시, 3회 뒤 힌트 |
| 07 가설 | 드라이버: "모터가 망가진 거 아냐?" / 엔지니어: "가능성은 있어. 하지만 확인하자." | H1/H2 중 우선 가설과 비교 실험 고르기 | 최소 두 가설의 차별 신호가 실제 모델에 있을 때만 활성 | 실제 모델에서 구분 불가→콘텐츠 구성 오류 처리 |
| 08 심상 실험 | 엔지니어: "같은 조건을 머릿속에서 한 번 돌려보자." | 숫자 입력 없이 실험 카드 2~3개 중 하나 선택→결과 패턴 예상 | 예상 확정 전 trace 본문 미공개 | 잘못된 실험→구분 불가 결과, 새 정보/재선택 |
| 09 반전/검증 | 엔지니어: "고장은 여기일 수도 있지만, 차가 스스로 제한했을 수도 있어." | 서로 다른 예상/관측선 비교·가설 갱신 | 실험 데이터 유효할 때만 | 가설 반박→기존 증거 보존, 압박 증가; 정답은 점진 공개 |
| 10 선택 조치 | 드라이버: "제한을 없애면 빨라지잖아!" / 엔지니어: "안전을 위한 제한이면 함부로 끌 수 없어." | 안전한 조치 카드 선택 | 충분한 증거/검증 후 | 보호 해제 카드 없음. 부적절 조치→제한 경로 유지 |
| 11 머릿속 회귀 | 엔지니어: "수정 조건에서도, 정상 조건에서도 괜찮은지 보자." | 고장/정상 두 시나리오를 토글 비교 | 조치 이후 | 한쪽 실패→조치 수정/보수적 탈출, 아무것도 학습 막지 않음 |
| 12 해적선 탈출 | 드라이버: "저 배야! 마지막 커브!" | 직접 운전·좁은 램프 진입·부스트 토큰 사용 | regression 또는 검증 보류 결과 | 잡히면 checkpoint, 보호 제한 시 다른 안전 경로 안내 |
| 13 결과 | 두 고양이 짧은 대화 + 보드에서 주요 3개 연결 재등장 | 사건 결과/학습 3가지 확인 | 성공/실패/보류 | 정답/운전 성적 별도 평가, 재도전 버튼 |

## B. 플레이어 선택의 실제 결과 계약
| 선택/사건 | Immediate UI | 상태/압박 영향 | 다음 허용 행동 |
|---|---|---|---|
| 정상 코너 통과 | wheel/roll/camera 반응 | pressure -2 (구간 최대 -6) | 계속 주행 |
| 충돌 | 카메라 흔들림/타이어 미끄럼 | pressure +8, 실제 차 상태는 선택된 게임모델 기준 | 계속 주행 또는 checkpoint |
| 필수 단서 획득 | 물리 카드 snap | evidenceId unlock; pressure 변화 없음 | 다음 단서/가설 |
| 가설 근거 관계 정확 | 연결선 밝아짐 | pressure -7 (같은 관계 중복 보상 없음) | 계속 추리 |
| 근거 관계 오답 | 연결선 되튐 | 첫 오답 pressure +3, 동일 오류 반복은 +0 | 바로 재시도 |
| 가설을 근거 없이 확정 | 불안한 엔지니어 표정 | pressure +9 (1회) | 반증/실험 |
| 분별력 있는 실험 선택 | miniature sim boot | pressure -6, experimentId 저장 | 결과 확인 |
| 정보가 없는 실험 선택 | 구분되지 않는 두 결과 | pressure +5 (1회), 새로운 힌트 | 실험 다시 고르기 |
| 정신적 시뮬레이션 데이터 오류 | 빨간 공구 아이콘과 오류 | pressure 변화 없음 | 기록된 유효한 데이터로 재실행/중단 |
| 안전 조치 선택 | 보호 icon + vehicle change 설명 | 정상/제한 경로로 이행 | regression |
| 추격 pressure >=100 | 경찰/부자 차량 접근 연출 | Caught | checkpoint 재도전/쉬운 모드 |
| timed microtask 만료 | 카드가 접혀 기록 슬롯에 들어감 | pressure +4 (1회, 오답 아님) | 계속 진행/나중에 리플레이 |
| Focus lost/Pause | UI frozen | pressure 고정 | 재개/종료 |

**밸런스 주의:** 숫자는 잠정 게임 파라미터일 뿐 EV 실물 측정 값이 아니다. 중간검토 플레이테스트 후 반드시 조정.

## C. 미리 결정한 실패 복구/에러 QA
| ID | 검수 시나리오 | 기대 결과 |
|---|---|---|
| QA01 | 첫 시작 | 2마리 고양이 → 개조 안내 → 도주로 진입 |
| QA02 | 개조 SW 순서 3회 오류 | 누락된 경로만 안내, 전체 정답 자동 공개 안 함 |
| QA03 | 주행 도중 2회 연속 충돌 | 입력 유지되고 checkpoint로 회복, 필수 단서 소실 없음 |
| QA04 | 고장 경고를 놓침 | 리플레이에서 원인 아닌 현상 재확인 가능 |
| QA05 | 단서 1개만 수집 | 필수 2개를 replay에서 재획득 가능 |
| QA06 | 압박 중 가설을 틀림 | 가까워지는 추격 연출과 반증 새 단서, 게임 이어짐 |
| QA07 | 계속 선택을 틀려 압박 100 | Caught 연출 후 안전 checkpoint, 사건 저장 유지 |
| QA08 | 조사 중 타이머 만료 | 자동 보관 후 다음 단계, 오답 단정 안 함 |
| QA09 | 정확한 수치가 필요하지 않음 | 실험카드만 선택, 텍스트/숫자 입력 0개 |
| QA10 | 실험 데이터가 누락됨 | MODEL_ERROR, 플레이어 점수 페널티 없음 |
| QA11 | 추적용 로그/신호가 샘플시간 다름 | 무단 오버레이 금지, 데이터 검증에서 오류 처리 |
| QA12 | 정상 검증 통과, 고장 검증 실패 | 안전 복구 미승인, 회귀 실패 표시 |
| QA13 | 정상 조건 회귀 실패, 고장 조건 통과 | 실패 설명 후 조치 수정 또는 제한된 탈출 |
| QA14 | 주행만 잘하고 추리 못함 | gameplay 진행은 가능하나 검증 점수/결말 구분 |
| QA15 | 추리 잘하고 운전 실패 | 검증 성취 유지, 탈출 checkpoint에서 재도전 |
| QA16 | 나쁜 주행 실력 | 필수 단서는 100% 접근 가능, optional clean-drive 단서만 차별 |
| QA17 | 모바일 크기/작은 창 | 지원범위 밖 안내 또는 UI 최소 크기 대응, 잘린 필수 CTA 없음 |
| QA18 | reduced motion | 카메라 흔들림 비활성, 추격/고장 시각+텍스트 정보 유지 |
| QA19 | 3D 부품 asset 미확인 | 물리 구조라는 허위 주장 금지, educational abstraction 표기 |
| QA20 | 신규 scenario data key 누락 | 해당 사건만 로딩 실패, 앱 타이틀/다른 사건 정상 |

## D. 교육용 최종 확인 과제 (플레이 종료 뒤 인터랙티브 3개)
1. 왜 차가 느려졌는지 '운전자 입력'과 '실제 반응' 카드의 관계로 설명.
2. 엔지니어링 단서 중 무엇이 두 후보를 구분했는지 하나 선택.
3. 정상 조건까지 회귀검증하는 이유를 보여주는 2장면 중 적절한 그림 고르기.
이 평가는 외워서 답하는 퀴즈보다 이미 수행한 행동의 재확인이다.
