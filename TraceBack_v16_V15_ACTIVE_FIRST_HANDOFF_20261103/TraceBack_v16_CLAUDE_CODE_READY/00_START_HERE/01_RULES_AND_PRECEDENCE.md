# 구현 우선순위 / 합의와 미확정의 경계

우선순위: (1) 이 문서 및 01_IMPLEMENTATION의 계약 > (2) 최신 v14 문서/실행기 > (3) 05_SCENARIOS의 승인된 JSON > (4) 02_UI_DESIGN의 Stitch 비주얼 > (5) 07_HISTORICAL_ARCHIVE 이전 제안.

### 확정된 목표
- 16:9 PC용 고양이 2명(드라이버/엔지니어)의 3D 아케이드 추격 레이싱 + 자동차 SW 고장 미스터리.
- 조향/가속/제동 직접 입력; 가속·감속·선회·충돌이 실제 변화하는 주행. 너무 빈 맵 금지. 항구, 시내, 해안, 컨테이너, 해적선까지 시각 밀도 유지.
- 차고지: 차량 전체 도메인 탐색 및 Vehicle/System → E/E → ECU SW Architecture → SW Detailed Design의 4개 설계 관점. 대표 구동 기능 1개만 필수 깊이 체험.
- 08-01 메모판 → 08-02 로직 작업대 → 08-03 쌍둥이 시험대. 화면 이름/번호는 임시 식별자, 실제 Stitch 디렉터리 이름과 혼동 금지.
- 관측→가설→고장 식별→요구사항 기반 로직 변경→시험 선택→판정/실패 분석→회귀→주행 복귀.
- 필수 2사건(가속, 열관리) + 제동 협조 선택형 3사건. 세 결함의 정확한 고장 원인·테스트 벡터·기대값은 아직 후보.
- v14 제어코어 재사용; 이전 엉킨 Git 전체 복원 금지. 최신 업데이트된 코어를 새 ZIP으로 받으면 adapter로 교체.
- 정식 AUTOSAR 구현, ISO26262 인증, HIL/PIL, 실제 양산 ECU 검증이라는 주장 금지.

### 미확정 — 임의 추론 금지
- 특정 화면/캐릭터의 최종 승인 버전(Stitch 다수 변형), 디자인 픽셀 수치, 고양이 색깔별 역할, 정확한 결함 정답·단위·임계값·주입 위치, 검증 시간 허용오차, 물리 수리 vs SW 복구, 자동차 모델 세부 물성.
- '무조건 2사건 발생'과 '조기 체포' 충돌: 플레이어가 두 사건을 **경험**한다는 것을 우선 보장. 구체 조기 체포 제한/체포 후 첫 시작 vs 체크포인트 규칙은 OWNER_DECISION 필요. 첫 빌드는 임시 선택을 `PROVISIONAL`로 명시.
- 레이싱 UI의 거리(m)를 쓰려면 경찰/차량의 실제 게임 월드 위치에서 계산. 게임 점수 P를 meter로 표기 금지.
- 실행 불가능한 임시 기술 데이터는 DEMO, UNVERIFIED, NOT_AVAILABLE을 표시하고 가짜 PASS 방지.

### 개발 기간 대응
첫 구현에서는 **한 사건 end-to-end**를 우선. 게임을 실제 실행할 수 있어야 하고 나머지는 정확히 구현/예정/미지원 구분. 빠진 기능의 mock 또는 stub은 표시해야 하며 완료라고 주장하면 안 됨.
