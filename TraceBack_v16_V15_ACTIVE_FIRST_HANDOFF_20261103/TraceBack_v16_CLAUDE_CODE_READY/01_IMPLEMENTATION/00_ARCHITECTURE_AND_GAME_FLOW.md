# 구현 목표 / 최종 플레이 흐름

### 게임 상태
TITLE → GARAGE → CHASE_NORMAL → FAULT_1_CUE → ASSIST_CHASE → BOARD → WIRING → TWIN_BENCH → (VERIFY_FAIL ↔ BOARD/WIRING/BENCH) → REPAIR_OR_SAFE_LIMIT → CHASE_RESUME → FAULT_2_CUE → BOARD → WIRING → TWIN_BENCH → CHASE → OPTIONAL_FAULT_3?(same loop) → SHIP_ESCAPE → ENDING.

게임의 진행 상태와 ECU 운용 상태(OFF/READY/DRIVE/DEGRADED/FAULT)는 서로 다른 상태기. 조사 UI 진입만으로 ECU 상태나 진단 래치 리셋 금지.

### 차고 튜토리얼
L1 시스템 기능/요구, L2 E/E 아키텍처 물리·통신 경로, L3 ECU 내부 SW 컴포넌트와 인터페이스, L4 상세 조건·상태·연산. 원칙적으로 11개 기능을 탐색할 수 있게 하되 구동 하나만 4층 필수 조작. 전체 시퀀스는 짧게; 개별 도메인 설명은 필요 시 열람.

### 메모판 08-01
관측 사실·검증 요구·가능 원인 2~3개, 지지/반박 증거 연결, 결정적 신호 관측 선택. 경고등=부품 고장으로 단정 금지. 선택 기록을 시나리오 상태에 저장. 정보 부족이면 INCONCLUSIVE와 재조사.

### 로직 08-02
자연어 요구사항 및 **일부만 드러난 설계 흐름**을 보고 HW 부품/신호/ECU 및 '한 문장 SW 판단·명령 블록' 4~6개 연결. 정답 순서가 완전히 드러난 흐름도 제공 금지. 연결 형식 오류와 논리 오류 구분. 논리 오류도 시험대 진입 가능. 단순 장식 그래프가 아니라 각 블록이 executor에서 계산되어야 함.

### 쌍둥이 시험대 08-03
검증 카드(정상/경계/고장/복귀) 선택 → 적용 입력/상태 요약 → 기대 결과 예측 → 같은 초기 상태/동일 시간축의 기준 및 플레이어 수정 모델 실행 → 로직 신호/ECU간 인터페이스/액추에이터 반응 비교 → 실패 위치 선택 → 수정 → 영향받는 정상·보호 요구 회귀 확인. '로직/신호 연동/차량 응답'은 관측 관점이며 공식 unit/integration/HIL 획득을 뜻하지 않음.

### 실패, 힌트, 종료
잘못된 가설은 반증을 제공하고 다른 신호·실험 선택 기회 부여. 형식 오류 배선은 배선 화면 수정, 논리 FAIL은 비교 후 해당 블록 복귀. MODEL_ERROR는 플레이어 오답 아님. 힌트는 방향 → 비교할 신호 → 판단 조건의 3단계. 오답 횟수만으로 학습 차단 금지. 정답/안전 제한 복구/미해결과 레이싱 결말을 분리.

### 월드 디자인
한 연결된 항구 맵: 도심 상점가→창고/컨테이너→해안도로→부두→해적선 램프. 근경 소품(가로등, 표지판, 차량, 화분), 중경(상점, 창고, 크레인), 원경(바다, 대형 선박, 스카이라인)을 함께 배치. 반복 텍스처와 단순 도로 하나로 대체 금지. 실제 3D 게임 카메라, 차선·커브, 조작 가능한 차량, 충돌과 추격 거리의 계산 필요.

### 콘텐츠 정책
기술적 수치, 판정, 고장 정답은 미승인 Scenario JSON을 실제 데이터로 표시하지 않음. 첫 데모에서 사용할 시나리오는 `EDUCATIONAL_DEMO`로 표시 가능. 플레이어에게 임의 숫자를 실제 ECU 측정처럼 소개 금지.
