# Screen routing and interactiveness

See `SCREEN_NAVIGATION_MATRIX.csv` (22 logical states) and `STITCH_REFERENCE_CANDIDATES.csv` (22 original visual reference folders; names are not approved IDs). These are different counts coincidentally. Do not assume one-to-one mapping. These are contracts to implement, NOT claims that all pages are coded.

- Global `CampaignState`: `scene`, `caseId`, `checkpointId`, `playerHypotheses`, `unlockedEvidence`, `activeProgram`, `attemptsByRequirement`, `modelError`, `raceOutcome`, `controlState`, `gameState`. Keep campaign and ECU state separated. In-memory state survives BOARD/WIRING/BENCH scene transitions; checkpoint serializes JSON-only campaign state, never arbitrary controller functions.
- `Navigate(event)` guarded reducer; `START_RACE` requires garage tutorial L4 propulsion complete and a valid boot route; `BENCH` is blocked for *type-invalid* block graph but not logically incorrect choices; `REPAIR` requires required normal, fault and protective regression tests plus correct root cause. `BACK` must not undo persistent ECU fault latches.
- BOARD: show 3 rivals and 2–4 dated observations, permit comparing independent signals, hide root-cause answer until evidence sufficient; incorrect hypothesis unlocks contradiction and an extra test rather than punitive dead end.
- WIRING: node categories `sensor`, `ecu`, `decision`, `actuator`. Typed ports include units, direction, update cadence; invalid edge `signal/command`, wrong units and loops get explicit error. **Current executable bridge supports only gateway preset mapping**, not a generic authored graph. GUI can stage a constrained selectable group of blocks which compiles into `nominal`/`underreport_45pct`; do not pretend arbitrary graph wiring changes runtime until graph execution implemented.
- BENCH: choose normal/fault/recovery cards; show raw pedal, gateway pedal, actual/command torque, time series, test verdict. `PASS` only if requirement oracle, safety regression, scenario conditions satisfied. The reference trace is not the oracle. Thermal hardware case uses command vs observed fan, with parked repair path.
- Driving: arrow/WASD or configurable keys, throttle W, brake S, steer A/D; automatic D after start tutorial; touch unsupported in approved PC slice; prevent browser page scroll while driving; pause on tab blur. Collision capture threshold configurable; after checkpoint retry preserve discovered clues, reset only race/vehicle state via explicit boot.
- Common state policy: `loading`, `ready`, `missing_data`, `invalid_connection`, `test_fail`, `test_pass`, `inconclusive`, `model_error`, `arrested`, `checkpoint_retry`; each interactive control has a disabled/error or active handler. Keyboard focus and accessible labels for puzzle controls.
- Copy displayed on main HUD at <=2 short Korean sentences, deeper terms through tooltips. Unit labels `Nm`, `N`, `%`, `°C`, `m/s`, `km/h` must match real source types. Error must show recovery action.
