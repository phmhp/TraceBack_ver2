## 0. 필수 정정: 이전 설계의 오류
1. **두 고양이:** F1 드라이버 고양이가 운전하고, F1 엔지니어 고양이가 진단한다. 플레이어는 두 역할을 모두 조작한다. '단독 고양이' 지시는 철회한다. 캐릭터 색상별 직무는 검토할 임시 기본안(드라이버=치즈냥이, 엔지니어=검은고양이).
2. **조사 중 시간:** 물리적으로 경찰차를 계속 시뮬레이션하며 주행과 동시에 복잡한 UI를 조작시키지 않는다. 드라이버가 차를 유지하는 **시네마틱 auto-pilot/슬로모션 주행 상태**로 전환하며, 추격 압박은 행동 결과와 짧은 결정 시간에 따라 **이산 단계**로 변한다. 계속 변하는 것처럼 보이는 시각 HUD와 실제 판정 수치는 구분한다. 이것이 위험하지 않은 기본안이다.
3. **가설 실험:** 자유 숫자 입력/제어 파라미터 직접 설정/수식 입력 전부 금지. 플레이어는 2~3개의 의미 있는 실험 카드에서 고른다.
4. **회귀검증:** 같은 현실 도주로를 여러 번 달려 실험하지 않는다. 엔지니어의 머릿속 **mental simulation/flashback lab**에서 사전 시뮬레이션 trace로 가설을 테스트하고 정상/고장 조건을 비교한다. 마지막 탈출 주행은 실제 게임 플레이.
5. **AUTOSAR:** 주교육/부교육/퍼즐 범위에서 제외. 기능안전은 보호 동작을 이해하는 게임 규칙으로만 구현.
6. **사전 개조 학습:** 도주 시작 전 고양이 둘이 차를 개조하는 40~75초의 인터랙티브 튜토리얼을 넣는다. 이것이 사건 해결 때 떠올릴 정보의 출처.
7. **화면 수:** 이전 18개를 독립 페이지로 구현하지 않는다. 5개 핵심 씬 + 5개 오버레이/서브모드로 유지해 몰입과 제작 효율을 확보한다.

## 1. 게임 기획 확정안
**한 줄:** 두 F1 출신 고양이가 개조한 EV로 부잣집을 털고 해적선까지 도주하는 동안, 주행 이상을 발견한 엔지니어가 기억 조각·차량 HW/SW 구조·단서를 연결해 원인을 추리하고 머릿속 시뮬레이션으로 검증하는 3D 레이싱 미스터리.

**주학습 목표:** (L1) 정상 요구와 비정상 응답을 구분한다. (L2) 운전자/센서 입력→ECU 소프트웨어 판단→명령→모터/액추에이터 동작을 연결한다. (L3) 경쟁 가설을 증거와 반증 가능 실험으로 평가한다. (L4) 보호 제한이 안전을 위해 의도적으로 활성화될 수 있음을 인지한다. (L5) 조치 이후 고장 조건·정상 조건에서 다시 확인해야 함을 이해한다.

**부학습:** EV 배터리/인버터/모터/회생제동·기본 신호 읽기, 테스트의 기대값과 관측값 구분, 드라이버/엔지니어 협업.
**확장:** 제동, 조향, BMS, 열관리, 고전압 전원, 충전. AUTOSAR와 규격 암기 없음. 3D 전체 차량 상세 모델과 실시간 co-simulation은 후속.

**세 가지 재미:** (a) 곡선·제동·장애물과 추격을 직접 조작하는 주행 (b) 증상·기억·물리 부품·신호 사이에서 모순과 규칙을 발견 (c) 자신이 고른 실험의 결과가 예상을 뒤집는 검증과 보상.

**첫 사건 예시(교육용 기획안, 모델 검증 전):** `풀 액셀이어도 차량이 더 이상 가속하지 않는다`. 후보 H1=구동계 전력 제약으로 의도된 토크 제한, H2=페달 신호 인식 문제. 실제 모델이 두 가설을 서로 다른 관측으로 구분하지 못하면 H2는 다른 검증 가능한 원인으로 교체. **현재 H1/H2와 신호 이름은 실제 MathWorks 모델에서 확인됐다는 주장이 아니다.**

## 2. 사건의 서사와 추리 반전 — 1사이클 상세
- **Act 0 / 개조 차고:** 드라이버가 '그 스위치가 가속을 더 올려주는 거지?'라고 묻는다. 엔지니어는 페달·제어 판단·모터의 순서로 구성된 세 부품을 조립하게 한다. 또 '차가 일부러 힘을 줄일 때도 있어'라는 정비 메모를 보게 한다. 이 메모는 후속 반전을 암시하지만 원인은 밝히지 않는다.
- **Act 1 / 도주 시작:** 절도에 성공한 고양이 둘이 경찰 및 부자 차량을 피해 항구 외곽을 달린다. 넓은 직선→컨테이너 장애물→두 번의 커브. 정상 상태에서 가속 감각을 익힌다.
- **Act 2 / 이상:** 차량은 가속 입력에 예전만큼 반응하지 않는다. 경고등/모터음/가속 변화가 일치한다. 원인명은 숨긴다. 별도의 화면 전환 없이 주행 중 이벤트 cue.
- **Act 3 / 엔지니어의 본능:** 드라이버 고양이가 '뭐야, 밟는데 왜 안 나가?!'라고 외친다. 엔지니어는 **움직이는 차 내부에서** 3개의 evidence micro-task를 수행한다: (1) 이전/현재 가속 반응 비교 (2) 관련 센서·부품 확인 (3) 흐릿한 기억 조각 복구. 이때 드라이버는 안전한 자율 주행 연출 상태로 유지, 추격 압박 게이지가 위협을 유지한다.
- **Act 4 / 미끼 단서:** 플레이어는 경고등을 보고 모터 자체 고장을 의심하기 쉽지만, 보호 제한 역시 유사한 증상을 만들 수 있음을 기억 조각으로 알게 된다. 경고는 직접 원인 증거가 아니라 차량 반응일 수 있다는 반전. **최종 정답은 공식 모델 추출 후 고정**.
- **Act 5 / 증거 조립:** 미니 작업대 보드에 `관측(페달 요구)`, `관측(차량 가속/구동 응답)`, `기억(보호 제한도 증상을 만든다)`, `추가 관측(구분 신호)`을 놓는다. 원인 후보 둘을 탭하고 `지지/반박` 형태로 연결한다. 복잡한 문자열 입력과 모든 단서의 손작업 연결은 금지.
- **Act 6 / 머릿속 실험:** '정상 조건 대 같은 입력의 이상 조건', '페달 입력 확인', '출력 제한 반응 확인' 등 **고정된 실험 카드 2~3개** 중 하나를 고른다. 어떤 실험이 두 가설을 구분하는지를 설명하는 1문장 예측 카드 선택. 숫자·솔버·모델 파라미터 입력 없음.
- **Act 7 / 반증:** 결과는 예상 trace와 관측 trace를 그래프와 애니메이션으로 비교한다. 틀린 가설은 왜 배제되는지 1~2개의 관측 사실로 설명한다. 새 단서를 제공하고 다시 시도할 수 있다.
- **Act 8 / 안전 동작:** 고장이라고 생각했던 출력 감소가 안전을 위한 제어 반응일 수 있다. 플레이어는 `출력 제한 유지하며 안전한 경로`, `원인 조건 해결 후 출력 회복` 중 실제 모델/사건에 타당한 조치 카드를 선택한다. 제한 무력화는 보상 수단으로 제공하지 않는다.
- **Act 9 / 회귀:** 엔지니어가 머릿속에서 같은 조건·정상 조건을 빠르게 재생한다. 변경 후 두 경우를 비교해 안전 동작이 유지되는지 확인한다. 이때 3D 차량 축소 모형과 신호 블록이 이어져 보인다.
- **Act 10 / 탈출:** 실제 레이싱 모드로 돌아와 해적선까지 마지막 커브와 좁은 램프를 통과한다. 원인 검증 결과는 차량 반응/안전 경로/추격 이득 중 확인된 부분에만 반영한다.
- **Act 11 / 결과:** 운전·추리·검증을 별도로 평가하고 3개 학습 인과를 요약한다.

**메모의 반전 설계:** `경고등 = 부품 고장`이라는 직관을 `경고등은 보호 반응일 수 있다`로 수정하는 추리. 원인 확정 이전에는 결론처럼 단정하지 않는다.

## 3. 게임 상태와 추격 규칙 — 임시 파라미터, 사용자 검수 대상
**주행:** `PLAY_DRIVE` (실제 입력/물리) → `FAULT_CUE` (계속 주행) → `ASSIST_DRIVE` (기본 autopilot 연출, 조작 진입 유예) ↔ `INSTANT_REPLAY` → `EVIDENCE_MICRO` ↔ `SYSTEM_TRACE` → `HYPOTHESIS` → `MENTAL_TEST` → `REGRESSION` → `PLAY_ESCAPE` → `RESULT`.

**압박 상태:** 단위는 실제 거리(m)가 아닌 추격 압박 점수 `P=0..100` (높을수록 위험), 화면에는 경찰차/부자차의 상대 위치와 시각화. `P>=100`이면 Caught. 거리(m)를 사용하려면 실제 위치기반 AI와 추격 물리가 있어야 하므로 P0에는 허위 m 단위 금지.

**잠정 수치:** 시작 P=35. 안전 주행 완료 −6, 충돌 +8, 조향 위험 +4(1구간 1회만), 증거 관계 맞음 −7, 잘못된 가설 확정 +9, 유용한 실험 +6(압박 감소가 아니라 `−6`), 근거 없는 실험 +5, 힌트 사용은 압박 변화 없음. 동시에 다수 패널티가 터질 때 1초당 한 번만 처리. 한 micro-task의 표시 시간 10~25초, 타이머가 끝나면 자동으로 보관하고 다음 안전 주행 cue로 넘어감(오답 확정 처리 금지). **실제 압박 수치/난도는 플레이테스트 후 수정, 이 값들은 개발 디폴트 초안이다.**

**조사 중 주행:** 운전 입력을 요구하지 않으면서 완전히 멈춘 느낌도 없게, `ASSIST_DRIVE`에서 차량·환경·추격 자동차의 카메라 이동을 보여준다. 물리 추격 AI가 정확히 계속 계산된다는 허위 주장은 금지. 퀴즈 타이머 압박 대신 짧은 task 전환과 pressure 피드백.

**Caught:** 추격 점수 100이면 2.5초 연출 → `RETRY_CHECKPOINT`(마지막 30~60초부터), 수집 증거/힌트 사용은 유지하되 해당 시도 점수만 리셋. 동일 실패 두 번이면 pressure 감소율 완화 및 `assist mode` 제안. 무한 막힘 방지.

**운전 실력과 증거:** 정상 운전 시 `quality=clean` 추가 관측 단서 1개 조기 해금. 충돌이 잦더라도 필수 단서 2개는 반드시 수집 가능, 부족한 optional evidence는 replay에서 볼 수 있음. 학습 진행을 실력으로 잠그지 않는다.

**부스트:** 발견/검증 보상은 `escapeBoostToken`으로 1회 소모형. 성능 제한을 안전상 이유 없이 강제 해제하지 않는다. 부스트는 게임상의 경로 이득/추격 압박 감소 보상이지 MathWorks 제어 로직의 물리 토크 증가라고 주장하지 않는다.

**화면 8계약:** 각 화면마다 목적/주요 행동/정보 우선순위/공개 조건/진입 상태/오류·막힘/행동 피드백/전환 조건을 UI 파일 `02_SCREEN_CONTRACTS.md`에 추가로 정의. 위 표는 최소 화면 목록이며 **완성된 와이어프레임이 아니다**.

**레이아웃 잠정 기준(데스크톱 16:9, 1920×1080 디자인 기준/비율 확대 축소):** 주행 3D viewport 최소 75%, HUD 상단 높이 80px 이내; 좌하단 속도/입력 260×140px, 우상단 chase 240×80px, 우하단 목적지 230×64px. 추리 S3 3D 차량/기억 55%, 단서/가설 35%, 항시 추격 HUD 10%; 글자 18px 본문/22px 버튼 최소 목표; 모바일 제작 범위 제외, 축소 시 스크롤보다 레이아웃 재배치. 수치 예시이며 실제 Figma/사용자 승인 전 수정 가능.

## 5. 3D/HW-SW 학습 통합
- 한 차량 Entity/ComponentGraph를 `Garage (예습)`, `Race (현상)`, `Engineer Mind (원인 탐색)`, `Mental Sim (검증)`이 공유한다.
- 물리 연동: 실제 구성 부품(센서/배터리/인버터/모터/휠)을 카메라 orbit·cutaway·select. 실제 모델/에셋 없는 부품을 있는 것처럼 그리지 않는다. 없는 경우 2.5D 분해 일러스트는 명시적 educational abstraction.
- 시각 언어: **기계/전력 경로** 실선, **제어 신호** 점선/다른 명도, **관측 trace** 물결선. 색만으로 구분하지 않는다.
- `vehicle-logic-lab`에서 확인된 그래프/포트/블록 아트가 있으면 재사용; Simulink 블록을 그대로 복제하는 것이 목적 아님.
- 초심자용 onboarding: 원인 지식의 70%는 차고의 세 가지 짧은 상호작용으로 예고, 나머지는 조사 중 문맥에 맞춰 해금. 이는 콘텐츠 배분 목표일 뿐 수량화된 시험 결과 아님.

## 6. Map / asset / animation budget
**항구 맵 한 개, 6개 세그먼트:** 차고 출구(입력 튜토리얼) → 창고/컨테이너(회피) → 연속 커브(핸들/제동) → 경광등/경비차 등장(압박) → 고장 관찰용 넓은 도로(시야 확보·중첩 obstacle 없음) → 선박 램프/결승(마지막 숙련도). 전후반은 동일 맵 리소스 재사용하되 조명/사건 cue/장애물 배치를 달리한다.

**반드시 실제 움직이는 요소:** wheel spin, steer orientation, chassis pitch/roll, chase camera damping, target pursuit position, 1~2종 near-miss/impact cue, cat idle/ear/tail/steering lean, signal pulse, evidence snap, trace scrub, card flip, mental-sim transition, ship reveal.
**잠정 애니메이션 값:** 상호작용 스냅 120~240ms, 메뉴 전환 180~350ms, 차고 부품 explode 450~800ms, 카메라 컷 350~650ms, incident warning 300~600ms. 서스펜션/조향/카메라 반응은 FPS 독립적 damping·blend로 구현. 실제 엔진에서 검증하고 수치를 조정.
**아트:** 포근한 파스텔 3D/아이보리·세이지·웜오렌지·하늘색의 계층, 도로/장애물은 명도 대비 강화. 두 고양이는 눈=검은 점 2개/넓고 둥근 얼굴/분명한 짧은 목/큰 머리와 작고 말랑한 몸/짧은 팔다리. 원본 face asset 최우선. Animal Crossing/Chiikawa는 스타일 감성만, IP 복제 금지. 음악앱·SaaS 카드 UI 금지.

## 7. MATLAB / 실제 기술 근거 / 라이선스
- 현재 MATLAB R2026b 및 Powertrain Blockset, Simulink, Stateflow, Simscape 등 설치 확인(사용자 `ver`).
- 기존 `traceback` 및 `vehicle-logic-lab` 코드의 **정확한 경로/구성은 아직 확인되지 않음**. 이전 AI 산출물 경로를 실제 소스 경로라고 거짓 작성 금지.
- 최초 후보 MathWorks 공식 EV reference application. 실제로 실행 가능한 모델 1개를 선정하고 신호/블록/출처를 확인할 것. 자동 생성 C 코드 전체를 Claude에게 던지지 않는다. 신호 map, 간소한 블록 그래프, 정상/이상 trace, 실험 결과만 준다.
- 실험은 학교 MATLAB이 가능한 Mac에서 기록된 trace를 export, 런타임 게임은 독립 실행. `RECORDED SIMULATION` 표시. 완전한 차량 물리, 안전 인증, 실시간 co-sim을 주장 금지.
- 배포 전 **예제별 라이선스, 생성 코드/모델의 재배포 권리, 학교 라이선스 조건, 외부 공모전 제출 조건**을 따로 확인한다. 공식 문서라고 무조건 재배포 가능한 것은 아니다. 확인 전에는 자체 제작 도해/퍼즐과 추출한 최소 관측 데이터만 후보로 두되 데이터 반출 가능성도 확인.
- 기능안전은 '잘못된 제한 해제는 위험'처럼 왜 보호가 필요했는지 추리하는 게임 규칙으로 구현. ISO 26262 인증이나 AUTOSAR 아키텍처 교육/코드 생성 제외.

## 8. 확장 아키텍처 / 오류 계약
**하나의 common runtime:** `ScenarioPack`은 `scenarioId, vehicleGraphId, faultId, trackId, observationIds, evidenceIds, hypothesisIds, discriminatingExperimentIds, safetyActions, outcomes, learningObjectiveIds, modelProvenance`를 갖는다. 신규 도메인은 pack+asset+trace만 추가하고 화면 코드를 복제하지 않는다. 다만 첫 미션 구현 전 거대한 추상 프레임워크 금지.

**결과:** `VERIFIED`, `REFUTED`, `INCONCLUSIVE`, `MODEL_ERROR` (가설 평가). 테스트 요구 결과의 `PASS/FAIL`과는 구분해 사용. 'FAIL'이 곧 가설 반박이라는 오해를 막는다.

**예외 계약:** collision→차량 피드백/압박 +8/체크포인트; road exit→3초 안내 후 부드럽게 복귀; 추리 시간 초과→선택 보관 후 다음 구간/해당 단서 복구 가능; 증거 부족→replay에서 2개 필수 단서 보충; 가설 오답→반증 + 힌트 + 압박 증가, 즉시 정답 노출 금지; 모델 trace 누락/NaN/단위 불일치→MODEL_ERROR 및 내장된 검증된 fallback만 허용; 추격 잡힘→재도전/최근 증거 유지; pause/focus loss→상태·타이머 정지; 저장 누락→새 게임 및 오류 안내; 애니메이션 중 상태 전이→기존 tween cancel + 다음 상태 기준 blend; 키보드와 마우스 초점 충돌→ASSIST_DRIVE에서는 주행 입력을 요구하지 않는다.

**QA:** 3회 연속 처음→결말 무중단 플레이; 틀린 가설 분기→복구; 타이머 초과→진행; 충돌/잡힘→재도전; 실험 데이터 누락→게임 오류 처리; 고장 조건 해소/정상 조건 회귀 둘 다 재생; FPS/조작 응답 측정; 대상 초심자 1인과 전공자 1인 think-aloud 플레이테스트(가능하면).
