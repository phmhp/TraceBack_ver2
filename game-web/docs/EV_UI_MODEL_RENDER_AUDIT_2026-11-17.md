# TraceBack EV UI·3D 모델·렌더링 교차검수 보고서

작성일: 2026-11-17  
대상: `game-web` 현재 코드와 1600×900 자동 브라우저 캡처  
판정 원칙: 코드 확인·화면 확인·거동 확인·공학적 추론·미확인을 분리한다.

## 1. 이번 점검 범위

- 정비소 최초 진입, 전체 차량 3D 보기, 협조 신호, 영역·도메인·기능 보기
- 전체보기의 실제 부품 인스턴스, 차체·휠·현가·ADAS 위치와 중복
- 도메인 3D 보기와 배선 보기
- 부품 더블클릭 → 단품 검사 화면의 모델 ID 전달
- 도미노 증거·역추적·가설 후보 패널
- 1600×900에서 문서 전체 페이지 스크롤·박스 범위·우측 패널 범위
- 빌드·기존 기능 테스트·레이아웃 감사

## 2. 이번 수정에서 확인된 핵심 원인과 반영

### 2.1 부품 더블클릭이 옛 기본 도형으로 열리던 원인

기존 전체보기는 중복 제거용 인덱스를 `PlacedPart`의 체인 인덱스로 재사용했다. 그래서 실제로 클릭한 `traction_motor`, `inverter` 등의 ID 대신 잘못된 체인 항목을 `PartInspector`가 조회할 수 있었다.

현재는 다음 계약으로 고쳤다.

```text
화면 인스턴스 → inspectId(실제 part model ID) → PartInspector → FittedPart
```

`VehicleLayout.tsx`의 `VehiclePlatformOverview`와 `PlacedPart`, `experiences.tsx`의 `GarageFlowPart` 및 `PartInspector`가 같은 ID를 전달한다. 전용 모델이 없는 경우에는 컬러 기본 도형을 표시하지 않고 `3D 에셋 미연결` 검수 표식으로 남긴다.

### 2.2 협조 신호 버튼이 무반응이던 원인

최초 전체 3D 화면은 이미 overlay 렌더 경로에 있었지만, 버튼이 별도 콘텐츠를 열지 않았다. 현재 클릭 시 `garageCoordOverlay`가 열리고 `COORD_SIGNALS`의 송신 도메인·수신 도메인·신호명이 표시된다.

### 2.3 전체보기 배선 보기

전체 차량 배선은 임의의 화면선이 아니라 `layoutOf(domain, 0).segments`와 각 모델의 `anchors`를 사용한다. 동일 경로는 중복 제거하고, 실제 `from`/`to` 포트 앵커를 변환해 표시한다. 배선 보기에서는 정지 상태의 색상만 보여주며, 시험 입력 전 임의 펄스 애니메이션은 실행하지 않는다.

### 2.4 차체와 휠

전체보기의 차체 투명도는 너무 낮아 상부 차체가 사라져 보였으므로 실제 차체 외형이 인식되는 강도로 조정했다. 휠은 공통 차량 문맥의 전륜 좌우·후륜 좌우 네 인스턴스가 `CAR_DIMENSIONS.frontAxleZ`, `rearAxleZ`, `wheelX`, `wheelRadius` 기준으로 생성된다.

## 3. 정비소 3D 모델 교차검수

### 3.1 기준 좌표와 인스턴스

코드상 차량 기준은 다음과 같다.

| 항목 | 코드 기준 | 판정 |
|---|---:|---|
| 전륜 차축 | `z=-1.18` | 코드 확인 |
| 후륜 차축 | `z=+1.16` | 코드 확인 |
| 휠 중심 좌우 | `x=±0.745` | 코드 확인 |
| 차량 좌표 높이 | `y` | 코드 확인 |
| 운전석 핸들 | `x=-0.31` | 코드 확인, authored 축은 화면 수동 확인 필요 |
| 계기판 | `[-0.4, 0.82, -0.3]` | 코드 확인, origin·시선축은 미확인 |

### 3.3 잘못된 매핑 방지

- `너클 → wheel` 오매핑을 제거했다. 너클 전용 에셋이 없으므로 누락 상태로 기록한다.
- `조향각 센서 → steering_wheel` 오매핑을 제거했다. 핸들 본체와 센서는 다른 기능이다.
- 전용 모델이 없는 센서·pawl은 실제 부품처럼 보이는 기본 도형으로 대체하지 않는다.
- `VehiclePlatformOverview`의 wheel·body·drive shaft 중복 정책은 유지하되, 구동 topology에서는 좌우 반축 링크를 별도로 표시한다.

## 4. UI·레이아웃 교차검수

### 확인된 통과 항목

- 1600×900 전체 페이지 `scrollWidth=viewportWidth`, `scrollHeight=viewportHeight`
- 도미노 캡처에서 페이지 overflow 없음
- 세부 단계 이전/다음 버튼이 표시됨: `이전 세부 단계`, `다음 세부 단계`
- 도미노 하단 선택 카드가 이미지·설명·영향 버튼을 하나의 고정 카드로 구성
- 폴라로이드 사진 창에 `aspect-ratio: 1 / 1`, `object-fit: contain` 적용
- 정비소 주요 버튼·카드에 동일한 `padding: 10px` 계약 적용
- 정비소 도메인 선택 화면에서 하단 영역 선택 카드가 화면 안에 들어옴

### 현재 캡처에서 남은 문제

정비소 도메인 화면은 기능 흐름을 보여주는 하단 패널과 우측 기능 선반을 함께 사용하는 구조라, 캡처상 우측 선반 내부에 6px 높이 overflow가 남아 있다. 이는 다음 작업에서 선반의 grid row와 하단 flow panel의 높이를 같은 측정 기준으로 재조정해야 한다.

### 아직 브라우저 수동 확인이 필요한 항목

- 실제 마우스 hover로 3D 부품 하나씩 선택할 때 클릭 영역과 시각 모델의 면적이 일치하는지
- 핸들·계기판·ADAS 카메라의 authored local axis와 최종 화면 방향
- 배선 보기에서 각 포트의 접점이 모델 외형을 관통하지 않는지
- 퍼즐의 실제 마우스 drag 경로가 시작부터 끝까지 연속인지
- 모든 팝업을 열고 닫은 뒤 배경 dim/중앙 정렬이 유지되는지

## 5. 에셋 상태

### 신규 제작이 필요한 필수 검토 후보

| 후보 | 현재 상태 | 추천 표현 |
|---|---|---|
| 조향각 센서 | 독립 모델 없음 | steering column 내부 통합 센서 링 또는 독립 센서 모델 중 하나를 승인 후 구현 |
| 냉각수 온도센서 | 독립 모델 없음 | 냉각수 매니폴드/호스에 체결되는 probe |
| park pawl | e-axle 내부 모델 없음 | 외부 전체보기에는 숨기고 e-axle 단면/exploded view에서 표현 |

### 선택형/신호형 후보

- 휠 가속도센서 4개: `cdc_full_corner_option`을 채택할 때만 필요
- chiller: 열관리 선택 사양을 확정할 때 필요
- gateway ECU·진단 포트·외부 충전기: 기존 ECU 재사용 또는 signal/external 오버레이로 우선 표현 가능

현재 신규 에셋은 만들지 않았다.
