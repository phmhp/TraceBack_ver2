# 처음 하는 플레이어 기준 점검 · 추리게임 품질 개선안 (2026-11-08)

기준 플레이어는 게임과 차량을 처음 접하는 사람이다(설명을 한 번 읽고, 모르는 단어는 넘기는 수준). 각 장면에서 "무엇을 하라는지 아는가", "왜 그런지 이해하는가"를 본다.

## 1. 장면별 따라가기

| 장면 | 플레이어가 받아들이는 것 | 막히는 지점 |
|---|---|---|
| 타이틀 | 이어하기와 새 게임이 분명함 | 없음 |
| 프롤로그 | 우승 → 누명 → 해고 → 되찾기 → 탈출, 한 줄씩 이해 | 없음 |
| 차고 | 튜토리얼로 "도메인 → 기능 → 관점" 순서는 앎 | E/E·Control SW·CAN·SWC 같은 낯선 단어가 많고, 무엇을 끝내야 다음으로 가는지 목표가 없음. 3D·E/E·SW가 따로 놀아서 같은 흐름이라는 걸 못 느낌. |
| 레이싱 | 조작, 경찰 추격, 효과음으로 긴장감 있음 | 고장이 나는 순간이 "왜 이게 문제인지" 감정적으로 약함 |
| 고장 감지 | 증상 한 줄과 경고등을 봄 | 없음(이번에 정리) |
| 원인 역추적 | 측정 → 먼저 달라진 것 따라가기를 반복하면 됨 | 카드 맞추기처럼 느껴짐. 차량 구조(E/E 판) 위에서 추리하는 감각이 없음. |
| 로직 퍼즐 | 요구사항을 보고 빈칸 채우기 | 단위 흐름 안내와 표 값 말풍선으로 나아짐. 다만 이게 범인 찾기와 어떻게 연결되는지 모름. |
| 시뮬레이션 검증 | 미션 A/B와 단계형으로 할 일은 앎 | 왜 이게 추리인지 약함. 관측점을 꽂고 결과를 확인하는 확인 작업처럼 느껴짐. |

## 2. 기준별 평가 (5점)

| 기준 | 점수 | 이유 |
|---|---|---|
| 차량 도메인 이해 | 2.5 | 데이터는 좋지만 보여 주는 방식이 정보 나열이다. 목표가 있는 체험이 아니다. |
| 검증적 사고 | 3.5 | 첫 불일치, 요구사항 기준, 레벨 선택, 회귀 시험까지 흐름은 맞다. 각 단계가 "왜"를 스스로 묻게 하지는 못한다. |
| 게임 흐름 | 3.5 | 순서와 튜토리얼이 생겼다. 단계 사이 연결 이야기(같은 사건을 쫓는다는 느낌)가 약하다. |
| 흥미·재미 | 2.5 | 레이싱과 효과음은 재밌다. 추리 단계는 실패해도 잃는 게 작고, 성공해도 반전이 없다. |
| 추리게임다움 | 2 | 용의자·알리바이·결정적 증거·지목 같은 추리 장르의 구조가 없다. |
| 메시지 전달 | 3 | "증상에서 원인까지, 검증으로 증명한다"는 엔딩에서야 드러난다. |

## 3. 시뮬레이션 검증은 지금 왜 추리처럼 안 느껴지나
- 플레이어가 **가설을 세우지 않는다.** 무엇을 의심하는지 정하지 않고 시험부터 돌린다.
- 결과가 **누구를 무죄로 만들었는지** 보이지 않는다. PASS/FAIL만 남는다.
- 관측점·레벨 선택이 **정보를 사는 결정**이 아니다. 비용 별점만으로는 긴장감이 약하다.

## 4. 추리게임 품질 개선안 — 세 단계를 하나의 "사건 파일"로 꿴다

> 2026-11-08 수정: 용의자·지목·반전은 필수가 아니다. 실제 반영 기준은 `IMPROVEMENT_PLAN_2026-11-08.md` 0절(가설 카드 · 증거 · 결론 근거)이다.
1. **용의자 카드(가설)를 처음부터 둔다**
   - 고장 감지 직후 용의자 5장을 사건 파일에 핀으로 꽂는다. 예(구동): 가속 페달 센서, VCU 계산, CAN 통신, 인버터, 모터.
   - 세 단계는 모두 이 카드를 "무죄"로 지워 가는 과정이 된다. 화면 위에 항상 남은 용의자가 보인다.
2. **원인 역추적 = 알리바이 확인**
   - 측정 하나가 용의자 하나 이상의 알리바이를 증명하거나 깬다. 예: "페달 센서 값 정상 → 페달 센서 무죄".
   - 측정은 추격 거리를 쓴다. 그래서 어디를 잴지가 추리가 된다(정보의 값).
   - 마지막에 "의심 구간 = 남은 용의자 2명"이 된다.
3. **로직 퍼즐 = 증언 대조**
   - 요구사항으로 "정상이라면 이래야 한다"는 기준 진술서를 만든다.
   - 다 맞추면 현장 차량의 실제 블록과 나란히 놓고, 다른 칸이 **결정적 증거**로 사건 파일에 붙는다. 예: 구동은 ×0.45 블록, 열관리·제동은 SW가 기준과 같다는 증거 → SW 무죄.
4. **시뮬레이션 검증 = 가설 검증·최종 지목**
   - 시작할 때 "누구를 의심하나요?"로 남은 용의자 하나를 고른다.
   - 그 용의자의 죄를 증명할 수 있는 시험(레벨·입력·관측점)을 설계한다.
   - 결과가 가설을 확인하면 지목 성공, 반증하면 그 용의자는 무죄 처리되고 다음 가설로 넘어간다.
   - 시험마다 추격 거리를 쓴다.
5. **반전과 함정**
   - 경고등, 운전자 진술("브레이크를 밟았던 것 같다"), 결과로 같이 변한 값 같은 오해 거리를 사건마다 하나씩 둔다.
   - 틀린 지목은 큰 "오답" 도장과 함께 경찰이 가까워진다.
6. **해결 보고서**
   - 마지막에 증거 사슬(증상 → 측정 → 기준 대조 → 시험 → 수정 → 회귀)을 한 장으로 보여 준다.
   - 이 장면에서 게임의 메시지가 선명해진다.

## 5. 재미는 어디서 오나 (설계 의도)
- **긴장:** 추격 거리 = 시간 압박. 측정·시험·오답이 모두 거리를 쓴다.
- **아하:** 가장 먼저 갈라진 신호, 기준과 다른 블록을 찾는 순간. 큰 도장으로 보상한다.
- **손맛:** 압정과 실, 조각 끼우기, 관측점 꽂기, 도장 찍기.
- **이야기:** 누명을 쓴 듀오가 실력으로 결백(차가 최고임)을 증명한다는 서사와 추리가 겹친다. 고장의 범인을 밝히는 것이 곧 자신들의 실력 증명이 된다.

## 6. 차고 개선 방향 (재설계안 4번 보강)
- 기능마다 **짧은 미션 3개**로 진행한다. 예: "페달 신호가 지나가는 부품 순서대로 누르기", "VCU 안에서 % → Nm로 바뀌는 블록 찾기", "토크 명령이 지나가는 통신 고르기".
- 미션을 끝내면 정비 노트 카드를 얻는다. 이 카드가 뒤 단계에서 용의자 설명으로 다시 나온다.
- 3D·E/E·SW는 같은 단계 번호로 함께 강조한다(재설계안 4).
