## 기술 답변
1. **주요 기능 목록 기준:** 기능은 E/E도 SW도 아닌 '도메인 아래 공통 기능'이다(예: 구동 › 운전자 토크 요청). 같은 기능을 3D(어디서), E/E(무엇과 연결), Control SW(왜 그렇게)로 깊이만 바꿔 본다. 코드도 `featureFlows[domain][feature].layers[0~3]` 하나에서 세 뷰가 나온다.
2. **계층:** System > E/E > Control SW 단일 트리는 맞지 않다. 도메인은 기능 분류, E/E는 연결 구조, Control SW는 구현이라 축이 다르다. 그래서 화면은 "차량 → 도메인 → 기능 선택" 아래에서 세 관점을 전환한다.
3. **도미노 역추적 ≠ FMEA·FTA·RCA:** 측정값을 신호 반대 방향으로 따라가 처음 어긋난 곳을 좁히는 관측 기반 역추적이다. FMEA는 설계 단계의 고장 모드 예측, FTA는 결과에서 원인 조합을 논리 트리로 푸는 분석, RCA는 재발 방지까지 포함하는 절차라 범위가 다르다.
4. **퍼즐의 목적:** 정상 기대값을 플레이어가 지어내지 않고 요구사항에서 도출해 검증의 기준(점선)을 만드는 것. 결과는 `sessionStorage tb-expect-<case>`로 검증에 넘어간다. 원인이 SW가 아니어도 E/E·부품 조각(출력단·팬·유압 모듈)이 들어가 '관찰 지점이 있는 정상 경로'를 만든다. 블록 배치는 논리 퍼즐이고, 어떤 시험으로 가설을 가를지는 검증 단계에서 고르는 진단적 추론이다.
5. **반례 ≠ 고장 기록:** 반례는 요구사항을 어기게 만드는 입력·상황이다. 검증 화면은 같은 입력으로 정상 모델과 고장 모델을 돌려 비교하므로 "고장 재현 시나리오"가 정확하다. 원 문구를 원하면 `VerificationLab.tsx`의 `bench-qa2` 한 줄만 바꾸면 된다.
6. **주행 조작·미션 (키 그대로):** ↑/W 가속, ↓/S 브레이크, ←→/AD 조향, 1~4 P·R·N·D(주행 중 P·R 금지, P 해제는 브레이크 권장 안내), Q/E 회생 단계 0~3, R READY 재시동, Esc 멈춤. 미션: 출발 시 브레이크+D, 추월 구간 끝까지 가속(사건 1), 신호 정지선 정차 → R 재시동(재주행), 장거리 고속 구간(사건 2), 수리 후 같은 조건 재주행(회귀). 추가 후보는 `FAULT_SCENARIOS` 5절.
7. **도메인 범위:** 플레이 가능 = 구동·열관리(+제동은 퍼즐·검증만). 시각화·오픈북만 = 조향·전원·변속·주차·현가(차고 3D·E/E·SW·조건 미션). 후속 확장 = `FAULT_SCENARIOS` 4절 후보.
