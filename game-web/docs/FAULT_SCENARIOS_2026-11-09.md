## 1. 현재 고장 3종 답지

### 1-1. 사건 1 · 구동 · 가속 저하 (경고등 없음)

| 구분 | 내용 |
|---|---|
| 전제조건(플레이어가 해야 할 것) | 차고지 → 범행·도주 컷신 → 첫 주행 시작. 출발 시 기어가 P라서 **브레이크(↓) 누른 채 4 → D**. 가속(↑)으로 달려 **추월 구간(150 m 지점)** 에 들어간다 |
| 플레이어에게 주어진 조건 | 화면 안내 "추월 구간 · 가속(↑)을 끝까지 밟아 추격차와 거리를 벌리세요" |
| 발생 조건(코드) | 추월 구간 안에서 가속을 0.25초 넘게 밟으면 증상 시작, 1.8초 밟았거나 330 m에 도달하면 고장 화면으로 전환 |
| 체감 현상 | 가속을 끝까지 밟아도 가속이 정상의 45% 수준, 속도가 잘 안 오름. 계기판 "출력 저하", 경고 말풍선 "가속 저하 발생". **경고등은 켜지지 않음** |
| 고장 팝업 | 볼트 "페달을 끝까지 밟아도 가속이 안나와! 경고등도 안떴는데! 왜이러지?" → 너트 "내가 만든 차가 이럴리 없는데! 내가 바로 고쳐볼게!" |
| 실제 원인(정답) | VCU 페달 처리 SW에 설계에 없는 **보정 계수 ×0.45** 블록이 들어가 있음. 페달 60% → 처리값 27% → 토크 요청 92 Nm (정상 204 Nm) |

**풀이 흐름 (답지)**

| 단계 | 화면에서 하는 일 | 정답 |
|---|---|---|
| ① 도미노 역추적 · 측정 | E/E 판에서 출력 쪽부터 눌러 잰다 | 차량 가속 2.8→1.2 m/s² 이상 · 인버터·모터(모터 토크 204→91 Nm) 이상 · CAN 토크 명령 204→92 Nm 이상 · VCU(페달 처리값 60→27%) 이상 · APS 이중 센서 60% **정상** |
| ② 처음 어긋난 곳 지목 | '처음 어긋난 곳 지목' → 부품 선택 (그 부품과 바로 앞 부품을 모두 재야 함) | **VCU** |
| ③ 의심 구간 3지선다 | 가속 페달 센서·배선 / **VCU 내부 (입력 회로·페달 처리·토크 계산)** / 인버터·구동 모터 | 가운데 |
| ④ 검증으로 넘기는 가설 | 페달 센서·배선 = 반박됨, 인버터·구동 모터 = 반박됨, **VCU 페달 처리 SW** = 판단 보류, **VCU 입력 회로(HW)** = 판단 보류 | — |
| ⑤ 로직 퍼즐 | 빈칸 3곳(4·6·7번 칸)에 조각 넣기 | 4번 **페달 맵(표 A: 60%→204 Nm)**, 6번 **가용 토크 MIN**, 7번 **램프율**. 함정: 페달 맵 표 B(60%→92 Nm), 토크 추정(인버터 안 블록) |
| ⑥ 검증 질문 1 "VCU 안 계산 SW가 잘못된 거야?" | 시험 고르기 → 실행 → 가설 판단 | **SW만 PC 시험(비용 1)** → 페달 처리값 낮음 → **가능성 높음**. 제어기·차량 시험 → 처리값을 볼 수 없음 → 아직 모름 |
| ⑦ 검증 질문 2 "VCU 입력 회로가 문제야?" | 같은 결과로 답할 수 있음 | SW만 PC 시험에서도 낮음 → 입력 회로 없이도 생긴 차이 → **가능성 낮음** |
| ⑧ 조치 | 3지선다 | **'보정 계수 ×0.45' 블록 제거**. 오답: 토크 지도 2.2배(증상만 가림), 모터 최대 출력 올리기(원인 아님) |
| ⑨ 재시험·재주행 | 같은 시험 → 통과 → 회귀. 재주행에서 가속 끝까지 1.5초 → 정상 기준 대비 85% 이상이면 "증상 재발 없음" | — |

### 1-2. 사건 2 · 열관리 · 파워다운(출력 제한)

| 구분 | 내용 |
|---|---|
| 전제조건 | 사건 1 수리 후 재주행. **550 m에서 신호 정지 미션**: 612 m 정지선에 멈춤(↓) → **R로 READY 재시동** → 출발. 이어 **장거리 고속 구간(760 m)** 에서 계속 가속 |
| 플레이어에게 주어진 조건 | "장거리 고속 구간 · 가속을 유지해 속도를 지키세요" |
| 발생 조건(코드) | 구간 안에서 가속 중 냉각수 온도가 초당 (12 + 속도×0.2)°C씩 오름. 80°C 이상이면 속도 55 km/h로 제한, 84°C 이상 또는 960 m에서 고장 화면 |
| 체감 현상 | 갑자기 힘이 빠지고 55 km/h 이상 안 나감, 계기판 "출력 제한", 경고 "파워다운 표시등 · 출력 제한" |
| 고장 팝업 | 볼트 "오래 달렸더니 힘이 빠졌어! 계기판에 출력 제한 표시등이 켜졌어! 왜이러지?" → 너트 같은 대사 |
| 실제 원인(정답) | **냉각 팬 모터 고착**. 팬 명령 100%, 커넥터 PWM·12 V 정상 도착, 회전 0 rpm → 냉각수 78°C → 구동계 보호로 출력 제한 |

|---|---|
| ① 측정 (E/E 판 순서: Thermal ECU → 냉각 팬 → 냉각수 온도 센서 → VCU → 차량 가속) | 차량 가속 이상 · VCU(출력 허용 100→62%) 이상 · 냉각수 온도 65→78°C 이상 · 냉각 팬 1850→0 rpm 이상 · Thermal ECU 팬 명령 100% **정상** |
| ② 처음 어긋난 곳 | **냉각 팬** |

| ⑧ 질문 3 "팬 자체 고장?" | 실제 부품 시험 → 팬 회전 낮음 + PWM·전원 정상 → **가능성 높음**. 제어기 시험은 팬이 모델이라 아직 모름 |
| ⑨ 조치 | **냉각 팬 모터 교체**. 오답: 팬 명령 100% 고정, 출력 제한 기능 끄기 |
| ⑩ 재주행 | 고속 가속 2초 → 냉각수 80°C 미만이면 "출력 제한 없음" |

### 1-3. 사건 3 · 제동 · 감속 부족 (선택 사건)

| 구분 | 내용 |
|---|---|
| 전제조건 | **현재 정상 플레이로는 도달하지 않음.** 레이스 고장 발생 코드가 없고(`OPTIONAL_BRAKE` 수락 버튼만 존재), 시작하면 도미노 역추적 없이 로직 퍼즐부터 열림. 개발용 주소 `?qa=WIRING&case=brake`로만 확인 가능 |
| 체감 현상(설계상) | 브레이크 55%에도 감속 1.4 m/s²(정상 3.2), 정지 거리 32 → 58 m, 브레이크 경고등 |
| 실제 원인 | **유압 경로 압력 전달 불량**: 명령 42 bar → 캘리퍼 입구 8 bar (19%) |
| 풀이 | ② 처음 어긋난 곳 = 유압 모듈레이터·캘리퍼 · ③ 의심 구간 = 압력 명령 이후 유압 경로 · ⑤ 퍼즐 빈칸 = 요구 수신 / 마찰 압력(표 A 2.1 m/s²→42 bar) / 유압 모듈 (함정: 표 B 8 bar, 슬립 임계) · ⑥ 배분 SW = 가능성 낮음(SW 시험 명령 같음) · ⑦ 유압 경로 = 가능성 높음(실제 부품 시험: 명령 같음·입구 압력 낮음) · ⑧ 캘리퍼 고착 = 가능성 낮음(입구 압력부터 낮음) · 조치 = 캘리퍼·유압 라인 수리 |

### 1-4. 검수 메모 (지금 발견한 것)
- 사건 3은 실제 플레이에서 나오지 않는다. 넣으려면 레이스 발생 조건을 만들어야 한다.
- 사건 2의 레이스 모델은 팬을 따로 계산하지 않고 "구간 안에서 가속하면 온도가 오른다"로 단순화되어 있다. 원인이 팬이어도 펌프여도 주행 체감은 같다 → 원인 구분은 측정 단계에서만 가능.
- 세 사건 모두 **고장 위치가 맵 구간(거리)으로 정해진다**: 추월 구간 150~330 m, 장거리 고속 구간 760~960 m.

## 2. 맵 종속 문제와 다양화 방법

### 지금 구조
`RaceExperience`(experiences.tsx)가 **거리 구간**으로 고장을 켠다. 사건 순서도 고정(구동 → 열관리)이다. 그래서 사건을 바꾸려면 맵 구간과 코드를 같이 손대야 한다.

### 바꾸는 방법 (갈아엎지 않고)
1. **발생 조건을 '차량 상태'로 정의한다.** 거리 대신 레이스가 이미 계산하는 값으로 조건을 쓴다: 속도, 가속 페달, 브레이크, 기어, 조향, READY, 회생 단계, 냉각수 온도, 경과 시간.
   - 예: "가속 페달 끝까지 0.25초" = 가속 중, "속도 0에서 브레이크 2초 후" = 정차 중, "R 재시동 시" = 시동, "조향 입력 중 속도 40 이하" = 저속 조향.
   - 맵 구간(추월 구간·신호등·고속 구간)은 그 상태를 **만들어 주는 기회**로만 쓴다.
2. **사건을 데이터 한 덩어리로 등록한다.** 지금 사건 하나는 7곳에 나뉘어 있다(아래 3절 표). 이를 사건 ID 하나로 모은 등록표(`SCENARIO_META` 확장)에서 읽게 하면 사건 추가 = 데이터 추가가 된다.
3. **레이스 고장 효과를 공통 '고장 훅'으로 만든다.** 이미 있는 훅(`pedalScale`, `fanStuck`, `brakePressureGain`)에 몇 개만 더하면 대부분 표현된다:
   - 출력 제한(최고속도 상한), 가속 배율, 제동 배율, 조향 응답 배율, 변속 거부(D 진입 불가), READY 거부(재시동 불가), 정차 유지 실패(밀림), 급제동 시 미끄러짐(차선 흔들림)
4. **사건 선택은 '주행 순서 슬롯'에 넣는다.** 1번 슬롯(첫 주행) = 가속 중 사건 중 하나, 2번 슬롯(재주행) = 정차·시동·감속 사건 중 하나처럼 정하면 랜덤이어도 튜토리얼 순서와 정답 데이터가 꼬이지 않는다. 첫 사건은 튜토리얼이 있으므로 고정하는 것을 권장.
