# TraceBack 화면 명세 V3

## 설계 원칙

- 표준은 검증 사고의 근거이며 화면 순서를 규정하지 않는다.
- 한 번에 하나의 질문과 하나의 행동을 제시한다.
- 그래픽과 상태 변화가 먼저 보이고 설명은 짧게 보조한다.
- 기존 네 단계와 주변 이야기 장면을 유지한다.

## STEP 01 차량 도메인 원리

- 질문: 같은 기능을 차량 위치, E/E 연결, 제어 판단 관점에서 어떻게 이해할까?
- 행동: 도메인/기능 선택 → OFF 상태 확인 → 조건 버튼 순차 인가 → 입력 유지 → 흐름과 액추에이터 반응 관찰.
- 피드백: 조건 누락 이유, 현재 흐름 종류, 최종 출력 도달 여부.
- 산출물: 정상 기능 기준, 사용 조건, 기대 반응.

## STEP 02 도미노 원인 역추적

- 질문: 관찰 가능한 증거에서 최초 편차가 나타난 경계와 유력 원인 후보는 어디인가?
- 행동: 우측 증거 확인 → 중앙 인과 경로 측정 → 정상/사건 값 비교 → 메모판에 가설 부착 → 근거 연결.
- 피드백: 확인한 사실, 반박된 후보, 아직 구분되지 않은 후보.
- 산출물: 가설 세트, 최초 편차, 관찰 근거, 추가로 구분해야 할 후보.

## STEP 03 요구사항 기반 로직·실험 퍼즐

- 질문: 선택한 가설을 구분하려면 어떤 조건, 입력, 관찰점, 기대 결과가 필요한가?
- 행동: 사건 유형에 맞는 블록을 단계적으로 배치하고 시험 계약을 완성.
- 피드백: 연결 의미, 관찰 가능 여부, 기대값 근거, 부족한 조건.
- 산출물: `ExperimentPlan`.

## STEP 04 시뮬레이션 검증

- 질문: 준비한 시험을 실행했을 때 어떤 결론까지 말할 수 있는가?
- 행동: 조건 확인 → 정상 실행 → 고장 재현 → 같은 축에서 비교 → 최초 편차/가설 판단 → 조치 → 같은 조건 재시험 → 회귀.
- 피드백: 시험 결과와 가설 상태를 분리해 표시.
- 산출물: 검증 기록, 근거가 있는 결론, 미확정 범위, 조치/재시험 결과.

## 주변 장면

- Title/Prologue/Drive/Fault/Repair/Ending은 기존 구조를 유지한다.
- 주행 기록은 STEP 02의 증거로 전달한다.
- 수리 후에는 동일 조건 확인 시험과 영향 범위 회귀 결과를 보여준다.
