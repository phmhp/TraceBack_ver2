# 복수 유효 시험 경로

## 평가 원칙

정답은 기법 이름이나 미리 정한 단일 버튼 순서가 아니다. 계획이 가설을 실제로 구분하는지 다음 다섯 축으로 평가한다.

| 축 | 질문 | 최소 조건 |
|---|---|---|
| 관련성 | 현재 가설과 요구사항을 직접 다루는가? | 하나 이상의 가설/요구사항 연결 |
| 관찰 가능성 | 선택한 값이 모델에서 실제 관찰 가능한가? | 존재하는 신호·상태·반응만 사용 |
| 판별력 | 경쟁 가설의 예상 결과가 달라지는가? | 최소 한 쌍의 가설을 구분하거나 한계를 명시 |
| 실행 가능성 | 현재 시뮬레이터가 조건과 고장을 재현하는가? | 유효한 초기 상태·입력·주입점 |
| 비교 가능성 | 정상과 사건 조건을 공정하게 비교하는가? | 잠금 조건 또는 차이 설명 |

## 결과 등급

- 충분: 현재 질문에 필요한 판별력을 갖춘 실행 가능한 계획.
- 부분 유효: 일부 범위는 확인하지만 원인 후보를 모두 구분하지 못함.
- 실행 불가: 모델에 없는 입력/관찰/고장 주입을 요구함.
- 무관: 현재 가설과 연결되지 않음.

부분 유효는 오답이 아니다. 실행 후 `실패 확인 / 원인 미확정` 또는 `추가 시험 필요`로 이어진다.

## 대안 경로 예

### 추진력 저하

- 경로 A: 페달 송·수신 비교 → 토크 요청 관찰.
- 경로 B: READY/기어/페달 조건 조합 → 허용 상태 관찰.
- 경로 C: 차량 감속/가속 반응만 관찰. 실패 확인에는 유효하지만 내부 원인 구분에는 부족.

### 열관리

- 경로 A: 온도 센서와 추정값 비교 → 냉각 요청 확인.
- 경로 B: 임계 전후 입력 → 상태 전이와 액추에이터 요청 확인.
- 두 경로를 순차 실행하면 센서/로직/액추에이터 후보를 더 좁힐 수 있다.

## 구현 방식

```ts
type TestEvaluation = {
  grade: 'sufficient' | 'partial' | 'not_executable' | 'irrelevant';
  discriminates: string[];
  cannotDistinguish: string[];
  observedScope: string[];
  missingEvidence: string[];
  suggestedNextActions: string[];
};
```

- 정답 배열의 완전 일치 대신 위 평가 결과를 계산한다.
- 행동과 기법은 다대다 매핑으로 저장한다.
- 여러 실행 결과를 누적해 가설 상태를 갱신한다.
- 첫 시험이 충분하지 않아도 진행을 막지 않고 다음 시험을 제안한다.
- 시험 결과와 원인 가설 상태는 서로 다른 UI 카드와 데이터 필드로 유지한다.
