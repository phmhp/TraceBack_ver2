# 표준 근거 추적 매트릭스

## 해석 원칙

이 문서는 표준이 말하는 **검증 대상·목적·활동**과 TraceBack이 선택한 **교육 표현·화면 흐름·조작법**을 분리한다. 표준은 게임 UI, 화면 순서, 버튼 배치, 정답 개수, 미니게임 규칙을 정하지 않는다. 그런 결정은 학습 목표, 인지 부하, 플레이 경험, 기존 자산 재사용성을 근거로 한다.

| 근거 | 공식 범위/목적 요약 | TraceBack에서 가르칠 개념 | 교육·게임 설계(표준 비규정) | 금지 표현 |
|---|---|---|---|---|
| ASPICE 4.1 SWE.4 | SW 단위가 상세 설계와 일치하는지 검증하고, 검증 수단·회귀 기준·결과·추적성을 관리 | 단일 로직의 입력, 조건, 계산, 출력 확인 | 블록 퍼즐, 경계값 슬라이더, 짧은 단위 실행 | “표준이 블록 퍼즐을 요구한다” |
| ASPICE 4.1 SWE.5 | SW 컴포넌트와 통합 SW 요소가 아키텍처/상세 설계에 맞는지 확인. 데이터 흐름, 동적 상호작용, 타이밍, 인터페이스 해석 포함 | 송신값·수신값·순서·타이밍과 컴포넌트 간 상호작용 | 신호 연결 퍼즐, 시간축 비교, 포트 강조 | “임베디드 탭이 SWE.5 그 자체다” |
| ASPICE 4.1 SWE.6 | 통합 SW가 SW 요구사항과 일치하는지 검증 | 요구사항의 조건·기대 결과·금지 동작과 통합 SW 결과 비교 | 요구사항 카드와 실행 결과 연결 | “SWE.6가 화면 순서를 규정한다” |
| ASPICE 4.1 SYS.4 | 시스템 요소를 통합하고 아키텍처와 일치하는지 검증. 인터페이스·상호작용·신호 흐름·타이밍 포함 | 센서–제어기–액추에이터와 시스템 요소 연결 확인 | 차량/E/E 하이라이트와 연결 경로 재생 | “SYS.4는 차량 애니메이션을 요구한다” |
| ASPICE 4.1 SYS.5 | 통합 시스템이 시스템 요구사항과 일치하는지 검증 | 운전 조건에서 차량 기능·반응이 시스템 요구사항을 만족하는지 확인 | 차량 반응, 계기판, 그래프를 한 화면에서 관찰 | “SYS.5와 고객 Validation은 같다” |
| ISO 26262-4:2018 | 안전 관련 E/E 시스템의 시스템 수준 제품 개발, 통합·시험·안전 검증 범위 | 안전 관련 시스템 시험은 명시된 안전 요구 및 오작동 위험 맥락을 가진다는 점 | 안전 개념은 도움말/출처에서만 정확히 한정 | 일반 성능 시험 전부를 ISO 26262 활동으로 표시 |
| ISO 26262-6:2018 | 안전 관련 SW 수준 제품 개발 | SW 안전 요구, 단위/통합/검증 관점의 구분 | 관련 시나리오에만 보조 근거 표기 | ASPICE SWE.4~6과 일대일 동일시 |
| ISTQB CTFL 4.0.1 | 시험 수준과 시험 기법은 별도 축. 명세 기반·구조 기반·경험 기반 기법을 구분 | 경계값, 동등 분할, 결정 테이블, 상태 전이, 오류 추정 등은 시험 행동을 설계하는 방법 | 기법 이름 객관식 대신 “입력을 조금씩 바꾼다” 같은 행동으로 제시 | 한 시험 수준에 한 기법만 대응한다고 표시 |

## 프로세스와 UI의 경계

| 결정 | 근거 유형 | 책임 주체 |
|---|---|---|
| 무엇을 검증하고 어떤 근거를 남길지 | 표준·요구사항 | 콘텐츠/검증 설계 |
| 4단계 학습 순서 | 교육 효과와 기존 게임 구조 | 게임 설계 |
| 한 번에 하나씩 선택지를 공개 | 인지 부하와 초보자 UX | UX 설계 |
| 증거 패널을 오른쪽에 고정 | 기존 사용성 문제와 사용자 결정 | UI 설계 |
| 버튼 크기·색·애니메이션 | 조작감·접근성·일관성 | UI/아트 설계 |
| 여러 유효한 시험 경로 허용 | 시험 설계의 비배타성과 교육 목표 | 게임 규칙 설계 |
