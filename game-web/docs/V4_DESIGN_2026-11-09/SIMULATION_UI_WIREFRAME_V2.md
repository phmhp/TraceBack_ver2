# 시뮬레이션 UI 와이어프레임 V2

## 기본 단일 화면

```text
┌────────────────────────────────────────────────────────────────────┐
│ STEP 04 시뮬레이션 검증     가설 요약       진행 3/6      도움말 │
├───────────────┬────────────────────────────┬───────────────────────┤
│ 실험 조건      │ 동적 차량/시스템 모델       │ 관찰·판정             │
│ READY [ ]     │                            │ 기대 / 실제           │
│ 기어  [D]     │   기존 차량 3D/애니메이션   │ 선택한 신호 3개       │
│ 입력  [---]   │                            │ PASS/FAIL/판정 불가    │
│               │ [실행] [정지] [초기화]      │ 가설 상태(별도)       │
│ 다음 행동 1개 │ 실행 상태·주입 위치 표시     │ 관찰 범위/한계         │
├───────────────┴────────────────────────────┴───────────────────────┤
│ 정상 기준 ━━━  사건 재현 ┅┅┅  동일 축·시간·단위  최초 편차 표시 │
└────────────────────────────────────────────────────────────────────┘
```

## 1054×723 기준

- 앱 헤더/단계 표시를 제외한 작업 영역 최소 높이: 600px.
- 본문 그리드: 좌 230px / 중앙 `minmax(360px, 1fr)` / 우 260px, 간격 12px.
- 하단 그래프: 높이 150~170px, 전체 3열에 걸침.
- 조건 칩은 한 줄 강제 배치하지 않고 `flex-wrap`; 레이블은 최소 폭 0과 2줄 허용.
- 주요 실행 버튼은 중앙 하단 고정 영역에 두되 그래프를 덮지 않는다.
- 오른쪽 판정 카드는 내부 스크롤을 사용하며 페이지 전체의 가로 스크롤을 만들지 않는다.
- 첫 진입 팝업은 최대 `min(680px, calc(100vw - 32px))`, 최대 높이 `calc(100vh - 32px)`와 내부 스크롤을 사용한다.

## 큰 화면(1280×720 이상)

- 좌 260px / 중앙 1fr / 우 300px, 그래프 180px.
- 중앙 모델을 키우되 좌우 패널의 의미와 조작 순서는 바꾸지 않는다.
- 정상/사건 3D를 강제 분할하지 않고 전환·겹쳐보기와 그래프 비교를 유지한다.

## 좁은 화면

- 900px 미만에서는 좌 조건 → 중앙 모델 → 우 관찰 → 그래프 순의 세로 스택.
- 실행 중 핵심 관찰값은 접힌 요약 바에 유지한다.
- 탭 전환 시 입력 상태와 실행 결과를 잃지 않는다.

## 상호작용 상태

| 상태 | 노출 요소 | 버튼 규칙 |
|---|---|---|
| 첫 진입 | 목적 팝업, 배경 비활성 | 닫기/시작만 활성 |
| 준비 전 | 가설과 STEP 03 계획 요약 | 누락 항목이 있으면 실행 비활성 및 이유 표시 |
| 정상 실행 | 현재 입력, 모델, 실시간 관찰 | 중복 실행 방지, 정지/초기화 활성 |
| 사건 실행 | 동일 조건 잠금, 주입 상태 | 비교 가능 조건 변경 시 경고 |
| 비교 완료 | 그래프, 최초 편차 선택 | 판정과 추가 시험 활성 |
| 조치 후 | 동일 조건 재시험 | 확인/회귀 결과를 분리 표시 |

기존 `TwinBenchExperience`의 단일 화면과 탭을 유지하며, 탭은 대상/관찰 관점 전환용이다. 탭마다 시험을 새로 시작하게 하지 않는다.
