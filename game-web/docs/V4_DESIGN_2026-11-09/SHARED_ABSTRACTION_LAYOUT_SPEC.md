# 세 관점 공통 프레임 명세

## 공통 그리드

```text
header
domain-tabs
perspective-nav | visualization | feature-list
flow-footer
```

세 관점은 같은 부모 컴포넌트와 CSS Grid 영역을 사용한다. 관점 전환 시 바뀌는 것은 `visualization` 내부뿐이다.

## 1054×723 기준 목표

| 영역 | 목표 |
|---|---|
| 헤더 | 전체 폭, 고정 높이 60px 내외 |
| 도메인 탭 | 전체 폭, 54~64px, 줄바꿈 금지 |
| 좌측 관점 | 164~180px, 고정 |
| 중앙 시각화 | `minmax(0, 1fr)`, 최소 430px |
| 우측 기능 | 220~240px, 고정 |
| 하단 흐름 | 112~126px, 세 관점 동일 |
| 간격 | 10~12px, 모든 모드 동일 |

정확한 픽셀은 구현 전 실측으로 확정하되, 세 관점의 좌/상/우/하 bounding box 차이는 1px 이하로 한다.

## 관점별 내부 콘텐츠

- Vehicle/System: 3D 차량/부품, 카메라 조작, 입력 부품 직접 조작.
- E/E Architecture: 연결 논리/겹쳐/실제 부품 탭은 좌측 관점 패널 상단에 둔다. 중앙 도면 위에는 겹치지 않는다.
- Control Software: 제어 블록과 단계 실행을 중앙 고정 캔버스 안에 맞춘다.

## 레이아웃 불변성

- 모드 전환, 조건 활성화, 완료 상태, 팝업 개폐로 외부 프레임이 이동하지 않는다.
- 버튼은 DOM에 항상 유지하고 `disabled/available/active/completed` 상태만 바꾼다.
- 내부 내용이 길면 내부 스크롤을 사용한다. 외부 행 높이를 늘리지 않는다.
- 팝업은 `fixed` 레이어와 명시적 z-index 토큰을 사용한다.

## QA 계약

- 1054×723, 1280×720, 1440×731, 1920×1080에서 캡처한다.
- 세 관점의 주요 패널 bounding box를 자동 측정한다.
- 텍스트 overflow, 버튼 이동, 팝업-하단 내비 간섭, 애니메이션 중 clipping을 검사한다.
