## 0. 추리게임의 기준 (수정)
- 추리게임의 핵심은 **모르는 것을 증거로 밝혀 가는 과정**이다. 용의자 지목·반전은 장르 장치 중 하나일 뿐 필수가 아니다.
- 그래서 머그샷·용의자 화면을 새로 만들지 않는다. 대신 이미 있는 화면 안에서 다음 세 가지가 보이게 한다.
  1. **모르는 것**: 지금 무엇을 모르는지(가설 목록).
  2. **증거**: 내가 고른 측정·시험이 무엇을 보여 줬는지.
  3. **결론의 근거**: 어떤 증거로 어떤 가설이 지지·반박됐는지.
- 1단계는 원인을 확정하지 않는다(가설을 좁힌다). 3단계에서 시험으로 확정한다.

8. 필수 사건 2개(구동·열관리) 처음부터 끝까지: 검증 단계까지 브라우저로 확인. 레이스 구간 실주행은 사용자 확인 필요

## 6. 기술 검증 (이번에 확인한 것)
- 구동: 입력만 관측 → 판단 불가 / 입력+출력 → FAIL / 처리값 포함 → VCU SW 지지·입력 회로 반박 → 원인 확정 → 수정 → 같은 시험 PASS.
- 열관리: SW 단위 PASS → 팬 제어 SW 반박 / 시스템 통합에서 회전+냉각수 온도만 → 추가 증거 필요 / 회전+커넥터 PWM+전원 → 팬 모터 지지·출력단 반박 → 원인 확정.
- 관측값은 모두 `simulate()` 계산 결과에서 읽음(장식용 그래프 없음).

## 7. 남은 위험
- 레이스 실주행(고장 트리거·복귀)은 이번에 직접 몰아 보지 않았다(브라우저 패널이 보일 때 확인 필요).
- 레이스 수치(`vehicleSim`)와 검증 수치(`simModel`)는 별도 모델이다. 핵심 값(60%→27%, 204→92 Nm, 42→8 bar)은 같지만 시간 축은 다르다.
- 열관리 커넥터 PWM은 고장 시 기준보다 높게(100%) 나온다. 결과(제어기가 명령을 올림)라는 설명을 가설 카드 근거에 넣었다.
- 효과음(시동·출발)은 합성음이라 실제 소리는 크롬에서 들어 봐야 한다.

## 9. 남은 일 전체 목록 (우선순위 순)

**마감 전 (P1)**
1. 처음부터 끝까지 한 사건 통합 플레이(타이틀 → 차고 → 레이싱 고장 → 역추적 → 퍼즐 → 검증 → 수리 → 재주행). 지금까지는 장면별로 확인. 실주행 키 입력은 사용자 크롬에서 한 번 확인 필요.
2. 차고 필수 학습 축소: 첫 진입은 공통 구조(입력 → 센서 → ECU → SW → 통신 → 액추에이터 → 차량) 2~3분, 도메인 상세는 자유 열람. 사건 직전 관련 기능 자동 강조 금지.
3. 튜토리얼을 한 번에 한 행동으로(긴 팝업 → 현재 할 일 한 줄 + 도움말 다시 보기).
4. 촉감 피드백: 퍼즐 조각 장착 눌림·스냅음, 관측점 체결 반응, 폴라로이드 들기·자석 스냅.
5. 레이싱 HUD 상시 정보 축소(속도·추격 거리·경고·미니맵만, 조작법은 접기).
6. 퍼즐(2단계)과 검증 연결 강화: 퍼즐 완료 시 "이 기준이 검증의 기대값이 됩니다" 한 줄 + 퍼즐 블록과 검증 신호 이름 일치 점검.
7. 원인 역추적 화면 정보량: 사건·증거 / 신호 경로 / 가설 세 영역 비율 조정.

**여력이 있으면 (P2)**
