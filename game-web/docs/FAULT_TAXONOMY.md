## 0. 원칙
1. **축은 독립이다.** 한 시나리오는 14개 축 각각에서 값을 고르며 한 카테고리로 귀속하지 않는다(예: thermal은 "결함 위치=I/O 어댑터"이면서 "성격=타이밍·실행 순서").
2. **위치·성격·증상은 다른 질문이다.** 위치=어디, 성격=어떤 종류, 증상=운전자/관측자에게 어떻게 보이나.
3. **복수 선택 칸**은 아래 각 축에 명시한다. 단일 선택 축은 "주(primary) 1개 + 부(secondary) 0~n개"로 쓰는 것을 허용한다.
4. 코드 지원 평가: **지원**(데이터 필드·분기 존재) / **부분**(문자열 설명으로만 존재) / **없음**.
5. 이 분류의 SW-only 근본 원인 제한은 **[게임] 정책(L-3)**이며 표준 요구가 아니다. 분류 축에는 HW·센서 위치도 포함해 두되, `게임 허용` 열로 사건 근본 원인 허용 여부를 따로 표시한다.

- 14축 중 **A6·A8·A12가 세 사건 모두 같은 값**이다: 연속량 편차 + 로직 조립 + 연속 그래프. 신규 결함 유형이 늘면 이 3축이 먼저 부족해진다(상태 전이·이벤트·진단·메시지).
