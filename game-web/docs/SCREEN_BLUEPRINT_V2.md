# TraceBack 화면 설계 기준 V2

이 문서는 구현 시 임의 해석을 막기 위한 페이지별 기준이다. 우선순위는 `v16 런타임 계약 → 원본 Stitch 와이어프레임 → 제작 이미지 → 과거 프로젝트의 질감 참고` 순서다. 한 화면의 설명은 최대 1~2문장으로 제한하고, 플레이어가 먼저 보는 것은 차량·부품·카드·배선·시험 장치여야 한다.

## 공통 UI

- 기준 화면은 16:9이며 상단 상태바와 하단 행동바의 높이는 화면의 약 6~8%다.
- 로고는 장식이 아니라 일시정지 메뉴 버튼이다. 메뉴에서 `계속하기`와 `처음으로`를 선택할 수 있다.
- 주요 행동은 오른쪽 아래, 뒤로/초기화는 왼쪽 아래에 둔다.
- 본문 글자는 작고 짧게 유지한다. 큰 글자는 장면 제목·속도·판정에만 사용한다.
- 모든 선택 카드는 다시 누르면 선택을 취소할 수 있다.

## 00 TITLE

- 표시: 붉은 EV, 루·밍 캐릭터, 새 게임, 이어하기, 설정/가이드.
- 동작: 새 게임은 프롤로그, 이어하기는 저장 체크포인트로 이동.
- 그래픽:정보 비율은 약 70:30. `00_traceback` 구도를 따른다.

## 01 PROLOGUE

- 표시: 레이스 우승 → 차량 강탈/추격 → 항구 탈출 계획을 3개 장면으로 전달.
- 이전/다음: TITLE → PROLOGUE → GARAGE L1.
- 동작: 계속, 전체 건너뛰기. 초기화 데이터는 건너뛰지 않는다.

## 02 GARAGE — 차량 도메인 학습

- 표시: 완성차 대신 선택한 도메인의 실제 구성 부품이 움직이는 3D 메커니즘. 상단 도메인 탭(구동·제동·조향·전원), 우측 핵심 기능 목록, 하단 신호 흐름을 함께 둔다.
- L1: 운전자 요구와 차량 기능/물리 반응. L2: 센서·ECU·액추에이터와 HW 배선. L3: ECU 내부 SW 컴포넌트와 포트. L4: 입력·조건·계산·보호 규칙.
- 네 단계는 순차 잠금이 아니라 언제든 눌러 왕복한다. 같은 도메인이라도 단계에 따라 본문의 추상화 수준과 표시 부품이 바뀐다.
- 핵심 기능: 구동(토크 요청·인터록·인버터 제어·동력전달), 제동(제동력 요구·회생/마찰 협조·ABS/EBD·ESC), 조향(전륜 각도·EPS·랙 전달·요 안정), 전원(Pack Safe·프리차지/접촉기·출력 가용량·OBC/DC-DC).
- 이전/다음: PROLOGUE → L1 → L2 → L3 → L4 → CHASE.
- 동작: 각 노드를 눌러 흐름을 확인하고 다음 설계 관점으로 이동. 차량/부품이 화면의 절반 이상을 차지한다.

## 04 CHASE — 주행과 자연 고장 체험

- 표시: 시작선·결승선이 있는 도로, 고양이 두 마리가 탄 오픈카, 경찰차, 속도계, 미니맵, 전체 주행거리 막대 위 두 차량 위치와 격차(m). 고장 전에는 사건명·원인 정보가 없다.
- 동작: W/S 가감속, A/D 조향, ESC/로고 일시정지.
- 진행: `3 → 2 → 1 → GO` → 정상 주행 → 좌상단 경광 경고와 출력 저하/열상승을 일정 거리 동안 직접 체험 → 드라이버/엔지니어 고양이 대화 → 제한 주행/추리.
- 장애물은 학습 흐름을 끊는 체포 조건으로 사용하지 않는다. 충돌 때문에 즉시 경찰에 잡히지 않는다.
- 추격 격차는 레이싱 이후 모든 조사 화면에서도 계속 줄어든다. 원인 정답은 +20m, 오답은 -20m이며 필수 고장 2회 전까지는 0m가 되지 않는다. 두 번째 고장 이후에는 0m까지 허용한다.

## 05 FAULT CUE — 증상 기록

- 표시: 짧은 고장 연출, 증상 1문장, 입력/명령/실제 응답의 그래픽 기록. 원인과 정답은 숨긴다.
- 이전/다음: CHASE → FAULT CUE → ASSIST CHASE 또는 BOARD.

## 06 / 06-1 BOARD — 메모판 추리

- 표시: 4:3 코르크 보드에 `주행 기록`, `관찰·진단 단서`, `원인 후보` 영역을 둔다. 모든 후보는 처음에는 하단 트레이에 흩어진 폴라로이드다. 사진 영역에는 파형/ECU/액추에이터 그래픽, 하단 흰 영역에는 라벨과 값이 들어간다.
- 동작: 카드를 드래그해 맞는 영역에 꽂거나 클릭해 자동 배치한다. 꽂힌 카드를 다시 누르면 취소된다. 정답과 오답 후보는 같은 외형으로 섞어 둔다.
- 주행 기록에는 선택적으로 다시 볼 수 있는 `QUICK REPLAY` 영상형 모달을 둔다. 재생 화면은 관찰값만 보여주며 원인명은 숨긴다.
- 완료 조건: 증거 2개 이상과 원인 후보 1개. 정답을 카드 외형으로 미리 노출하지 않는다.
- 이전/다음: BOARD → WIRING. 검증 실패 시 BOARD로 돌아와 선택을 수정할 수 있다.

## 06-1 HW/SW WIRING — 요구사항 플로차트와 E/E 설계

- 표시: 전체 작업대는 4:3. 좌측에 세로형 `입력 ↓ IF ↓ 제어 ↓ THEN ↓ 출력` 요구사항 시나리오, 중앙에 격자 배선 캔버스, 우측에 핵심 HW/SW 부품 트레이를 둔다.
- 동작: HW도 고정하지 않는다. 모든 센서·ECU·SW·액추에이터를 드래그 배치하고, 출력 포트→입력 포트 순서로 구불구불한 배선을 직접 잇는다. 노드와 선은 삭제·이동·재연결 가능해야 한다.
- 부품 트레이에는 정상 블록, 오류 후보 블록, 관측 전용 블록을 함께 둔다. 구동은 APS/Signal Adapter/정상·오류 Torque Map/CAN/VCU/Inverter+PMSM 수준으로 제공한다.
- 형식 오류는 이 화면에서 설명하고, 논리 오류는 시험대까지 진입시켜 결과로 발견하게 한다.
- 이전/다음: BOARD → WIRING → TWIN BENCH.

## 06-2 TWIN BENCH — 3수준 검증

- 표시: 고양이 실험실 안에 `정상 시나리오 설계`와 `내가 만든 설계`를 같은 크기로 나란히 둔다. 텍스트 표 대신 실제 신호/부품/차량 애니메이션으로 비교한다.
- 탭은 `SW`(로직 입·출력/flowchart), `임베디드`(ECU·HW 배선과 3D 부품 동작), `차량`(주행 시뮬레이션) 세 개다. 기존 정상/고장/복귀 탭은 사용하지 않는다.
- 현재 사건에 맞춰 구동 모터, 냉각팬, 제동 캘리퍼 그래픽을 바꾼다. 정상 설계는 움직이고 잘못 연결한 설계는 끊기거나 멈춰야 한다.
- PASS/FAIL은 초록/빨강 경광등과 글자를 함께 표시한다. 세 탭 실행 후 종합 판정한다.
- 공식 HIL/인증 획득으로 표현하지 않는다. FAIL이면 BOARD 또는 WIRING으로 복귀한다.

## REPAIR / SAFE LIMIT

- 표시: ECU→배선→현재 사건 부품이 실제로 다시 움직이는 복구 애니메이션과 엔지니어 고양이 대화. 구동 SW 사건은 `OTA 업데이트를 해서 고장을 해결했어! 휴…`라고 명시한다.
- 이전/다음: TWIN BENCH PASS → REPAIR → CHASE RESUME.
- 복귀 시 주행거리와 추격 격차를 초기화하지 않고 고장 직전/정차 지점에서 이어간다.

## CHASE RESUME / OPTIONAL / SHIP ESCAPE

- 수리 후 같은 주행 상태로 복귀한다. 다음 자연 고장을 경험하면 새 사건의 BOARD가 시작된다.
- 선택 제동 사건은 건너뛸 수 있고 결말을 막지 않는다.
- 최종 항구 구간에서 해적선 램프로 진입하면 ENDING.

## ENDING

- 운전 성과와 추리·검증 성과를 분리해 보여준다.
- 공식 안전 인증이나 실제 HIL 완료처럼 오해할 수 있는 배지는 사용하지 않는다.
