# TraceBack v3 플레이어 용어 사전

화면 문구와 사건 시트에서 같은 개념은 같은 말로 쓴다. 개발 메모의 표현을 플레이어 화면에 그대로 노출하지 않는다.

| 쓰는 말 | 뜻 | 화면에서 쓰지 않는 말 |
|---|---|---|
| 첫 편차 | 출력에서 거꾸로 따라가 처음 기준과 달라진 신호 | 처음 어긋난 곳 |
| 의심 구간 | 첫 편차를 만든 것으로 의심되는 부품·SW 범위 | 구간 안쪽 |
| 가설 후보 | 의심 구간에서 원인으로 검증할 후보 | 가설후보가 생겼어요 |
| 영향을 줬어요 | 현재 출력보다 먼저 달라져 원인 경로에 들어간 신호 | 유력 |
| 영향을 주지 않았어요 | 정상 신호 또는 출력보다 늦게 달라진 결과 신호 | 반박(도미노 단계) |
| 후보에 올려요 | 실험대에서 시험할 후보로 남김 | 보류(도미노 단계) |
| 후보에서 빼요 | 지금까지 확인한 값으로 시험 대상에서 제외 | 반박됨(도미노 단계) |
| 정상 기준 | 요구사항으로 만든 비교용 정상 동작 | 정상 모델(단독 설명) |
| 시험 수준 | SW 단위·SW 통합·제어기 I/O·시스템 중 시험 범위 | 검증 레벨을 섞어 쓰기 |
| 통과 | 시험 결과가 요구사항과 같음 | PASS만 단독 표기 |
| 실패 | 시험 결과가 요구사항과 다름 | FAIL만 단독 표기 |
| 판정 불가 | 이 시험 범위에는 필요한 신호가 없어 원인을 가를 수 없음 | 보류(시험 결과) |
| 원인으로 보여요 | 시험 결과가 해당 가설의 예측과 일치함 | 지지(플레이어 버튼) |
| 원인이 아니에요 | 시험 결과가 해당 가설의 예측과 다름 | 반박(플레이어 버튼) |
| 아직 몰라요 | 해당 시험만으로 가설을 판단할 수 없음 | 보류(플레이어 버튼) |
| 영향 범위 | 수리 후 함께 정상 복귀를 확인할 출력 목록 | 회귀 후보(플레이어 문구) |

## 원인 종류 태그

가설 카드에는 다음 중 하나를 붙인다: `SW 로직`, `SW 설정`, `통신`, `센서`, `HW`.

## 표기 원칙

- 수치와 단위는 코드 글꼴로 표시한다. 기준은 회색, 이번 값은 붉은 계열로 구분한다.
- 한 화면의 질문은 하나만 두고, 선택지는 하단에 둔다. 우측 패널은 기록·참고용이다.
- 단계 안내는 `방금 한 일 → 이번에 할 일 → 하는 방법` 순서로 세 문장으로 쓴다.
