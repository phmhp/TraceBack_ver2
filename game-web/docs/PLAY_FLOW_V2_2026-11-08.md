# 추리 흐름 v2 (초안)

- 1·2단계: 사용자 프롬프트 PART B·C와 재설계안 3절(E/E 판·머그샷)을 따른다.
- 3단계: "볼트의 질문에 증거로 답한다"(새 제안, 승인 대기).
- 공통(이후 합의): 숫자는 결론 근거만, 스토리 = 실무(고장 밝히기 → 고객에게 근거 설명 → 수리 요청), 3단계 왼쪽 시각화는 탭.

## 3단계를 바꾸는 이유
- 지금 흐름: 레벨 고르기 → 입력 고르기 → 관측점 꽂기 → 판정. 플레이어가 하는 일이 "작업"처럼 보인다.
- 고객사 대응이라는 목적이 화면에 안 보인다.

## 핵심 아이디어
**3단계는 볼트(고객)가 던지는 질문 3개에 답하는 게임이다.**
- 질문 하나 = 가설 하나를 가르는 일.
- 답하려면 시험을 하나 고르고, 결과를 근거로 답한다.

## 1단계 · 원인 역추적 — "어디서부터 이상해졌나?" (원인은 확정하지 않음)
기준: 사용자 프롬프트 PART B(5~9, 36) + 재설계안 3절(E/E 판 + 틀린그림찾기 + 거꾸로 도미노 + 카드로 좁히기).

**화면 배치 (기존 폴라로이드·노트 판·도미노 재사용)**

```
┌──────────────────────┬──────────────────────────────────────┐
│ 사건·증거 폴라로이드    │ 전체 차량 E/E 아키텍처 판              │
│ (주행 사진·경고등·      │ (차고 E/E 설계도 재사용)                │
│  볼트 진술·측정 증거)   │                                      │
├──────────────────────┴──────────────────────────────────────┤
│ 머그샷 용의자 줄 (지금 고른 출력에 영향을 준 후보만 켜짐)             │
└─────────────────────────────────────────────────────────────┘
```

**진행**
1. **증거 보기:** 왼쪽 폴라로이드(정상 vs 이번 주행)에서 이상한 곳을 돋보기로 찾는다. 예: 가속이 덜 올라감.
2. **출력 고르기:** 그 증거를 근거로 E/E 판에서 **출력 부품**을 고른다. 예: 차량 가속 → 구동 모터.
3. **용의자 활성화:** 그 출력이 만들어질 때 영향을 주는 앞쪽 부품만 아래 머그샷 줄에 켜진다(상태: 미조사). 나머지는 흐려진다.
4. **하나씩 고르며 좁히기:** 머그샷을 하나 골라 잰다(측정 1번 = 추격 거리 조금). 결과는 왼쪽에 증거 카드로 쌓인다.
   - 정상이면 → 플레이어가 **반박됨** 도장
   - 이상한데 더 늦게 달라졌으면 → 결과(함정)라서 **반박됨**
   - 이상하고 더 먼저 달라졌으면 → **유력** 도장. 이 부품이 새 "출력"이 되고, 머그샷 줄이 **그 부품의 앞쪽 후보로 갱신**된다.
   - 도장은 플레이어가 고르고 게임은 맞는지만 확인한다. 근거 없이 찍으면 "더 재 보세요"로 유도한다.
5. **도미노:** 유력 → 유력으로 이어진 경로가 출력에서 원인 쪽으로 거꾸로 쓰러진다. 앞쪽 입력이 모두 정상인 곳이 **처음 어긋난 곳**이다.
6. **끝:** 처음 어긋난 곳 안쪽의 후보(SW인지 HW인지 등)는 이 단계의 측정으로는 가를 수 없다. **판단 보류 2명 이상**을 들고 다음 단계로 간다.

**용의자 (머그샷)**
| 사건 | 용의자 | 1단계 끝 상태 |
|---|---|---|
| 구동 | 가속 페달 센서 / VCU 처리 SW / VCU 입력 회로 / CAN 통신 / 인버터·모터 / 배터리 출력 제한(BMS) | 반박: 페달 센서, CAN, 인버터·모터, BMS · **판단 보류: VCU 처리 SW, VCU 입력 회로** |
| 열관리 | 온도 센서 / 팬 제어 SW / ECU 출력단·배선·전원 / 냉각 팬 모터 / 냉각수 펌프 / 출력 제한 로직 | 반박: 온도 센서, 팬 제어 SW, 펌프, 출력 제한 · **판단 보류: 출력단·배선·전원, 팬 모터** |

- **얻는 것:** 차량 E/E 구조에서 신호 경로를 출력부터 거꾸로 따라가는 법. 결과와 원인 구분. "관측된 이상 ≠ 원인"(가설로 남김).
- **출처:** 차고 › 해당 도메인 › E/E 관점(구동: APS → VCU → CAN → 인버터·모터). 측정값은 `DominoTrace.tsx` CASES, 용의자는 `scenarios.ts` SCENARIO_META(용의자 추가 필요).

## 2단계 · 요구사항 기반 로직 퍼즐 — "정상이라면 어떤 출력이 나와야 하나?"
기준: 사용자 프롬프트 PART C(10~15, 37).

| 항목 | 내용 |
|---|---|
| 미션 | 의심 구간의 정상 로직을 퍼즐로 완성한다 |
| 요구사항 | 공개한다. 단 **슬롯 순서대로 나열하지 않고** 기능별로 섞는다(지금은 사실상 정답 순서라 바꿈). 사양은 범위·단위·보간·한계를 명시한다(예: 페달 0~100% → 토크 0~340 Nm 선형, 가용 한계 260 Nm) |
| 선택지 | 조각 5개: 정답 3 + 표 값만 다른 함정 1 + 다른 기능 블록 1 |
| 조작 | 드래그 → 슬롯 근처 흡착 → 눌림·복원 + 딸깍 소리. 연결되면 포트를 따라 신호 점이 흐른다 |
| 판정 | **연결 확인**(모양·신호 종류가 맞음)만 한다. 요구사항을 만족하는지는 판정하지 않는다 → 3단계 몫 |
| 탐색 | 예시 입력 슬라이더(페달 0~100% / 온도)로 칸마다 값이 어떻게 바뀌는지 본다. 정답 표시 없음 |
| 사건 성격에 맞춤 | 구동(SW 로직 고장) = 계산 순서(맵·MIN·램프). 열관리(구동기 고장) = **명령 → 구동 → 피드백 관계**(히스테리시스 → PI → 출력단 → 팬 → 회전 피드백) |
| 끝 | **기대값 카드**: 구동은 "60% → 204 Nm", 열관리는 "65°C 넘으면 팬 1850 rpm". 3단계 점선(기준)으로 그대로 쓰인다 |
| 얻는 것 | 핵심 제어 로직, 요구사항을 읽고 기대값을 세우는 법 |
| 출처 | 차고 › 해당 도메인 › Control SW. 값은 `RefPuzzle.tsx` REF, 수치는 `simModel.ts`와 같음 |

## 3단계 · 시험과 답변 — "볼트의 질문에 증거로 답하기"

**한 질문의 진행 (3번 반복)**
1. **질문 카드:** 볼트가 묻는다.
2. **시험 카드 고르기 (2~3장 중 하나):** 각 카드에는 그림, 쉬운 이름, 비용이 있다. 전문 이름(레벨)은 작게 보인다.
    - 예: "SW만 PC에서 돌려 보기 (SW 단위 시험) · 비용 1"
    - 예: "실제 부품을 붙여 돌려 보기 (시스템 통합 시험) · 비용 5"
3. **잴 곳 고르기 (그림에서 2곳):** 왼쪽 시각화(탭: SW 로직 / 제어기 / 부품) 위에 측정 지점이 핀으로 표시된다. 눌러서 고른다.
4. **실행:** 결과는 기대값 카드와 나란히 "기준 / 지금" 한 쌍으로 나온다.
5. **답하기 (버튼 3개 중 하나, 글쓰기 없음):** "문제 있음 / 문제 없음 / 이 시험으로는 모름". 고르면 시험 결과가 근거로 자동으로 붙는다. 틀리면 너트가 이유를 짚어 준다.

**구동 사건의 질문 3개**
| 볼트 질문 | 맞는 시험 | 결과 | 답 |
|---|---|---|---|
| ① "페달 센서 고장 아니야?" | (1단계에서 이미 답함) 페달 값 측정 | 60% 정상 | 문제 없음 |
| ② "SW가 이상한 거야, 제어기 회로가 이상한 거야?" | SW만 PC에서 돌려 보기 | SW만 돌려도 처리값이 낮음 | SW 문제 있음, 회로 문제 없음 |
| ③ "그래서 뭘 고치면 돼?" | 보고서 → 수리 요청 → 같은 시험 다시 | 기대값과 같아짐 | 보정 블록 제거 |

**열관리 사건의 질문 3개**
| 볼트 질문 | 맞는 시험 | 결과 | 답 |
|---|---|---|---|
| ① "팬 끄는 SW가 잘못된 거 아니야?" | SW만 PC에서 돌려 보기 | 요구사항대로 켜짐 | SW 문제 없음 |
| ② "그럼 배선이야, 팬이야?" | 실제 부품 붙여 돌려 보기 · 잴 곳: 팬 커넥터 + 팬 | 커넥터에 명령·전원 도착, 팬은 멈춤 | 배선 문제 없음, 팬 문제 있음 |
| ③ "그래서 뭘 고치면 돼?" | 보고서 → 팬 교체 요청 → 다시 시험 | 팬이 돔 | 팬 교체 |

- **함정 시험:** 열관리 ②에서 "SW만 돌려 보기"를 고르면 결과는 PASS다. 답은 "이 시험으로는 모름"(팬이 모델이라 안 보임). 비용이 들고 너트가 이유를 설명한다.

**마지막 · 볼트에게 브리핑 (보고서 한 장)**
- 질문 3개와 답이 근거와 함께 한 장에 자동 정리된다(플레이어가 글을 쓰지 않음). 플레이어가 고른 답과 시험 결과로만 채워진다.
- "보고하기"를 누르면 볼트가 "좋아, 고치자!" → 수리 → 재주행(같은 조건 회귀 카드).

| 지금 | v2 |

| 미션 A·B, 레벨 4개 → 입력 → 관측점 6개 중 3개 | 질문 카드 → 시험 카드 2~3장 → 잴 곳 2곳 |
