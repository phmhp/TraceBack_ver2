# 추리 흐름 v2 (초안) — "볼트의 질문에 증거로 답한다"

## 바꾸는 이유
- 지금 흐름: 레벨 고르기 → 입력 고르기 → 관측점 꽂기 → 판정. 플레이어가 하는 일이 "작업"처럼 보인다.
- 고객사 대응이라는 목적이 화면에 안 보인다.

## 핵심 아이디어
**3단계는 볼트(고객)가 던지는 질문 3개에 답하는 게임이다.**
- 질문 하나 = 가설 하나를 가르는 일.
- 답하려면 시험을 하나 고르고, 결과를 근거로 답한다.

---

## 1단계 · 탐문 — E/E 지도 위에서 출력부터 거꾸로 (REDESIGN §3 반영)

**화면 배치**
```
┌──────────────────────────────────────────────┬──────────────┐
│ 차량 전체 E/E 아키텍처 (전 도메인, 사건 도메인 강조)    │ 용의자 머그샷 │
│  센서 ── 제어기 ── CAN ── 구동 부품 ── 차량 반응      │  라인업       │
│  (지나온 길은 빨간 실, 무혐의 부품은 회색)            │ (지금 칸 앞   │
│                                              │  연결된 부품)  │
├──────────────────────────────────────────────┴──────────────┤
│ 너트 말풍선: 지금 할 일 한 줄                                   │
└────────────────────────────────────────────────────────────────┘
```

**진행**
| 순서 | 미션 | 플레이어가 하는 것 | 보이는 것 |
|---|---|---|---|
| ① 틀린 그림 찾기 | "정상 주행과 이번 주행, 뭐가 달라요?" | 폴라로이드 두 장(정상 / 이번)에서 다른 곳을 누른다 | 정답이면 E/E 지도에서 **출력 부품(차량 반응)**에 빨간 표시 |
| ② 용의자 소환 | "이 부품에 값을 보낸 건 누구?" | 지도에서 지금 부품 **앞에 연결된 부품**들이 켜지고 머그샷으로 줄 선다 | 머그샷: 부품 사진 · 이름 · 역할 한 줄 · "?" |
| ③ 알리바이 확인 | "누가 먼저 이상해졌나?" | 머그샷을 눌러 잰다(1번 = 추격 거리 조금) | 기준/지금 막대 + 도장: **무혐의**(정상) / **수상**(먼저 이상) / **피해자**(나중에 이상 = 결과) |
| ④ 따라가기 | | "수상" 머그샷을 빨간 실로 지금 부품에 잇는다 → 그 부품이 새 "지금 칸" | 지도 위 빨간 실이 한 칸 거꾸로 늘어난다 |
| ⑤ 반복 | | 앞 용의자가 모두 무혐의가 될 때까지 ②~④ | |
| ⑥ 의심 구간 | "들어오는 값은 정상, 나가는 값만 이상. 범인은 이 안에 있어요" | 지도에서 의심 구간(부품 안쪽)을 확대해 본다 | 구간 안 **남은 용의자 2명** = 3단계 볼트 질문 |

- **판단 규칙(두 개뿐):** 원인은 결과보다 먼저 이상해진다 / 입력이 모두 정상이고 출력만 이상하면 그 안쪽이 범인이다.
- **함정:** 결과로 함께 이상해진 부품(계기판, 배터리 전류 등)은 "피해자" 도장. 잘못 이으면 너트가 "이건 나중에 이상해졌어요"라고 짚는다.
- **얻는 것:** 차량 전체 E/E 구조 속에서 신호가 흐르는 길, 거꾸로 추적하는 법, 원인과 결과를 구분하는 법.
- **재사용:** 차고 E/E 설계도(`EeBlueprint`), 지금 도미노의 측정 데이터·시간 규칙, 폴라로이드 스킨. 머그샷은 엔딩의 머그샷 카드 스타일을 재사용한다.

**구동 사건 예시(해답)**
- ① 틀린 그림: 가속 그래프의 꺾임 → 출력 "차량 가속" 표시
- 차량 가속 ← 용의자 [모터 힘 = 수상 · 계기판 = 피해자 · 회생 제동 = 무혐의]
- 모터 힘 ← [CAN 토크 명령 = 수상 · 배터리 전류 = 피해자 · 모터 온도 = 무혐의]
- CAN 명령 ← [VCU 처리값 = 수상 · 인버터 전류 = 피해자 · 게이트웨이 = 무혐의]
- VCU ← [페달 센서 · 브레이크 스위치 · 기어 · BMS 허용 · 온도 보호 = 모두 무혐의]
- ⑥ 의심 구간: VCU 안쪽 → 남은 용의자 "VCU SW 계산" / "VCU 입력 회로"

**열관리 사건 예시(해답)**
- ① 틀린 그림: 출력 제한 표시등 · 가속 꺾임 → 출력 "차량 가속" 표시
- 차량 가속 ← 출력 허용(수상) ← 모터 온도(수상) ← 냉각수 온도(수상) ← 냉각 팬 회전(수상)
- 냉각 팬 ← [Thermal ECU 팬 명령 100% = 무혐의 · 바깥 기온 · 펌프 = 무혐의]
- ⑥ 의심 구간: 명령 이후 팬 구동 경로 → 남은 용의자 "출력단·배선·전원" / "팬 모터"

## 2단계 · 설계도 복원 — "정상이라면 어때야 하지?"
| 항목 | 내용 |
|---|---|
| 미션 | 빈칸 3개를 채워 정상 로직 완성 |
| 선택지 | 조각 5개(정답 3, 표 값이 다른 함정 1, 다른 기능 블록 1) |
| 보이는 것 | 요구사항 줄, 조각 "?"(표 값) |
| 끝 | **기대값 카드 1장**: 구동은 "페달 60% → 204 Nm", 열관리는 "65°C 넘으면 팬 1850 rpm" |
| 얻는 것 | 핵심 제어 로직(맵·MIN·램프 / 히스테리시스·PI), 3단계 판정 기준 |

## 3단계 · 시험과 답변 — "볼트의 질문에 증거로 답하기"

**한 질문의 진행 (3번 반복)**
1. **질문 카드:** 볼트가 묻는다.
2. **시험 카드 고르기 (2~3장 중 하나):** 각 카드에는 그림, 쉬운 이름, 비용이 있다. 전문 이름(레벨)은 작게 보인다.
    - 예: "SW만 PC에서 돌려 보기 (SW 단위 시험) · 비용 1"
    - 예: "실제 부품을 붙여 돌려 보기 (시스템 통합 시험) · 비용 5"
3. **잴 곳 고르기 (그림에서 2곳):** 왼쪽 시각화(탭: SW 로직 / 제어기 / 부품) 위에 측정 지점이 핀으로 표시된다. 눌러서 고른다.
4. **실행:** 결과는 기대값 카드와 나란히 "기준 / 지금" 한 쌍으로 나온다.
5. **답하기 (3지선다):** "문제 있음 / 문제 없음 / 이 시험으로는 모름". 고르면 결과가 근거로 붙는다. 틀리면 너트가 이유를 짚어 준다.

**구동 사건의 질문 3개**
| 볼트 질문 | 맞는 시험 | 결과 | 답 |
|---|---|---|---|
| ① "페달 센서 고장 아니야?" | (1단계에서 이미 답함) 페달 값 측정 | 60% 정상 | 문제 없음 |
| ② "SW가 이상한 거야, 제어기 회로가 이상한 거야?" | SW만 PC에서 돌려 보기 | SW만 돌려도 처리값이 낮음 | SW 문제 있음, 회로 문제 없음 |
| ③ "그래서 뭘 고치면 돼?" | 보고서 → 수리 요청 → 같은 시험 다시 | 기대값과 같아짐 | 보정 블록 제거 |

**열관리 사건의 질문 3개**
| 볼트 질문 | 맞는 시험 | 결과 | 답 |
|---|---|---|---|
| ① "팬 끄는 SW가 잘못된 거 아니야?" | SW만 PC에서 돌려 보기 | 요구사항대로 켜짐 | SW 문제 없음 |
| ② "그럼 배선이야, 팬이야?" | 실제 부품 붙여 돌려 보기 · 잴 곳: 팬 커넥터 + 팬 | 커넥터에 명령·전원 도착, 팬은 멈춤 | 배선 문제 없음, 팬 문제 있음 |
| ③ "그래서 뭘 고치면 돼?" | 보고서 → 팬 교체 요청 → 다시 시험 | 팬이 돔 | 팬 교체 |

- **함정 시험:** 열관리 ②에서 "SW만 돌려 보기"를 고르면 결과는 PASS다. 답은 "이 시험으로는 모름"(팬이 모델이라 안 보임). 비용이 들고 너트가 이유를 설명한다.

**마지막 · 볼트에게 브리핑 (보고서 한 장)**
- 질문 3개와 답이 근거와 함께 한 장에 정리된다. 플레이어가 고른 시험 결과로만 채워진다.
- "보고하기"를 누르면 볼트가 "좋아, 고치자!" → 수리 → 재주행(같은 조건 회귀 카드).

## 지금 화면에서 바뀌는 것
| 지금 | v2 |
|---|---|
| 미션 A·B, 레벨 4개 → 입력 → 관측점 6개 중 3개 | 질문 카드 → 시험 카드 2~3장 → 잴 곳 2곳 |
| 신호 모니터에 숫자 여러 줄 | 기준/지금 한 쌍 + 막대 + 한 단어 |
| 판정 노트(가설마다 3버튼) | 질문 하나에 답 하나 |
| 1단계 도미노 카드 줄 | 전체 E/E 지도 + 출력부터 거꾸로 + 용의자 머그샷 |
| 처음 갈라진 신호에 깃발 | 질문 ②의 답이 곧 범인 지목 |
| 보고서는 마지막에 자동 정리 | 같음(질문·답·근거 한 장) |

- 유지: 수치 모델, 판정 규칙(레지스트리), 왼쪽 탭, 비용 별점, 회귀.
- 신호 모니터는 "자세히 보기"로 접어 두고, 원하면 열어서 그래프를 본다.
