# STEP01 도메인 데이터 교차 검토 요청 (GPT용)

사용법
1. 아래 "공통 지침"을 ChatGPT 새 대화에 먼저 붙여 넣습니다.
2. 도메인 블록을 **한 번에 하나씩** 붙여 넣고, 답변을 받으면 이 문서 맨 아래 "검토 결과 기록"에 요약합니다.
3. 지적 사항은 심각도(오류 / 개선 / 참고)별로 정리해 Claude에게 전달합니다. 수정은 Claude가 반영합니다.

## 공통 지침 (먼저 붙여 넣기)
```
당신은 자동차 전동화(EV) 시스템 엔지니어이자 소프트웨어 검증 전문가입니다.
기준: EV 일반 아키텍처, AUTOSAR Classic(SWC, Runnable, RTE, BSW, E2E), ASPICE(SYS.2~5, SWE.1~6), ISO 26262(Part 3, 4, 6).
신입 사원 교육용 게임의 "차량 도메인 학습" 데이터를 검토합니다. 특정 OEM 사양과의 일치는 요구하지 않으며, 일반 EV 아키텍처 관점에서 틀리거나 오해를 부르는 부분만 지적하세요.
각 도메인은 기능 4개이고, 기능마다 같은 흐름을 4개 해상도로 적습니다.
0 기능 흐름(차량 관점), 1 부품·E/E 연결(센서→제어기→버스→구동기), 2 SW 컴포넌트(AUTOSAR SWC 이름), 3 SW 로직(함수·블록).
검토 항목: (a) 용어와 구조가 EV 일반 아키텍처와 맞는가 (b) 기능 4개의 중복·누락 (c) 4개 층이 같은 흐름을 일관되게 보여 주는가 (d) SWC 이름이 AUTOSAR 관례에 맞는가 (e) 안전 메커니즘이 ISO 26262 관점에서 타당한가 (f) 신입이 오해할 만한 표현.
출력 형식: 표 하나. 열 = 기능 번호 | 층 | 문제 | 심각도(오류/개선/참고) | 수정 제안. 문제가 없으면 "이상 없음"만 쓰세요. 서론과 결론은 쓰지 마세요.
```

## 파워트레인 · 구동
```
도메인: 구동 (파워트레인)
목적: 가속 의도를 모터 토크와 바퀴 구동력으로 바꿉니다.

기능 1. 운전자 토크 요청 해석 [요구 해석]
  설명: 가속 페달 입력을 검증해 운전자가 원하는 토크로 바꿉니다.
  층 0 기능 흐름: 가속 페달 조작 → 가속 의도 → 가용 토크 판단 → 전륜 추진력 → 차량 가속
  층 1 부품·E/E: APS A/B 가속 페달 → VCU → CAN 토크 → MCU·인버터 ECU → 인버터 → 전륜 PMSM 모터 → 전륜 감속기 → 차동기어 → 드라이브 샤프트 → 전륜
  층 2 SW 컴포넌트(SWC): PedalInput → DriverRequest → TorqueArbiter → TorqueCmdTx
  층 3 SW 로직: A/B 상관성 → 입력 필터 → 페달 맵 → 구동 허용 → 가용 토크 MIN → 램프율 → 토크 출력

기능 2. 구동 허용·인터록 [제어·배분]
  설명: D단과 READY 조건이 모두 맞을 때만 구동 토크를 허용합니다.
  층 0 기능 흐름: D단 선택 → READY 확인 → 구동 허용 → 안전 출발
  층 1 부품·E/E: PRND 센서 → VCU Interlock → CAN Permit → 인버터 Enable
  층 2 SW 컴포넌트(SWC): GearInput → DrivePermit → FaultManager → PermitTx
  층 3 SW 로직: Gear==D → HV READY → 브레이크 인터록 → 고장 래치 → Permit Gate

기능 3. 토크 배분·제한 [제어·배분]
  설명: 배터리·모터·열 한계를 모아 낼 수 있는 최대 토크로 제한합니다.
  층 0 기능 흐름: 토크 요청 → 한계 수집 → 가용 토크 판단 → 최종 토크 명령
  층 1 부품·E/E: VCU → BMS → 모터 NTC 센서 → Thermal ECU → CAN 토크 → MCU·인버터 ECU
  층 2 SW 컴포넌트(SWC): LimitCollector → TorqueArbiter → RampLimiter → TorqueCmdTx
  층 3 SW 로직: 배터리 한계 수신 → 열 한계 수신 → 가용 토크 MIN → 램프율 → 토크 명령 확정

기능 4. 인버터 전류·토크 제어 [실행·보호]
  설명: 토크 명령을 3상 전류로 만들어 전륜 PMSM·감속기 어셈블리의 축 토크를 냅니다.
  층 0 기능 흐름: 토크 요구 → 전류 목표 → dq 제어 → PWM → 모터 회전 → 축 토크
  층 1 부품·E/E: VCU → CAN → 인버터 MCU → 3상 브리지 → PMSM → 리졸버
  층 2 SW 컴포넌트(SWC): TorqueCmdRx → CurrentCtrl → PwmDriver → ResolverIf → MotorProtect
  층 3 SW 로직: 명령 수신 → dq 변환 → 전류 PI → 전압 제한 → PWM 생성 → 리졸버 피드백 → 토크 추정
```

