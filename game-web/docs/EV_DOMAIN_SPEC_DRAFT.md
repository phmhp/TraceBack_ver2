# EV 도메인·기능 구조 초안 (검수용)

기준: EV 일반 아키텍처 / AUTOSAR(Classic: SWC·RTE·BSW) / ASPICE(SYS.2~5, SWE.1~6) / ISO 26262(Part 3·4·6).
수치는 "예시 파라미터"이며 특정 OEM 사양이 아닙니다. 최종 검수는 사람이 합니다.

## 1. 구조: 3묶음 11도메인 × 4기능 = 44기능

가로 내비게이션은 묶음 → 도메인 순서입니다. 도메인마다 기능 4개를 같은 3분류로 정리합니다.
- **요구 해석**: 입력을 읽고 의도·상태를 확정
- **제어·배분**: 목표값 계산, 도메인 간 협조·제한
- **실행·보호**: 구동기 출력, 이상 시 폴백·차단

| 묶음 | 도메인 | 상태 |
|---|---|---|
| 파워트레인 | 구동, 고전압 전원, 충전, 열관리 | 구동·전원·열관리 기존 / 충전 신규 |
| 섀시 | 제동, 조향, 현가, 변속·주차 | 모두 기존 |
| 차량 제어 | 차량 통합(VCU), 통신·진단, 운전자 지원·HMI | 모두 신규 |

단계 도입: 1차 = 기존 7개 재작성 + 충전·통신·진단 / 2차 = 차량 통합, 운전자 지원·HMI.

## 2. 도메인별 기능 (기능명 / 분류 / 핵심 부품 · SWC / 근거)

### 구동
1. 운전자 토크 요청 해석 / 요구 해석 / APS A·B, VCU `DriverRequest` / 이중 센서 상관성 (ISO 26262 ASIL 가정 시 입력 검증)
2. 구동 허용·인터록 / 제어·배분 / PRND, READY, VCU `DrivePermit`
3. 토크 배분·제한 (가용 토크 MIN) / 제어·배분 / BMS 한계, 모터 한계, 열 한계 → `TorqueArbiter`
4. 인버터 전류·토크 제어 / 실행·보호 / MCU, 3상 브리지, PMSM, 리졸버, dq 전류 PI, 과전류·과온 보호
- 감속기·차동기어는 기능이 아니라 기계 경로(1층)에 포함.

### 고전압 전원
1. 팩 안전 판단 (전압·절연·온도) / 요구 해석 / BMS `PackMonitor`, 절연 모니터
2. 프리차지·접촉기 시퀀스 / 제어·배분 / 프리차지 릴레이, 주 접촉기, 상태기, 용착 진단
3. 출력 가용량(SOP) 계산 / 제어·배분 / SOC·온도·셀 편차 → 방전·회생 한계
4. 고장 차단·HVIL / 실행·보호 / 인터록 루프, 충돌 신호, 접촉기 개방
- OBC·DC/DC는 충전·LV 공급으로 분리 (DC/DC는 아래 "차량 통합"의 12V 전원 관리).

### 충전 (신규)
1. 충전 연결·잠금 확인 / 요구 해석 / 충전구, CP/PP 신호, 잠금 액추에이터, EVCC
2. 충전 전류 협상 (AC: PWM duty, DC: 통신) / 제어·배분 / EVCC `ChargeNegotiator`, BMS 요구
3. OBC 변환 제어 / 실행·보호 / OBC 전류 PI, 충전 접촉기
4. 충전 중 보호·종료 / 실행·보호 / 온도·절연·잠금 이탈 감시

### 열관리
1. 온도 상태 추정 / 요구 해석 / 배터리·모터·인버터·냉각수 NTC, 필터·타당성
2. 펌프·팬·컴프레서 제어 / 제어·배분 / 목표 온도, 히스테리시스, PI
3. 냉각·난방 회로 배분 (히트펌프) / 제어·배분 / 칠러, 전자식 팽창밸브, 방향 밸브, PTC
4. 열 한계 출력 제한 / 실행·보호 / 디레이팅 단계, 복귀 히스테리시스

### 제동
1. 제동력 요구 계산 / 요구 해석 / 페달 A·B, 마스터 실린더 압력
2. 회생·마찰 협조 / 제어·배분 / 회생 가용량(BMS·모터), 마찰 보상
3. ABS·EBD 휠 슬립 제어 / 실행·보호 / 휠속, 유압 모듈레이터, 감압·유지·증압
4. ESC 차체 안정 제어 / 실행·보호 / 요·횡가속도, 휠별 제동

### 조향
1. 조향 입력 해석 / 요구 해석 / 토크·각도 센서, 타당성
2. EPS 보조 토크 계산 / 제어·배분 / 속도별 맵, 센터 보정
3. 모터 전류 제어·랙 구동 / 실행·보호 / EPS 모터, 랙, 전류 PI
4. 폴백·조향 안정 협조 / 실행·보호 / 센서 고장 시 보조 축소, ESC 오버레이

### 현가
1. 노면 입력 해석 / 요구 해석 / IMU, 차고·휠 가속도 센서
2. 댐핑력 제어 (CDC) / 제어·배분 / 차속·상태별 맵, 밸브 전류
3. 차고·자세 유지 (에어 스프링 사양) / 제어·배분 / 컴프레서, 밸브, 누설 진단
4. 센서 고장 폴백 / 실행·보호 / 고정 댐핑, 경고

### 변속·주차
1. PRND 입력 판독 / 요구 해석 / 시프터, 접점·통신 이중 검증
2. 방향 전환 인터록 / 제어·배분 / 차속·브레이크 조건
3. P단 잠금 제어 / 실행·보호 / Park ECU, 잠금 액추에이터, 위치 센서
4. 기어 상태 배포·표시 / 실행·보호 / 상태 인코딩, E2E, 타임아웃

### 차량 통합 VCU (신규, 2차)
1. 차량 상태 관리 (SLEEP / WAKE / READY / DRIVE / FAULT) / 제어·배분 / 상태기, 시동 요청
2. 도메인 요구 중재 / 제어·배분 / 토크·제동·열 요구 우선순위
3. 12V 전원 관리 / 실행·보호 / DC/DC, LV 배터리, 전압 감시
4. 고장 등급·안전 상태 전이 / 실행·보호 / 고장 코드, 림프홈, 경고 요청

### 통신·진단 (신규)
1. 도메인 간 신호 전달 / 요구 해석 / CAN, 게이트웨이, 신호 매핑
2. 통신 건전성 감시 / 제어·배분 / 타임아웃, 롤링 카운터, CRC (E2E)
3. 진단 요청·응답 / 실행·보호 / 진단 포트, UDS, DTC
4. 원격 진단·OTA / 실행·보호 / 텔레매틱스 제어기, 업데이트 조건

### 운전자 지원·HMI (신규, 2차)
1. 전방 인지 (카메라·레이더) / 요구 해석 / 센서 융합, 타당성
2. 목표 감속·거리 제어 (AEB·SCC) / 제어·배분 / ADAS ECU, 제동·구동 요청
3. 경고·개입 협조 / 실행·보호 / 제동·조향 요청 중재
4. 클러스터 표시·경고등 / 실행·보호 / 상태 수신, 점등 조건

## 3. 4층 데이터 규칙 (기능마다 동일)
| 층 | 내용 | 노드 수 | 기존 대비 |
|---|---|---|---|
| 0 기능 흐름 | 의도 → 요구 → 동작 → 결과 | 3~5 | 유지 |
| 1 부품·E/E | 센서 → ECU → 버스 → 구동기 → 부품 | 4~7 | 유지 |
| 2 SW 컴포넌트 | 실제 의미를 가진 SWC 이름, 입출력 포트, 실행 주기 | 3~5 | 신규 시각화 (기존 템플릿 이름 제거) |
| 3 SW 로직 | 함수/블록 단위, 보호·진단 분기 | 4~7 | 유지, 품질 균일화 |

2층 SWC는 AUTOSAR Classic 구조(Runnable, 주기, Port)로 표기합니다 (예: `DriverRequest` 10 ms).

## 4. 도메인 간 협조 신호 맵 (전체 보기에 표시)
| 신호 | 보내는 곳 → 받는 곳 | 목적 |
|---|---|---|
| 방전·회생 한계 | 전원(BMS) → 구동·제동 | 토크·회생 상한 |
| 열 디레이팅 요청 | 열관리 → 구동 | 출력 제한 |
| 회생 요청 토크 | 제동 → 구동 | 회생·마찰 협조 |
| 구동 허용 | 변속·주차, 전원 → 구동 | 출발 조건 |
| 충전 중 구동 금지 | 충전 → 차량 통합 → 구동 | 인터록 |
| 안전 상태 | 차량 통합 → 전 도메인 | 고장 대응 |
| ESC 개입 | 제동 → 조향·구동 | 차체 안정 |
| ADAS 감속 요청 | 운전자 지원 → 제동·구동 | AEB·SCC |
| 기어 상태 | 변속·주차 → 클러스터·구동 | 표시·허용 |
