## 1. 유형별 매트릭스

규모 표기: **S** 데이터/문구만 · **M** 기존 UI 소폭 확장 + 데이터 · **L** 신규 UI 또는 모델 구조 신설.

### 유형 1. 연속적인 수치 편차 (현재 3사건)
| 항목 | 내용 |
|---|---|
| 예 | 스케일링 계수(propulsion ×0.45), I/O 변환 중복(brake ×0.19) |
| STEP01 | 기능의 정상 입력→출력 관계(맵, 한계)를 값과 함께 보여 주기(현재 값 없음) — **M**(필드 추가) |
| STEP02 | 폴라로이드 기준/현장 막대 + 달라진 시각(**현재 지원**) |
| STEP03 | 로직 블록 조립 + 예시 슬라이더 값 흐름(**지원**), 표 A/B(설정 비교 단순형) |
| STEP04 | 연속 그래프 정상 vs 결함, PASS/FAIL(**지원**) |
| 시험 수준 | SW 단위(입력 인가→출력) 또는 I/O 경계 |
| 관측 신호 | 연속 신호(%·Nm·bar) 계산값→출력값 |
| 오라클 | 식 또는 골든 모델 ± 허용오차 |
| 필요 추가 | 없음. 단 정합 데이터(M1·M4·M9) |
| 규모 | **S** |

### 유형 2. 상태 전이 오류
| 항목 | 내용 |
|---|---|
| 예(설명용) | 히스테리시스 임계 뒤바뀜, 변속 인터록(브레이크 없이 P→D 허용), 프리차지 상태기 점프 |
| STEP01 | **상태도 렌즈**: Control SW 관점에서 기능을 상태·전이·조건으로 표시(현재는 블록 이름). 입력 조작(READY·브레이크·D단)이 전이를 일으키는 체험 — 기존 `INPUT_MISSION` 재사용 가능 — **M** |
| STEP02 | 최초 편차 = **상태 값**("ON→OFF"). 폴라로이드에 "상태 + 전이 시각" 표시(문자열 값은 이미 `Dom.ref/run`이 지원) — **M** |
| STEP03 | **상태 전이 구성 퍼즐**: `Kind:"state"` 블록을 상태/전이/가드 조각으로 확장. 기존 슬롯·조각 UI는 재사용 불가에 가까움(간선 편집) — **L** |
| STEP04 | **상태 타임라인 레인** + 전이 이벤트 마커(기존 그래프 아래 보조 레인) — **M** |
| 시험 수준 | SW 단위(상태기 + 입력 시퀀스) → SW 통합 → 제어기(실 신호) |
| 관측 신호 | 상태 변수(enum), 전이 조건 입력(온도·스위치), 전이 발생 시각 |
| 오라클 | **기대 상태 시퀀스**(순서·시간 창), 허용 편차는 시간 기준 |
| 모델 필요 | 상태기 모델(현재 `on` 하나)을 일반화한 이산 상태 시뮬레이터 — **L** |
| 데이터 | 상태·전이·가드 목록, 입력 시퀀스 |
| 규모 | **L** (모델+STEP03 UI), STEP02/04는 M |

### 유형 3. 이벤트 누락 및 오발생
| 항목 | 내용 |
|---|---|
| 예(설명용) | 프리차지 완료 이벤트 미발생→접촉기 미투입, 충돌 신호 오발생→HV 차단 |
| STEP01 | 정상 이벤트 순서(시동→프리차지→접촉기→READY)를 **순서 카드**로 — 전원 도메인 f1 기존 문구 재사용 — **M** |
| STEP02 | 최초 편차 = "발생해야 할 이벤트가 **없음**/**있어서는 안 될 이벤트가 있음**". "값이 다르다"가 아닌 "**일어나지 않았다**" 표현 — 폴라로이드의 값 대신 **이벤트 칩 + 기대 시각** — **M** |
| STEP03 | **이벤트·타이밍 조건 퍼즐**(트리거→동작 규칙 조립; `check`/`switch` 블록 재사용 가능성) — **M~L** |
| STEP04 | **이벤트 타임라인**(기대 마커 vs 실제 마커). 누락은 빈 칸, 오발생은 추가 마커 — **M**(레인 컴포넌트 신규) |
| 시험 수준 | SW 통합(컴포넌트 간 이벤트 전달) → 제어기 I/O → 시스템(실 접촉기) |
| 관측 신호 | 이벤트 플래그·시각, 선행 조건 신호 |
| 오라클 | 기대 이벤트 목록(**존재/부재** + 시간 창) |
| 모델 필요 | 이벤트 생성 규칙(조건→이벤트) — 소형 이산 모델, **L**(현재 없음) |
| 규모 | **M~L** |

| 항목 | 내용 |

| 오라클 | 응답 시간 상한(`within N ms`), 주기 허용 |
| 모델 필요 | **스케줄러/주기 작업 모델 + 버스·샘플 지연 — L**. 현재 수준별 시험은 "같은 모델의 신호 보기"라 타이밍 차이를 계산하지 못함 [기존 UX_AUDIT §9.4(10)-2] |
| 규모 | **L** |

## 4. 우선순위 제안 (결정 필요)
1. **먼저**: 유형 6(조건 분기·로직)과 유형 5(통신·인터페이스) — 기존 UI·모델 재사용도가 높고 신규 구조가 작다.
2. **다음**: 유형 3(이벤트) — 타임라인 레인 컴포넌트 1개가 새 자산.
3. **후속**: 유형 2(상태 전이), 7(진단), 4(타이밍) — 모델·STEP03 UI 신설이 필요(2일 범위 밖).
4. [결정] 공모전 개선판에서 "다양한 결함 유형"을 **몇 유형까지 약속**할지: 현재 3사건은 유형 1·5(brake의 I/O 스케일링)·4(thermal의 실행 순서, 단 현재는 값으로만 표현)에 걸치지만 UI·모델은 모두 유형 1 방식. 유형 4·5의 현재 사건은 **분류상으로는 해당하나 학습 경험은 연속량 비교**라는 점을 인지해야 한다.
