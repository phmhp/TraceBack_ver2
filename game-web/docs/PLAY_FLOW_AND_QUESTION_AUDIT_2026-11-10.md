### STEP02 문제와 추천 로드맵

현재 메인 게임은 유지한다. 실제 필수 **판단**은 3개(Q1~Q3), 필수 **행동**은 출력 선택·입력 재생·측정이며 설명/탭/확대/부착은 질문이 아니다.

1. **Q1/3 — 어느 후보가 출력보다 먼저 달라졌는가?** 측정 표와 시간 순서를 보며 후보를 반박/유력으로 분류한다.
2. **Q2/3 — 최초 편차가 시작된 의심 구간은 어디인가?** Q1의 남은 경로를 근거로 3지선다를 고른다.
3. **Q3/3 — 지금 증거만으로 각 경쟁 가설을 어떻게 기록할 것인가?** `반박` 또는 `보류`만 허용한다. `지지`/근본 원인 확정은 STEP04 시험 결과 뒤에만 허용한다.

따라서 측정값을 본 직후 같은 사실을 객관식으로 다시 묻는 추가 퀴즈, SW 내부 계산의 세부 정답 암기는 삭제/통합 후보다. `sortHyp`의 목적은 경쟁 가설을 **보류 포함**으로 전달하는 것이며, `EeTrace.finish()`의 `SELECT_HYPOTHESIS(scenario.root)`는 T-25로 분리 수정해야 한다.

| 사건 | STEP02가 확정해도 되는 것 | STEP03/04로 넘길 것 |
|---|---|---|
| propulsion | 센서는 기준과 같고 VCU 처리 이후 명령이 낮음 | VCU SW 계산 vs 입력회로 경쟁 가설, 의심 구간, 측정 경로 |
| thermal | 팬 요청과 PWM/피드백 경계의 불일치가 의심됨 | 정상 PWM/1850 rpm 정의를 기술 정합 후 확정; 상태전이 vs 출력 어댑터 가설 |
| brake | 일반 플레이 미도달 | 데이터/정답 ID/신호 의미 T-02~04/T-11 정합 후에만 설계 |

### STEP04 실제 질문 로드맵 제안

사건별 N은 현재 `QUESTIONS[caseId]`의 실제 가설 수를 따라 propulsion **2**, thermal **3**, brake **3**(미도달)로 고정한다. 실행 버튼·탭 이동·도움말·입력 선택은 질문 수가 아니다.

1. **Q1/N — 이 가설을 가르려면 어느 시험 수준이 필요한가?** 시험 수준 선택. 선택 이유는 “어느 경계가 보이는가”로 즉시 피드백.
2. **행동 — 같은 입력 조건을 정하고 시험을 실행한다.** 계약에서 가져온 값과 실제 모델 입력을 명시한다.
3. **Q1/N의 판정 — 결과는 이 가설을 지지/반박/판단 불가 중 무엇인가?** 관찰 신호와 기준선이 표시된 뒤에만 답한다.
4. 다음 가설로 반복하고, 마지막 보고서에서 **수리 조치 선택**과 **동일 조건 재시험**을 별도 행동으로 둔다.

`level` 선택과 가설 판단은 교육 목적이 달라 하나의 질문으로 합치지 않는다. 단, 각 가설은 “시험 선택 → 실행 → 판단”이라는 하나의 번호 블록으로 표시해 진행 번호가 중간에 바뀌지 않게 한다.

## 8. 우선순위·승인 필요 사항

1. **P0 기술 정합:** T-25/T-32 → T-24 → T-22/T-23/T-27 → thermal T-01/T-08. 질문/화면 개선보다 데이터 진실성이 선행한다.
2. **P1 흐름:** STEP02 Q1~Q3 상태 모델과 STEP03 Q1/1, STEP04 사건별 Qn/N/공개 규칙을 구현한다.
3. **P1 UI QA:** 1054×723 STEP02~04, 반복 왕복, Windows Chrome, STEP04 M-07을 실제 브라우저로 확인한다.
4. **P2 범위 결정:** brake를 일반 경로에 넣을지, 미도달 콘텐츠로 명시할지 결정한다.

사용자 승인이 필요한 설계 결정:

- brake 사건을 필수 2사건 이후의 선택 사건으로 복구할지, 현재처럼 비활성 데이터로 둘지.
- STEP02에서 가설을 `보류`로만 남기고 STEP04에서만 `지지`를 허용할지.
- STEP03 계약을 실제 모델 입력으로 만드는 범위와, 계약과 모델이 불일치할 때 어느 쪽을 SSOT로 삼을지.
- 수리 오답의 실제 부작용 모델링 범위 및 추격 보상 규칙.

## 9. 최종 결론

유지할 것은 STEP02 보드의 역추적·증거 레이아웃, STEP03 드래그 퍼즐, STEP04 검증 작업대/네 관점 탭, 공통 프레임, 저장·다시 풀기·추격 흐름이다. 재설계 대상은 이 메인 게임 위에 얹힌 판단의 순서와 정보 공개다.

권장 최종 필수 판단 수는 STEP02 **3개**, STEP03 **1개**, STEP04 **propulsion 2개 / thermal 3개 / brake 3개(도달 경로 승인 후)** 이다. 이 수는 현재 질문·가설 데이터에 근거한 설계 제안이며, 승인 전 구현 사양이 아니다.
