# C06 추운 아침 첫 감속이 너무 세요 (도메인 간 협조 신호: 회생 한계 미반영)

레벨 배치: **7레벨 선택(마지막 탈출은 8레벨로 이동)**, `CaseId` `cold`.
선정 근거: 사용자 요청(2026-11-15 3.5): 퍼즐 단계에서 **도메인 수준** 사건이 없다. 이 사건은 기능 하나가 아니라 **도메인 사이 협조 신호**(고전압 전원 → 구동·제동)를 다루고, 정비소 "차량 시스템 › 도메인 협조 신호" 화면에서 시작합니다. UI 유형은 `ui: "path"`(신호 경로 선택)를 **도메인 단위**로 재사용합니다.

## 0. 한 줄 요약
추운 상태에서 가속 페달을 떼면 평소보다 훨씬 세게 감속하고 가끔 바퀴가 미끄러지는 느낌이 납니다 → 제동 도메인이 BMS의 **회생 수용 한계(저온에서 낮아짐)**를 받지 않고 **상온 한계값을 고정으로** 써서 회생을 과하게 요구하고, 구동 도메인이 그 값을 그대로 따릅니다.

## 1. 개요
| 항목 | 내용 |
|---|---|

| 고장 범주 | C 통신·협조(주), K 구성(보조: 한계값 고정) |
| 빈도·심각도 | 보통(저온 구간) · 중(과한 감속, 뒤차 추돌 위험) |
| 가르는 수준 | **시스템 통합 시험**(BMS·게이트웨이·제동·구동 제어기가 함께 도는 모델에서 배터리 온도 재현). SW 단위·통합·임베디드는 단일 ECU라 판단 보류 |
| 새 학습 | 도메인이 서로 주고받는 **협조 신호의 수신 측 사용 여부**를 확인한다. 값이 맞게 보내져도 받는 쪽이 고정값을 쓰면 환경(온도)이 바뀔 때만 문제가 드러난다 |
| 표준 | ASPICE SYS.3/SYS.4/SYS.5(시스템 설계·통합), SWE.5, ISO 26262-4(도메인 간 안전 요구 할당) |
| 난이도 | 3 |
| 정비소 연결 | 차량 시스템 › **도메인 협조 신호** "방전·회생 한계"(BMS → 제동·구동), 구동 기능 "토크 배분·제한", 제동 기능 "회생·마찰 협조" |

## 2. 운전자가 보는 것
- 시점·트리거: 배터리 온도가 낮은 구간(레이스에서는 시작 후 첫 60초 또는 `environment` 존 "cold"). 가속 페달을 40 km/h 이상에서 떼는 순간. 지속성: **영구**(조건이 있는 동안)
- 화면·경고등: 계기판 회생 표시가 평소보다 크게 나오고 경고등 없음
- 운전자 진술: "발만 뗐는데 확 서요. 추울 때만 그래요."

### 2.1 레이싱 영향·추격 연동 (R17)
| 항목 | 내용 |
|---|---|
| 이동 가능 여부·방향 | 전진 가능 |
| 속도·가속 | 페달을 뗄 때 감속이 평소의 약 2.2배(−0.5 → −1.1 m/s²). 가속은 정상 |
| 조작 가능 범위 | 가속·제동·조향 정상(조향은 감속 중 하중 이동으로 약간 무거워지는 연출만) |
| 시동 | 유지 |
| 충돌 위험 | 중간(뒤차 추돌: 상황 세트 1 뒤차 규칙과 연결) |
| 추격차 변화 | 속도가 빨리 떨어져 경찰이 따라붙음. 페달을 계속 밟으면 영향 없음(해결 힌트) |
| 정상 동작과의 대비 | 추울 때 회생이 줄어드는 것은 정상이며, 그만큼 마찰 제동이 보충한다 |
| 레이스 연출 | `FaultEffect`에 `regenScale`(신규) 또는 기존 `brakeScale`/코스팅 감속 계수 확장. 트리거 `environment` 존 `cold` 신규 |

## 3. 정상 기준
- 요구사항: BMS가 보내는 회생 수용 한계(온도 의존: 25 °C에서 60 Nm, 0 °C에서 20 Nm)를 제동·구동 도메인이 **매 주기 받아서** 회생 요청의 상한으로 쓴다. 한계를 넘는 몫은 마찰 제동이 채운다.
- 입력 → 출력 표(허용 오차 ±3 Nm):

| 배터리 온도 | BMS 회생 한계 | 제동이 쓰는 한계 | 회생 토크 | 마찰 보충 |
|---|---|---|---|---|
| 25 °C | 60 Nm | 60 Nm | 40 Nm(요청 40) | 0 |
| 0 °C | 20 Nm | 20 Nm | 20 Nm | 20 Nm |

## 4. 고장 모델
- 주입 지점: 제동 도메인 회생·마찰 협조 SWC(`RegenLimitRx`)가 협조 신호를 읽지 않고 **고정 상한 60 Nm**를 사용(`REGEN_LIMIT_FIXED`).
- 정상 vs 고장(0 °C, 회생 요청 40 Nm): 제동이 쓰는 한계 20 vs **60**, 회생 토크 20 vs **40**, 마찰 보충 20 vs 0, 감속 −0.5 vs −1.1 m/s²(주행 저항 포함 근사). BMS가 보내는 값(20 Nm)과 게이트웨이 전달 값은 **정상**.
- 달라지는 순서: 제동 쪽 한계값(최초 편차) → 회생 요청 토크 → 인버터 토크 → 차량 감속.

## 5. 진단 (R11)
- 진단이 잡았는가: **못 잡음**(회생 토크가 BMS 한계를 넘는 조건에 대한 감시가 없음). 경고등 없음. 학습 연결: "협조 신호는 보내는 쪽만 검증하면 안 되고 받는 쪽 사용 여부도 시험해야 한다".

## 6. STEP02 데이터 (요약)
- 증상 카드: 감속 느낌(기준 −0.5 · 이번 −1.1 m/s²) / 조향 반응 / 가속 반응(정상)
- 노드: 차량 감속(결과) ← 인버터 회생 토크 ← 제동 쪽 한계값(최초 편차, 기준 20 · 이번 60 Nm) ← 게이트웨이 한계 전달(정상 20) ← BMS 회생 한계(정상 20) ← 배터리 온도(정상 0 °C)
- 함정: 인버터 토크가 크다는 이유로 인버터·모터를 의심(결과일 뿐), 날씨 때문이라고 보는 오해
- 의심 구간: ① BMS 회생 한계 산출(반박: 값 정상) ② **제동 도메인의 한계 수신·사용(정답)** ③ 게이트웨이 신호 중계(반박: 전달값 정상)
- 가설 4개: BMS 한계 산출 로직(통신 아님, 반박) / 게이트웨이 중계 지연(통신, 반박) / **제동 도메인 한계 고정값 사용(SW 설정, 참)** / 인버터 토크 제한 설정(SW 설정, 반박: 요청이 이미 크다)

## 7. STEP03 데이터 — UI: **신호 경로 선택(도메인 수준)** (R23)
- 판: 차량 시스템 구조도에서 도메인 사각형(고전압 전원, 제동, 구동)과 협조 신호 화살표. 플레이어가 **도메인 사이 경로 빈칸 2개**(BMS → ? → 제동, 제동 → ? → 구동)와 **규칙 표 1개**(한계 사용 방식: 수신값 사용 / 고정값 60 Nm)를 채운다.
- 조각: 게이트웨이 중계(정답), 직결(함정), 한계 수신 사용(정답 표 A), 고정 상한 표 B(함정, 같은 블록 다른 표 값), 구동 직접 한계(다른 도메인 블록).
- 요구사항 줄·시험 설계서: 0 °C, 회생 요청 40 Nm → 제동이 쓰는 한계 20 Nm, 회생 토크 20 Nm(±3). 설계서의 "이 시험이 보는 영역"에서 `정비소에서 보기` → 차량 시스템 › 도메인 협조 신호.

## 8. STEP04 데이터 (요약)
- 시스템 통합에서만 결정: 배터리 온도 재현으로 BMS 한계가 낮아졌을 때 제동 쪽 한계가 그대로 60 Nm이면 지지. 25 °C 입력은 고장이 드러나지 않음(재현 입력 선택 R6: 25 °C / 0 °C / −10 °C).
- 수리 선택지: ① 협조 신호의 한계를 읽도록 복원하고 저온 시험 추가(정답) ② 감속 필터로 값을 완화(증상 가림) ③ BMS 한계를 올림(안전 침해)

## 9. 정비소·학습 연결 (R13)
- 차량 시스템 › 도메인 협조 신호 "방전·회생 한계" → 제동 "회생·마찰 협조" → 구동 "토크 배분·제한". 오픈북 `BOOK.cold`에 같은 항목.
- 배운 원리 3줄: 1. 도메인은 협조 신호로 서로의 한계를 전달해요. 2. 받는 쪽이 값을 쓰지 않으면 환경이 바뀔 때만 문제가 드러나요. 3. 협조 신호는 보내는 쪽과 받는 쪽을 둘 다 시험해요.

## 10. 안전·확장 (R12)
- 위험: 저온에서 과도한 회생 감속(뒤차 추돌, 후륜 슬립). 안전 목표 "회생 토크는 BMS가 허용한 한계를 넘지 않는다". ASIL은 위험 분석에 따르므로 지정하지 않음. 안전 메커니즘: 수신 측 한계 클램프, 협조 신호 타임아웃·유효성.
