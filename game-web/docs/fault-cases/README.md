# 고장 시나리오 작성 규칙 · 템플릿 (개발 에이전트용 진입점)

새 고장 사건을 추가하거나 기존 사건을 고치는 사람(또는 에이전트)은 **이 폴더의 문서만 읽고 같은 규칙으로 작업**할 수 있어야 합니다.

| 순서 | 문서 | 용도 |
|---|---|---|
| 1 | `RULES.md` | 모든 사건에 적용되는 규칙(번호 R1~R15). 위반하면 사건이 아닙니다 |
| 2 | `../FAULT_CASE_SELECTION_V3.md` | 사건을 고르는 기준(게이트, 균형, 점수), 고장 범주·시점 분류, 후보 목록 |
| 3 | `TEMPLATE_CASE_SHEET.md` | 사건 시트 양식. 구현 전에 `docs/fault-cases/<id>.md`로 복사해 채우고 승인받습니다 |
| 4 | `DIAGNOSTICS_AND_FUTURE.md` | 진단(DTC·경고등) 채널, 기능안전·AUTOSAR 확장을 위한 예약 필드 |
| 5 | `CHECKLIST.md` | 구현 후 화면별 대조 검수표 |
| 6 | `LEVEL_PROGRESSION_AND_LEARNING_LINKS.md` | 레벨형 진행과 정비소 학습 연결 설계 (승인 대기) |
| 예시 | `n01_regen_sign.md`(첫 사건 시트, 승인 대기), `speedo.md`(R16으로 제외, 보관) | 사건 시트 작성 예 |
| 참고 | `AUDIT_EXISTING_2026-11-14.md` | 기존 3사건을 규칙에 비춰 검수한 결과와 수정 내역 |
| 참고 | `../DESIGN_DECISIONS_V3.md` | 단계별 화면·데이터 계약(7절 사건 추가 파일 표 포함) |

작업 흐름: 후보 선정 → 사건 시트 작성 → 시트 교차 검토(GPT/사람) → 승인 → 구현 → 체크리스트 대조 → 전수 UI 검수 → 시트 갱신.
**사건을 한꺼번에 만들지 않습니다.** 한 번에 한 사건, 시트가 승인되기 전에는 코드를 쓰지 않습니다.
