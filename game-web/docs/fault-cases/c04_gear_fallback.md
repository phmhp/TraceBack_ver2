# C04 D에 놓았는데 가끔 뒤로 가요 (변속 신호 타임아웃 폴백값 오류)

상태: **초안 (승인 대기)**   작성: 2026-11-15   템플릿: `TEMPLATE_CASE_SHEET.md`   규칙: R1~R17 (+ `../PLAYER_FLOW_AUDIT_2026-11-15.md` 6절 R18~R23 제안 반영)
레벨 배치: 미정(제안: 6레벨 선택). 구현 시 새 `CaseId`(예: `gear`)와 **새 퍼즐 유형 "신호 경로 선택"**이 필요합니다.

## 0. 한 줄 요약
기어를 D에 놓고 바로 출발하면 가끔 차가 뒤로 움찔하거나 반응이 없습니다(계기판은 D) → VCU가 변속 위치 메시지를 100 ms 안에 못 받으면 쓰는 **타임아웃 폴백값이 안전 값(N)이 아니라 R(후진)로 설정**돼 있습니다.

## 2. 운전자가 보는 것
- 시점·트리거: **정차 → 출발**. 변속 레버를 P에서 D로 바꾸고 **0.3초 이내에 가속 페달**을 밟을 때. 지속성: **간헐**(재현 조건: 변속 직후 0.3초 이내 출발. 2초 이상 기다렸다 출발하면 정상)
- 화면·소리·경고등: 계기판은 D 표시. 출발 때 차가 뒤로 움찔하거나(후진 경고음 없음) 잠깐 반응이 없다. 경고등 없음.
- 이후 흐름: 0.5초 뒤 정상 전진. 같은 일이 반복돼 고양이가 차를 세우고 조사한다.
- 운전자 진술 (해요체): "D에 놓았는데 가끔 뒤로 가요."
- 표현 제한: 접촉·충돌 장면 없음(후진은 최대 6 km/h, 0.5초).

## 3. 정상 기준 (요구사항)
- 요구사항: 변속 위치 메시지(`Gear_Status`)는 20 ms 주기로 전달되고 VCU는 마지막 수신 후 **100 ms(5주기)** 안에 새 메시지가 없으면 통신 오류로 보고 **안전 값 N(중립)**을 쓴다. 정상 수신이 재개되면 즉시 복귀한다.
- 입력 → 출력 수치 표 (허용 오차 ±10 ms):

| 상황 | 메시지 간격 | VCU가 쓰는 기어 값 | 구동 |
|---|---|---|---|
| 정상(버스 부하 40 %) | 20 ms | D | 전진 |
| 변속 직후 버스 부하 85 % | 120 ms | **N**(타임아웃 100 ms 초과) | 구동 토크 0(움찔 없음) |
| 수신 재개 | 20 ms | D | 전진 |
- 관계식: 타임아웃 = 5 × 20 ms = 100 ms. 버스 부하 85 %일 때 최악 수신 간격 120 ms는 타임아웃보다 크다. 폴백 값은 N.

## 4. 고장 모델
- 주입 지점: VCU 변속 수신 SWC(`GearRx`)의 **E2E 타임아웃 폴백값 설정**(`GEAR_FALLBACK`)이 N이 아니라 **R**.
- 정상 vs 고장 (변속 직후 0.3초, 버스 부하 85 %):

| 항목 | 정상 | 고장 |
|---|---|---|
| 메시지 간격 | 120 ms(같음) | 120 ms(같음, 버스 응답은 정상) |
| 타임아웃 판정 | 100 ms 초과 → 통신 오류 | 같음(감시는 정상 동작) |
| 폴백 값 | N | **R** |
| 구동 지령 (페달 40 %) | 0 Nm | **후진 토크 약 -60 Nm** |
| 차량 | 정지 유지 | 후진 최대 -6 km/h, 0.5초 |
- 달라지는 시점(변속 후): 수신 간격 120 ms(정상·고장 동일) → 100 ms 타임아웃 판정(동일) → 100 ms 폴백 값(N vs R) → 120 ms VCU 구동 지령 → 200 ms 모터 토크 → 300 ms 차량 후진 시작. 계기판은 클러스터가 레버 신호를 직접 받아 D를 계속 표시한다(함정: 계기판이 정상이라 "변속 신호는 문제없음"으로 오해).
- 영향 없는 신호: 변속 레버 위치(D), 게이트웨이 입력·출력(D, 카운터 정상), 브레이크 신호, 계기판 기어 표시(D), 차속 센서.

## 7. STEP03 데이터 — **새 퍼즐 유형: 신호 경로 선택 (시스템·E/E 수준)**
- UI 종류: **신호 경로 선택**. 로직 블록이 아니라 E/E 구조도 위에서 신호가 지나는 노드와 연결, 그리고 지점마다 적용되는 규칙(표)을 고른다. 정비소의 "시스템 › E/E" 도식(`EeBlueprint`)과 같은 그림을 써서 연결감을 준다.
- 요구사항 줄: ① 변속 레버 위치는 게이트웨이를 거쳐 CAN으로 VCU에 20 ms 주기로 전달된다 ② VCU는 100 ms 안에 새 메시지가 없으면 통신 오류로 본다 ③ 통신 오류일 때는 안전 값 N을 쓴다 ④ 계기판은 레버 신호를 별도 경로로 직접 받아 표시한다
- 판: E/E 구조도(센서 → 게이트웨이 → CAN 버스 → VCU, 클러스터 별도 경로). 플레이어가 하는 일은 두 가지:
  1. **경로 연결(빈칸 2개):** `시프터 → [?] → CAN` (중계 ECU 고르기), `CAN → [?] → 구동` (수신 처리 고르기)
  2. **규칙 표 고르기(빈칸 1개):** VCU 수신 처리의 **타임아웃 규칙 표**에서 A/B 중 맞는 표를 고른다
- 남은 조각 5개: 게이트웨이(정답) · 직결 연결(다른 구조, 함정) · 수신 처리 표 A(타임아웃 100 ms · 폴백 N) · 수신 처리 표 B(타임아웃 100 ms · 폴백 R, 함정: 같은 블록 다른 표 값) · 마지막 값 유지 규칙(다른 정책, 함정: "마지막 유효 값을 계속 쓰기")
- 옆 입력(병렬): 클러스터는 별도 경로로 직접 받음(계기판 D가 정상인 이유를 보여 줌)
- 함정 조각과 구분 기준: 표 B는 "실행 결과 폴백이 R이라 후진해요. 요구사항은 안전 값 N". 마지막 값 유지는 "변속 직전 값이 P/D 어느 것이든 계속 쓰여 위험하다".
- 예시 입력 슬라이더: 이름 "메시지 간격", 단위 ms, 범위 0~200, 요구사항 값 120(변속 직후 버스 부하 85 %일 때). 슬라이더를 움직이면 경로 위 값(수신 상태, 기어 값)이 바뀌어 100 ms를 넘으면 폴백이 켜지는 것을 본다
- 시험 설계서: 입력 조건 = P→D 변속 후 0.2 s에 페달 40 % · 버스 부하 85 %(메시지 간격 120 ms), 기대값 = VCU 기어 값 N · 구동 지령 0 Nm(허용 ±5 Nm), 관측 신호 = 메시지 간격·VCU 기어 값·구동 지령, 목적 = "VCU 수신 처리 설정과 게이트웨이·변속 레버 중 원인 구분"
- "왜 필요한가" 문장: "통신이 끊겨도 차가 엉뚱한 방향으로 가면 안 되므로, 끊겼을 때 쓰는 값은 가장 안전한 값이어야 해요."
- **정비소 연결 버튼:** 설계서의 "이 시험이 보는 영역"에서 `정비소에서 보기` → 변속·주차 › 기어 상태 › 부품·E/E 층으로 이동(시스템 수준 사건이라 시작은 차량 시스템 › E/E 그림)

| 신호 | SW 단위 | SW 통합 | 임베디드 | 시스템 통합 |
|---|---|---|---|---|
| 변속 레버 위치·브레이크(입력) | 주입 | 보임 | 보임 | 보임 |
| 메시지 간격 | - | - | - | **보임**(버스 부하 재현) |
| VCU 기어 값(폴백 적용 후) | 보임(메시지 지연 없이 정상) | 보임 | 보임 | 보임 |
| 구동 지령 | - | - | 보임 | 보임 |
| 차량 거동 | - | - | - | 보임 |
- 가설별 판정 규칙:
  - 폴백 값 설정(참): **시스템 통합에서 지지**(메시지 간격 120 ms일 때 기어 값 R이 나옴). 단위·통합·임베디드는 단일 ECU라 버스 지연을 만들 수 없어 **판단 보류**(다음: 시스템 통합).
  - 게이트웨이 매핑(오답): **시스템 통합에서 반박**(게이트웨이 출력 D이고 카운터 정상).
  - 변속 레버 HW(오답): **시스템 통합에서 반박**(레버 위치 D). 이하 단위·통합은 보류.
  - 인터록 로직(오답): 단계 1에서 반박(브레이크 입력 정상).
- **재현 입력 선택(R6, 간헐 고장):** 입력 파생 3종: ① 변속 직후 0.2초 출발(버스 부하 85 %, 고장이 드러남) ② 변속 후 2초 대기 출발(버스 안정, **고장이 안 드러남 → 이 입력으로는 판단 불가**) ③ 평상시 부하 40 %로 출발(안 드러남). 플레이어가 재현 조건을 골라야 한다.
- 최종 원인 카드: 이름 "변속 수신 폴백값 설정 오류" · 유형 "구성·파라미터 오류(통신 폴백)" · 위치 "VCU · 변속 수신 SWC" · 설명 "타임아웃 때 쓰는 값이 안전 값 N이 아니라 R로 설정" · 이미지 VCU(재사용)
- 수리 선택지 3개 (정답 **1번째**): ① 폴백 값을 N으로 복원하고 통신 타임아웃 시험 추가 (정답) ② 변속 후 1초간 가속 페달을 무시 (증상 가림: 출발이 느려지고 다른 폴백 오류는 그대로) ③ 타임아웃을 100 ms에서 300 ms로 늘리기 (무관/부작용: 폴백이 늦게 켜질 뿐 값은 R이고 실제 통신 끊김 대응이 늦어짐)
- 재시험 합격 조건: 같은 입력(변속 후 0.2초 출발, 버스 부하 85 %)에서 기어 값 N, 구동 지령 0 Nm. 회귀: 정상 부하에서 D 출발 정상, 의도적 R 후진 정상, 통신 복구 때 즉시 복귀

## 9. 정비소·학습 연결 (R13)
- 시스템 수준 → E/E → 도메인 → 기능 순서로 연결: 차량 시스템 › E/E 아키텍처 › 변속·주차 › 기어 상태(4층), 통신·진단 › 신호 수신·폴백. 오픈북 `BOOK.gear`에 같은 기능 연결
- 오픈북 노트 문구 (정답 비공개): "변속 위치는 20 ms마다 CAN으로 오고, 100 ms 동안 새 메시지가 없으면 VCU는 통신 오류로 보고 가장 안전한 값(N)으로 바꿔요."
- 사건 후 "배운 원리" 3줄: 1. 통신이 끊겼을 때 쓰는 값(폴백)은 안전한 방향이어야 해요. 2. 계기판이 정상이어도 제어기가 받는 값은 다를 수 있어요(경로가 달라요). 3. 간헐 고장은 재현 조건을 골라야 보여요.
