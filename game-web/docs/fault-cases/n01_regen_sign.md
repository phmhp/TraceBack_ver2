## 0. 한 줄 요약
가속 페달에서 발을 떼면 감속해야 하는데 오히려 속도가 올라갑니다 → VCU가 회생 요청의 부호를 반영하지 않아 토크 지령이 반대 방향(구동)으로 나갑니다.

## 2. 운전자가 보는 것
- 시점·트리거: **가속 페달을 놓는 순간(코스팅 회생이 켜지는 조건: 속도 40 km/h 이상, 페달 0%)**. 긴 내리막이면 더 뚜렷하지만 필수는 아님(현재 코스 평지에서 재현 가능). 지속성: 영구(조건이 맞는 동안 계속)
- 화면·소리·경고등: 속도 숫자가 페달을 놓은 뒤에도 올라감. 회생 표시(계기판)가 충전 쪽으로 가지 않음. 경고등 없음.
- 이후 흐름: 브레이크 페달(마찰 제동)은 정상이라 멈출 수는 있다. 고양이가 "발을 뗐는데 더 빨라져요"라고 알리고 차를 세워 조사한다.
- 운전자 진술: "발을 떼도 차가 계속 빨라져요."
- 표현 제한: 사고 장면 없음(가속과 제동으로 정지까지만).

### 2.1 레이싱 영향·추격 연동 (R17)
| 항목 | 내용 |
|---|---|
| 이동 가능 여부·방향 | 전진 가능, 페달을 놓으면 오히려 가속 |

| 조작 가능 범위 | 조향 가능, **마찰 제동은 정상**(감속 가능), 가속 페달 off로는 감속 불가 |
| 시동 상태 | 유지 |
| 충돌 위험 | **높음**: 속도가 계속 올라 앞차·가드레일 접촉 위험. 충돌 연출·상대 차 반응·고양이 반응 필수 |
| 추격차 변화 | 가속하면 추격차는 벌어지지만 충돌하면 속도 손실로 추격차가 급감. 안전하게 멈추면(정차) 추격차 접근 |
| 정상 동작과의 대비 | 충돌 시 에어백·HV 차단은 정상 동작(고장 아님) |

## 3. 정상 기준 (요구사항)
- 요구사항: 가속 페달 0%이고 속도 40 km/h 이상일 때 코스팅 회생이 동작해, 모터 토크 지령은 회생 요청과 같은 방향(−40 Nm)이어야 한다. 이때 차량 가감속은 평지 기준 −0.5 m/s²이다.
- 관계식: 40 Nm ↔ 0.5 m/s² (80 Nm당 1 m/s²), 평지 기준.

| 입력 | 정상 출력 |
|---|---|
| 회생 요청 −40 Nm | 토크 지령 −40 Nm → 가감속 −0.5 m/s² |
| 회생 요청 −80 Nm | 토크 지령 −80 Nm → −1.0 m/s² |
| 회생 요청 0 Nm | 토크 지령 0 Nm → 0 |
허용 오차: 토크 ±2 Nm, 가감속 ±0.1 m/s².

## 4. 고장 모델
- 주입 지점: VCU 토크 지령 변환 SWC의 **회생 요청 부호 반영 블록 누락**(요청의 크기만 쓰고 부호를 버림)
- 정상 vs 고장 (회생 요청 −40 Nm): 지령 −40 → **+40 Nm**, 가감속 −0.5 → **+0.5 m/s²**
- 달라지는 시점(코스팅 시작 후): VCU 변환 출력 10 ms → CAN 토크 지령 20 ms → 모터 토크 30 ms → 배터리 전류 40 ms(함정) → 차량 가감속 60 ms
- 영향 없는 신호: Brake ECU 회생 요청(−40), 가속 페달 값(0%), 차속(60 km/h), 기어 D, 마찰 제동 감속(3.2 m/s²), 조향 반응

## 7. STEP03 데이터
- UI 종류: 블록 조립
- 요구사항 줄: ① 페달 0%·40 km/h 이상에서 코스팅 회생 동작 ② 토크 지령은 회생 요청과 같은 방향(음수) ③ 회생 크기는 가용 회생 한계 이내
- 판: 회생 요청 수신(CAN) → 부호 반영 → 가용 회생 한계(MIN) → 램프율 → 토크 지령 출력
- 빈칸: 부호 반영(2번), 가용 회생 한계(3번)
- 남은 조각 5개: 부호 규약 표 A(요청 음수 → 지령 음수) · 부호 규약 표 B(요청 음수 → 지령 양수, 함정: 같은 블록 다른 표) · 가용 회생 한계 MIN · 페달 맵(다른 기능, 함정) · 평균 필터
- 슬라이더: 회생 요청 −80~0 Nm, 요구사항 값 −40
- 시험 설계서: 입력 회생 요청 0 → −40 Nm 유지 5 s(페달 0%, 속도 60 km/h), 기대 토크 지령 −40 Nm ±2, 관측: 회생 요청·지령·모터 토크
- 왜 필요한가: "방향이 틀리면 크기가 맞아도 정반대로 움직여요."

## 8. STEP04 데이터
- 질문(가설별, 해요체): "Brake ECU가 틀린 요청을 보낸 건가요?" / "가속 페달 값이 틀린 건가요?" / "VCU가 회생 요청의 부호를 놓친 건가요?" / "인버터 배선이 반대로 연결된 건가요?"
- 수준별 관측 신호:
| 신호 | SW 단위 | SW 통합 | 임베디드 | 차량 |
|---|---|---|---|---|
| 회생 요청(입력) | 주입 | 보임 | 보임 | 보임 |
| VCU 지령 변환 출력 | 보임 | 보임 | 보임 | 안 보임 |
| CAN 토크 지령 | - | 보임 | 보임 | 보임 |
| 모터 토크 | - | - | 보임 | 보임 |
| 차량 가감속 | - | - | - | 보임 |
- 판정: VCU 가설은 SW 단위에서 **지지**(입력 −40 → 출력 +40). 차량 수준은 **판단 보류**(가속이 보이지만 위치 불명, 다음: SW 단위). Brake·페달은 요청·페달 값이 정상으로 **반박**. 배선(HW)은 구동 토크 방향이 정상임을 보는 임베디드/차량 시험에서 **반박**.
- 수리 선택지 (정답 **2번째**): ① 코스팅 구간 가속 페달 off일 때 토크 지령을 0으로 고정 (증상 가림: 회생 감속이 사라져 감속감이 없고 연비·제동 협조가 깨짐) ② 회생 요청의 부호 규약을 인터페이스 정의대로 반영하고 부호 단위 시험 추가(정답) ③ 모터 최대 토크 한계를 낮추기 (무관: 가속이 줄 뿐 부호 오류는 그대로)
- 재시험 합격: 같은 입력에서 토크 지령 −40±2, 가감속 −0.5±0.1. 회귀: 평지 코스팅 감속, 회생·마찰 협조 전환, 구동 가속 시 토크 방향

## 9. 정비소·학습 연결
- 정비소: 구동 기능 3(토크 배분·제한)의 4층, 제동 기능 2(회생·마찰 협조)의 "회생 한계" 신호
- 오픈북 노트: "회생 중에는 모터가 브레이크처럼 일하므로 토크 지령은 음수(감속 방향)다. VCU는 Brake ECU의 회생 요청을 받아 같은 방향으로 지령한다."
- 배운 원리 3줄: ① 방향(부호) 규약이 틀리면 크기가 맞아도 정반대로 동작한다 ② 진단 모니터는 작동 범위 밖에서는 고장을 못 잡을 수 있다 ③ 구간별로 입력과 출력을 비교하면 어느 단계에서 뒤집혔는지 알 수 있다
