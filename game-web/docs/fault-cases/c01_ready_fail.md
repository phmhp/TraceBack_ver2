## 0. 한 줄 요약
시동 버튼을 눌러도 READY가 켜지지 않고 시동이 반복해서 실패합니다 → VCU 시동 시퀀스의 "프리차지 완료 대기 시간"이 설계값(1500 ms)보다 짧게(500 ms) 들어가, 정상적으로 충전 중인 고전압 버스를 "실패"로 판정합니다.

## 2. 운전자가 보는 것
- 시점·트리거: **시동 전**. 브레이크를 밟고 시동 버튼(레이싱에서는 R 키)을 누르는 순간. 지속성: 영구(누를 때마다 반복)
- 화면·소리·경고등: 클러스터가 잠깐 켜졌다가 READY 표시 없이 꺼지고 "HV 시스템 점검" 표시등이 켜진다. 접촉기 "딸깍" 소리는 한 번만 난다.
- 이후 흐름: 레이스 출발 전 시동을 3번 시도해도 READY가 안 켜지면 볼트가 차를 세우고 조사한다(차는 움직이지 않는다).
- 운전자 진술 (해요체): "시동 버튼을 눌러도 READY가 안 켜져요."
- 표현 제한: 사고·위험 장면 없음. 차가 못 움직일 뿐 안전 위협은 없다.

## 3. 정상 기준 (요구사항)
- 요구사항: 시동 요청을 받으면 VCU 시동 시퀀스는 프리차지 접촉기를 닫고, HV 버스 전압이 팩 전압의 95 % 이상이 되면 주 접촉기를 닫아 READY로 전환한다. 프리차지 완료 대기 시간은 **1500 ms**이다.
- 정상 프리차지 곡선(RC 충전): 팩 전압 400 V, 시정수 τ = 250 ms, 버스 전압 V(t) = 400 × (1 − e^(−t/250 ms)).
- 입력 → 출력 수치 표 (허용 오차: 전압 ±5 V, 시간 ±50 ms):

| 시각 (프리차지 시작 후) | HV 버스 전압 | 95 % (380 V) 도달 | 시퀀스 상태 |
|---|---|---|---|
| 250 ms | 252.8 V | 아니오 | PRECHARGE |
| 500 ms | 345.9 V | 아니오 | PRECHARGE (정상) |
| 750 ms | 380.1 V | **예** | 주 접촉기 닫기 → READY |
| 1500 ms | 399.0 V | 예 | READY 유지 |
- 관계식: 95 %까지 걸리는 시간 = −τ·ln(0.05) = 250 × 3.0 = 약 750 ms. 타임아웃 1500 ms는 이 시간의 2배로 여유가 있다.

## 4. 고장 모델
- 주입 지점: VCU **시동 시퀀스 SWC(PrechargeSeq)**의 프리차지 완료 대기 타임아웃 설정값(`PRECHARGE_TIMEOUT_MS`)이 1500이 아니라 **500**으로 들어감(구성 데이터 오류).
- 정상 vs 고장 (시동 시도 시):

| 항목 | 정상 | 고장 |
|---|---|---|
| 타임아웃 설정 | 1500 ms | 500 ms |
| 500 ms 시점 버스 전압 | 345.9 V (95 % 미달, 아직 정상 진행) | 345.9 V (같음, 물리 응답은 정상) |
| 500 ms 시점 시퀀스 판정 | 계속 대기 | **타임아웃 → PRECHARGE_FAIL** |
| 750 ms 시점 | READY | 이미 실패 상태(READY 안 됨) |
- 달라지는 시점(프리차지 시작 후): 500 ms에 VCU 시퀀스 상태가 갈라짐 → 510 ms 주 접촉기 명령 미출력 → 520 ms READY 신호 미출력 → 1000 ms 클러스터 점검 표시. 버스 전압 곡선은 정상·고장 모두 같다(함정: "전압이 95 %에 못 미침"이 고장처럼 보이지만 500 ms 시점의 정상값이기도 하다).
- 영향 없는 신호: 팩 전압(400 V), BMS 시동 허용(=1), 브레이크 페달(ON), 기어(P), 프리차지 저항·접촉기 응답(곡선이 설계와 같음), 12 V 전원.

## 7. STEP03 데이터
- UI 종류: **블록 조립**(상태 블록 사용). 상태 전이도 채우기 UI는 아직 없으므로(R8 "설계 예정"), 이번에는 기존 블록 조립에 `state` 종류 블록으로 상태 전이를 표현한다. 전용 UI는 후속 사건(C12 등)과 함께 판단한다.
- 요구사항 줄: ① 시동 요청과 브레이크 입력이 있으면 프리차지를 시작한다 ② 버스 전압이 팩 전압의 95 % 이상이 되면 주 접촉기를 닫는다 ③ 프리차지 대기 시간(타임아웃)은 1500 ms이다
- 판: 시동 요청 입력 → 시동 조건 확인 → 프리차지 접촉기 닫기 → **프리차지 대기(전압 95 % 또는 타임아웃)** → **주 접촉기 닫기** → READY
- 빈칸: 프리차지 대기(4번), 주 접촉기 닫기(5번)
- 남은 조각 5개: 프리차지 대기 표 A(타임아웃 1500 ms) · 프리차지 대기 표 B(타임아웃 500 ms, 함정: 같은 블록 다른 표 값) · 주 접촉기 닫기 · 용착 진단(다른 기능 블록, 함정) · 충전 잠금 확인(다른 도메인, 함정)
- 옆 입력(병렬): BMS 시동 허용(=1) → 프리차지 대기 앞 조건
- 함정 조각과 구분 기준: 표 B는 "실행 결과 READY 실패"이고 요구사항은 "1500 ms". 같은 이름이라도 표 값을 비교한다.
- 예시 입력 슬라이더: 이름 "프리차지 경과 시간", 단위 ms, 범위 0~1600, 요구사항 값 750(95 % 도달 시각)
- 시험 설계서: 입력 조건 = 시동 요청 1 · 브레이크 ON · 팩 400 V · BMS 허용 1 · 프리차지 곡선 τ=250 ms, 기대값 = 750 ms 부근에 버스 380 V 이상 + 주 접촉기 명령 + READY=1(허용 ±50 ms), 관측 신호 = 버스 전압·시퀀스 상태·주 접촉기 명령, 목적 = "프리차지 시퀀스 SW와 프리차지 회로(HW) 중 원인 구분"
- "왜 필요한가" 문장: "전압이 충분히 오르기 전에 주 접촉기를 닫으면 돌입 전류가 커서 위험하므로, 충전이 끝날 때까지 기다려야 해요."

  1. 프리차지는 커패시터를 먼저 충전한 뒤 주 접촉기를 닫는 순서예요.
  2. 대기 시간(타임아웃)이 실제 충전 시간보다 짧으면 정상 동작도 실패로 판정돼요.
  3. 진단 코드는 어느 단계에서 실패했는지 알려 주고, 원인은 시험으로 가려요.
