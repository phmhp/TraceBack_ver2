# S01 속도계가 실제보다 높게 나와요  (입문 사건, 레벨 1 후보)

상태: **보관(제외)** — R16/G7: 도주 상황에서 차량 거동에 영향이 없어 게임에서 제외. 규칙 적용 예시 시트로만 보존   작성: 2026-11-14   템플릿: `TEMPLATE_CASE_SHEET.md`
이 시트는 규칙 R1~R15를 적용한 첫 사건 시트입니다. 승인 전에는 코드로 옮기지 않습니다.

## 0. 한 줄 요약
내비게이션 속도는 100 km/h인데 계기판은 113 km/h로 나옵니다 → 클러스터 SW가 타이어 둘레 코딩값을 한 단계 큰 규격 값으로 읽고 있습니다.

## 2. 운전자가 보는 것
- 시점·트리거: **트리거 없음(처음부터 항상)**, 지속성: 영구
- 화면·소리·경고등: 계기판 속도가 내비 속도보다 일정 비율 높음. 경고등 없음. 주행거리 증가도 빠름.
- 이후 흐름: 달리는 데는 지장이 없어 레이싱은 계속된다. 레이싱 구간 중 지정된 지점에서 고양이가 "속도가 이상해요"라고 알리고 차를 세워 조사한다(레벨 시작 브리핑 방식도 가능).
- 운전자 진술: "내비는 100인데 계기판은 113으로 나와요."

## 3. 정상 기준 (요구사항)
- 요구사항: 실제 속도 100 km/h에서 계기판 표시 속도는 103 km/h(설계 +3%)이고 허용 오차는 ±1 km/h이다. 표시 속도는 실제 속도 이상이어야 한다.
- 수치: 실제 v → 표시 = v × 타이어 코딩계수(1.00) × 표시 보정(1.03)

| 실제 속도 | 정상 표시 | 허용 범위 |
|---|---|---|
| 50 | 51.5 | 50.5~52.5 |
| 100 | 103 | 102~104 |
| 150 | 154.5 | 153.5~155.5 |

## 4. 고장 모델
- 주입 지점: 클러스터 속도 표시 SWC의 **타이어 둘레 코딩값** 로드 (코딩 표 항목이 한 단계 큰 규격 값 1.10으로 설정됨)
- 정상 vs 고장 (실제 100 km/h): 코딩계수 1.00 → 1.10, 표시 103 → 113.3 (표시 113)
- 관계식 검산: 100 × 1.10 × 1.03 = 113.3, 정상 100 × 1.00 × 1.03 = 103
- 영향 신호(시험 시작 후 달라지는 시점): 코딩값 로드 0 ms → 변환 출력 20 ms → 표시 갱신 40 ms → 주행거리 적산 증가율 100 ms(함정)
- 영향 없는 신호: ABS 제어기 출력 휠속(100 km/h), 게이트웨이 전달 휠속(100 km/h), 센서 신호

## 6. STEP02 데이터
- 진술: "내비는 100인데 계기판은 113으로 나와요." / 계기판: 경고등 없음, 속도 표시 113 / 관찰 요약: 운전자 체감(속도 표시 높음), 계기판(경고등 없음), 주행 기록(내비 100 km/h), 도로(평지 직선 일정 속도)
- 증상 카드 3장 (R4): 계기판 속도 표시 (기준 103 · 이번 113 km/h, **정답**), 제동 감속 (3.2 · 3.2 m/s²), 조향 반응 (100 · 100 %). 정답은 **2번째**에 배치.

## 7. STEP03 데이터
- UI 종류: 블록 조립
- 요구사항 줄: ① 실제 100 km/h에서 표시는 103 km/h(±1) ② 표시는 실제 속도 이상 ③ 코딩계수는 장착 타이어 규격 값(1.00)을 쓴다
- 판: 휠속 신호(CAN) → 단위 변환 → 타이어 코딩 보정 → 표시 보정(+3%) → 표시 필터 → 속도 표시
- 빈칸: 타이어 코딩 보정(3번), 표시 보정(4번)
- 남은 조각(5개): 타이어 코딩 보정 표 A(1.00) · 표 B(1.10, 큰 휠 규격) · 표시 보정 +3% · 표시 보정 +10% · 평균 필터. 함정 = 같은 블록의 표 B / 다른 값의 보정 (값을 비교하면 구분됨, R8)
- 슬라이더: 실제 속도 0~200 km/h, 요구사항 값 100
- 시험 설계서: 입력 실제 속도 100 km/h 유지 5 s, 기대 표시 103 km/h ±1, 관측 신호(코딩계수, 변환 출력, 표시값)
- 왜 필요한가: "속도는 안전 판단의 기본값이라 표시가 실제와 맞는지 확인해요."

## 8. STEP04 데이터
- 질문(가설별): "휠속 센서 신호가 틀린 건가요?" / "ABS 휠속 계산이 높게 나오는 건가요?" / "표시 필터가 값을 부풀리는 건가요?" / "클러스터 코딩값이 잘못된 건가요?"
- 수준별 관측 신호:
| 신호 | SW 단위 | SW 통합 | 임베디드 | 차량 |
|---|---|---|---|---|
| 코딩계수 로드값 | 보임 | 보임 | 보임 | 안 보임 |
| 변환 출력 | 보임 | 보임 | 보임 | 안 보임 |
| 표시값 | 보임 | 보임 | 보임 | 보임 |
| CAN 휠속 | 입력으로 주입 | 보임 | 보임 | 보임 |
| 내비(GPS) 속도 | - | - | - | 보임 |
- 판정: 코딩 가설은 SW 단위에서 **지지**(코딩계수 1.10), 차량 수준은 **판단 보류**(표시가 높다는 것만 보이고 위치를 못 가름, 다음: SW 단위). 필터 가설은 SW 단위에서 **반박**. ABS·센서는 CAN 휠속으로 **반박**(통합 이상).
- 최종 원인 카드 4개: 가설 4개와 대응(이름·유형·위치·설명)
- 수리 선택지(R10, 정답 위치 **1번째**): ① 타이어 코딩값을 장착 규격 값(1.00)으로 정정하고 코딩 검증 추가(정답) ② 표시 값에 0.91을 곱해 맞추기(증상 가림: 규격이 바뀌면 오차가 다시 생기고 주행거리 적산은 그대로 틀림) ③ ABS 제어기 소프트웨어 재설치(무관: 휠속은 이미 정상)
- 재시험 합격: 같은 입력(100 km/h 유지)에서 표시 103±1, 주행거리 적산 100%. 회귀: 주행거리 적산, 속도 경고음 기준

## 9. 정비소·학습 연결
- 정비소: `adas` 기능 4 클러스터 표시·경고등(SW 구성 StateRx → LampLogic → DisplayDriver 외 표시 변환), `comm` 기능 1 신호 전달
- 오픈북 노트: "클러스터는 CAN 휠속을 단위 변환하고 타이어 코딩 보정과 표시 보정을 거쳐 표시한다. 표시는 실제보다 낮으면 안 된다."
- 배운 원리 3줄: ① 표시값은 신호, 단위 변환, 코딩 설정을 거쳐 만들어진다 ② 신호가 정상이어도 설정이 틀리면 출력이 틀린다 ③ 진단은 의미가 틀린 설정을 못 잡을 수 있다
