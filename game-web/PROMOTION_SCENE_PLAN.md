## 2. 장면별 실행 조건과 캡처 방법

### Scene A — 첫 화면: 고양이 듀오와 붉은 EV

- 목적: 1초 안에 세계관·캐릭터·차량을 전달
- **[확인] 화면 조건**: 앱 초기 `state.scene === "TITLE"`; `Title`이 `stitch23/menu-garage.png`를 배경으로 사용하고, `ASSET_003_Cat_Face_Identity_REFERENCE.png`를 로고 옆에 표시한다.
- 코드 위치: `src/main.tsx:507-582`, 앱 분기 `src/main.tsx:1513`.
- 사용 에셋:
  - `public/assets/stitch23/menu-garage.png` — 1376×768 PNG
  - `public/assets/ASSET_003_Cat_Face_Identity_REFERENCE.png` — 1276×1233 PNG
- 캡처 방법: 앱을 새로 열어 저장 상태가 없어도 타이틀이 보이는지 확인하고, 16:9 한 장 캡처. 현재 조사에서는 브라우저 실행을 하지 않았다.
- GIF 가능 여부: **[제안] 낮음**. 정적 히어로에 쓰고, 버튼 hover나 CSS 효과는 홍보 페이지에서 별도 적용.

### Scene B — 첫 추격: 경찰차가 붙는 해안 도로

- 목적: 게임의 즉각적인 긴장과 자동차 플레이를 전달
- **[확인] 실행 조건**: `DRIVE_BRIEFING`에서 준비가 끝난 후 `BEGIN_RACE`를 보내면 `CHASE_NORMAL`; 일반 모드에서 경과 3초·거리 45m 이후 경찰차가 합류한다.
- 코드 위치: 실제 브리핑은 `src/features/cutscenes/StaticCutscenes.tsx:24-68`, 주행은 `src/experiences.tsx:1692-2179`, 특히 `1974-1979`.
- 화면 요소: Three.js `RaceWorld`, 붉은 EV, 경찰 인터셉터, 추격 격차 HUD, 미니맵, 속도/열/기어 표시.
- 캡처 방법:
  1. `DRIVE_BRIEFING`에서 `도주 시작`.
  2. D단·가속 입력으로 45m 이상 주행.
  3. 경찰차와 플레이어 차량이 함께 보이고 `PursuitRouteBar`가 표시되는 순간을 캡처.
  4. 재현성 있는 GIF는 같은 조건에서 4~6초 녹화.
- GIF 가능 여부: **[확인] 높음**. rAF 기반 주행·차량 이동·HUD 숫자 변화·경찰 합류가 코드에 있다.
- 주의: 홍보 GIF에서는 실제 조작 키보다 장면의 추격과 차량 간격을 우선 보여주고, 소리는 선택 사항으로 둔다.

### Scene C — 고양이 강조: 운전자·엔지니어의 반응

- 목적: 공학 설명이 캐릭터 서사로 이어진다는 점을 전달
- **[확인] 사용 위치**:
  - 타이틀: `src/main.tsx:519-522`
  - 프롤로그 대화: `src/main.tsx:584-623`
  - 추리/퍼즐/검증 안내: `src/features/board/EeTrace.tsx:378`, `src/features/wiring/RefPuzzle.tsx:502`, `src/features/verification/VerificationLab.tsx:528`
  - 수리 완료: `src/experiences.tsx:3097-3100`
- 사용 에셋: `ASSET_003...`, `cutscene-character-master-v1.png`, `cutscene-repair-v1.png`.
- 캡처 방법: 타이틀의 얼굴은 가장 안전한 정적 컷. 감정 변화는 `FAULT_CUE`에서 운전자 대사 → 엔지니어 대사 순으로 2장 캡처하거나 화면 녹화.
- GIF 가능 여부: **[제안] 중간**. 런타임 캐릭터 표정 자체보다 대사 패널/반응 말풍선의 전환을 GIF로 만드는 편이 안정적.
- 주의: 코드에는 단일 얼굴 에셋이 반복 사용된다. 별도 감정별 고양이 파일이 실제로 존재한다고 홍보하지 않는다.

### Scene D — 도미노 추적: 첫 편차 찾기

- 목적: 게임의 추리 퍼즐을 한 프레임으로 설명
- **[확인] 실행 조건**: `FAULT_CUE`에서 계속 → `CONTINUE_FAULT` → `BOARD`; `main.tsx`의 실제 라이브 컴포넌트는 `EeTraceV2`다.
- 코드 위치: `src/game/runtime.ts:295-305`, `src/main.tsx:1530`, `src/features/board/EeTrace.tsx:331-566`.
- 플레이어 행동: 출력 선택 → 앞 신호 측정 → 정상/이상 스탬프 확인 → 의심 구간 선택 → 가설을 반박/보류/시험 후보로 분류.
- 추천 캡처 순서:
  1. `도미노 판`의 신호 경로가 모두 보이는 기본 화면.
  2. 기준/이번 값이 함께 표시된 카드 확대.
  3. `첫 편차`와 `의심 구간`이 강조된 결과 화면.
- GIF 가능 여부: **[확인] 높음**. 단계별 상태와 카드/도크 변화가 있고, 측정 결과가 순차적으로 표시된다.
- **[캡처 필요]** `--help/27_evidence_board.png`는 기존 실행 캡처지만, 현재 라이브 마운트가 `EeTraceV2`인지 같은 화면인지 재확인 후 사용.

### Scene E — 정상 로직 조립: 퍼즐이 값으로 실행됨

- 목적: “추리만 하는 게임”이 아니라 정상 기준을 직접 구성한다는 점 전달
- **[확인] 실행 조건**: `BOARD`에서 `OPEN_WIRING` → 빈칸에 조각 배치 → 모든 빈칸 채움 → `▶ 실행해서 확인`.
- 코드 위치: `src/game/runtime.ts:320-333`, `src/features/wiring/RefPuzzle.tsx:384-507, 714-773`.
- 시각 포인트: HW/SW 블록, 요구사항 카드, 값이 슬롯을 따라 이동, 첫 불일치에서 멈춤, PASS 후 `다음: 시뮬레이션 검증`.
- 캡처 방법: 정답을 미리 노출하지 않도록 ① 빈칸 상태 ② 실행 중 ③ 첫 불일치 또는 PASS 중 하나만 선택. 홍보에는 PASS 장면보다 실행 중 흐름이 더 매력적.
- GIF 가능 여부: **[확인] 높음**. `run.status`가 `running/fail/pass`로 바뀌고 슬롯별 pulse가 있다.
- **[제안]** GIF에는 블록이 화면 밖으로 드래그되는 동작보다, 이미 조립된 퍼즐의 값 흐름을 크게 잡는다.

### Scene F — 실험 검증: 정상과 고장 비교

- 목적: 학습 가치와 개발 방법을 한 장면으로 설명
- **[확인] 실행 조건**: `WIRING`에서 설계서 확정 → `OPEN_BENCH` → `TWIN_BENCH`에서 시험 조건을 선택하고 실행.
- 코드 위치: `src/features/verification/VerificationLab.tsx:1719-2301`, 수치 모델 `src/features/verification/simModel.ts:1-371`.
- 플레이어 행동: 시험 레벨/기법 선택, 입력 조건 확인, 관측 신호 선택, 정상·고장/수정 결과 비교, 원인 판정.
- 추천 캡처: 그래프에서 점선 기준선과 실선 실행선이 처음 갈라지는 시점, `PASS` 또는 `FAIL` 스탬프, 고양이의 짧은 해설을 한 화면에 넣는다.
- GIF 가능 여부: **[확인] 높음**. 실행 버튼, 모니터 그래프, 결과 상태가 순차 변한다.
- 주의: “실제 ECU 시험”이라고 쓰지 말고 **웹 기반 시뮬레이션 검증** 또는 **정상/고장 모델 비교 실험**으로 표기.

### Scene G — 마지막 플레이 유도: 램프 도약과 해적선 착지

- 목적: 스크롤 끝에서 실제 플레이를 누르게 만들기
- **[확인] 실행 조건**: `SHIP_ESCAPE`에서 거리 1080m 이상으로 `FINISH_ESCAPE` → 엔딩. 별도 `SHIP_BOARDING` 장면은 두 프레임이 각각 4.5초 후 전환되며 클릭도 허용.
- 코드 위치: 주행 램프/거리 조건은 `src/experiences.tsx:1300-1350, 2034-2051`, 컷신 전환은 `src/features/cutscenes/StaticCutscenes.tsx:106-130`, 상태 전이는 `src/game/runtime.ts:391-404`.
- 사용 에셋: `cutscene-ship-jump-v1.png` 1672×941, `cutscene-ship-land-v1.png` 1672×941, `stitch23/ship-escape.png` 1376×768.
- 캡처 방법: 도약 프레임과 착지 프레임을 각각 한 장, 또는 두 프레임 전환을 5~7초 GIF. GIF 끝에 `직접 플레이` 버튼을 덧붙인다.
- GIF 가능 여부: **[확인] 높음**. 별도 컷신 타이머와 Three.js `ShipJumpScene`이 존재.

## 3. 홍보 페이지에 넣지 않을 장면

- **[미구현/미확인]** 모바일 터치만으로 레이싱을 완주하는 장면. 현재 레이싱 입력은 키보드 이벤트 중심이다.
- **[미구현/미확인]** 실제 차량·실 ECU·실제 HIL 장비를 연결한 검증 장면. 현재는 코드 기반 웹 시뮬레이션이다.
- **[미확인]** 감정별 고양이 표정이 다수 준비되어 있다는 주장. 현재 대표 얼굴 에셋이 반복 사용되고, `cat-expr`는 코드 주석에만 언급된다.
- **[미확인]** 모든 과거 `--help` 캡처가 현재 라이브 화면과 같다는 주장. `main.tsx` 주석상 일부 레거시 컴포넌트가 보존되어 있다.

## 4. GIF 제작 체크리스트

### [제안] 공통 규칙

- 4~7초, 무음 기본, 16:9 원본과 4:5/9:16 crop을 별도로 만든다.
- 텍스트는 GIF 안에 많이 넣지 않고, 장면 바깥의 짧은 캡션으로 둔다.
- `prefers-reduced-motion` 사용자를 위해 모든 GIF에 정적 poster를 같이 둔다.
- 게임 화면 녹화본과 홍보 페이지용 합성본을 구분한다. 합성본은 기존 게임 소스를 수정하지 않고 별도 페이지에서 만든다.

### [제안] 제작 우선순위

1. 추격: 경찰차가 합류하는 5초
2. 도미노: 첫 편차가 강조되는 5초
3. 퍼즐: 값이 블록을 통과하는 5초
4. 벤치: 기준선과 실행선이 갈라지는 5초
5. 엔딩: 램프 도약 → 착지 6초
