## 검증 여권을 게임으로 푸는 방식

플레이어에게 ID나 커버리지 표를 직접 작성시키지 않는다. 각 시험 실행 결과를 게임이 자동으로 도장처럼 누적한다.

1. 요구사항 ID: 사건마다 한 개의 대표 ID만 전면에 노출한다.
2. 기대값/실제값: 정상 설계와 내 설계를 실행하면 자동 기록한다.
3. 최초 불일치 경계: 플레이어가 찾는 정답이 아니라 실험 결과 보상으로 공개한다.
4. 커버리지: `SW → 임베디드 → 차량` 세 시험을 실행할 때 1/3, 2/3, 3/3 도장으로 표시한다.
5. 상세 리포트: 평소에는 닫혀 있고 `검증 여권`을 눌렀을 때만 열린다.

이 구조면 추리/배선 조작을 늘리지 않으면서도 실무의 추적성 사고를 남길 수 있다.

## 기술적 관점 정리

- 차량 시스템: 운전자/환경의 요구가 어떤 차량 기능과 실제 거동으로 이어지는지 본다.
- E/E 아키텍처: 센서, ECU, 네트워크, 전기 I/O와 액추에이터 명령의 배치를 본다.
- SW 로직: 신호 유효성, 상태, 계산, 제한, 중재와 출력값을 본다.
- 물리 플랜트: 토크·압력·힘이 기계 전달계를 거쳐 실제 움직임이 되는 경계 모델이다.

게임에서는 첫 3개를 선택 가능한 학습 관점으로 쓰고, 물리 플랜트는 입출력 경계를 설명하는 공통 레이어로 두는 것이 난이도와 정확성의 균형이 가장 좋다.

## 검증 명칭

- SW 탭: 브라우저 실행 모델 기반 MIL/SIL 개념 학습
- 임베디드 탭: ECU I/O·하니스·Plant 통합 시뮬레이션(HIL 개념 학습)
- 차량 탭: 요구사항 기반 차량 수준 시나리오 검증

현재 웹 3D 실험은 실제 ECU와 실시간 하드웨어가 없으므로 엄밀한 HIL이라고 부르지 않고 `HIL 학습 모델`로만 표시한다.
