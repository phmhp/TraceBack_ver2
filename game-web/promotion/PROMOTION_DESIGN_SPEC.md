# TraceBack 홍보 랜딩페이지 디자인 명세

## 방향

TraceBack을 기능 목록이 아니라 **자동차 도메인 학습과 검증 사고를 추격 게임으로 경험하는 교육 프로토타입**으로 보여준다. 페이지는 “왜 만들었는가”를 초반에 명확히 밝힌 뒤, 상황 → 학습 흐름 → 추격 → 추리 → 실험 → 제작 과정 → 플레이 유도의 순서로 이어진다.

## 시각 언어

- 바탕: 딥 네이비와 블랙
- 강조: 게임 에셋과 맞춘 레이싱 레드
- 보조: 경고를 연상시키는 옐로
- 텍스트: 짧은 헤드라인, 모노스페이스 메타 정보, 소프트 그레이 설명
- 레이아웃: 풀스크린 이미지, 비대칭 분할, 증거 보드 중첩, 컷신 프레임 콜라주

과도한 네온, 무의미한 파티클, 반복 카드, 외부 스톡 이미지, 실제 구현으로 오인될 수 있는 가상 UI는 사용하지 않는다.

## 카피 원칙

- 한 화면에 한 메시지만 둔다.
- 실제 게임 대사와 홍보용 카피를 구분한다.
- “실제 ECU/HIL”, “AI가 전부 자동 개발” 같은 검증되지 않은 표현은 사용하지 않는다.
- 검증 섹션은 **웹 기반 시뮬레이션 검증**으로 표현한다.
- 모바일에서는 게임을 모바일로 플레이할 수 있다고 암시하지 않고 PC 권장 문구를 둔다.

## 페이지 내 게임 실행

독립형 랜딩페이지에는 same-origin 게임 실행 모달을 넣었다. 기본값 `promotion/landing/`에서 `../../?embed=1`을 불러오므로 `game-web` 루트가 같은 호스트에서 Vite 또는 정적 빌드로 제공될 때 페이지 안에서 게임을 열 수 있다. 홍보 폴더만 별도 호스팅하는 경우에는 `landing/script.js`의 `GAME_URL`을 실제 게임 배포 주소로 교체한다.

사내 게시판 버전은 iframe·JS를 사용하지 않으므로 페이지 안 게임 실행을 제공하지 않고, 실제 게임 URL을 받은 뒤 링크로 연결하는 구조로 둔다.

## 반응형 원칙

- 데스크톱: 7개 장면의 이미지 비중과 비대칭 여백을 유지한다.
- 태블릿: 2열 레이아웃을 필요한 곳에서 1열로 전환한다.
- 모바일: 제목 → 대표 이미지 → CTA 순서를 우선하고, 원본 16:9 이미지를 단순 축소하지 않고 `object-position`과 crop으로 재구성한다.
- 모바일에서는 추격 HUD와 증거 카드 정보를 최소 단위로 줄인다.
- `prefers-reduced-motion`에서는 등장·패럴랙스·펄스 효과를 제거한다.
