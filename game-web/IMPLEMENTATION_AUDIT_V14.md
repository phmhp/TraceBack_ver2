# TraceBack V14 구현·개념 검수

## 올바른 개념 축

- **차량 시스템**이 최상위 학습 대상이다.
- **구동·제동·조향·전원·기어·열관리·현가**는 차량 시스템을 기능적으로 분해한 도메인이다.
- **Vehicle/System · E/E Architecture · Control Software**는 도메인 아래의 소속 단계가 아니라, 선택한 차량 기능을 서로 다른 경계에서 보는 **독립된 관점 축**이다.
- 물리 플랜트는 네 번째 SW 상세 단계가 아니다. 제어기 바깥에서 토크·압력·열·운동을 만드는 환경/대상 모델이다.
- 퍼즐은 전체 차량 아키텍처를 재배선하는 문제가 아니라, 한 고장에 직접 관련된 **기능 슬라이스**의 관찰 경계를 복원한다.

## 검증 구조 검수

기존 `SW → 임베디드 → 차량` 3단계는 ECU 간 상호작용을 건너뛰었다. V14는 다음 네 경계를 사용한다.

1. **SW** — 제어 모델/코드의 입력 검증, 상태, 계산, 제한, 출력, 피드백 추적(MIL/SIL 개념)
2. **ECU 통합** — 실제 제어기 I/O와 하니스, 가상 Plant의 폐루프 반응(HIL 개념)
3. **차량 시스템** — 여러 ECU와 차량 기능/네트워크 통합
4. **차량 시나리오** — 주행 조건에서 최종 요구 성능 확인

`요구사항 기반 다계층 검증`은 방향은 맞지만 너무 넓은 이름이었다. 화면 명칭을 **요구사항 기반 V-모델 검증 실험실**로 바꾸고, 모든 결과를 별도 TC 패널에 모았다. TC 패널은 요구사항 ID, 시험 기법, 인가값, 기대값, 실제값, 판정을 한 영역에서 보여준다. 플레이어는 요구사항 기반/경계값/고장 주입과 정상값/한계값을 직접 고른다. 실제 ECU와 실시간 Plant가 없는 웹게임이므로 HIL/MIL/SIL은 자격 판정이 아니라 개념 학습으로 명시한다.

## 요청 30개 반영표

1. 차체를 직육면체에서 4.70 × 1.85 × 1.45m 세단 비율의 후드-캐빈-데크 연속 실루엣으로 교체.
2. 배터리팩·HV·LV 하네스를 승객 공간 아래로 이동. 주 하네스와 제어기 분기 하네스를 다대다 구조로 교체.
3. 차고지 하단 기능 흐름을 남는 폭 없이 확장하고 진행 버튼을 같은 그리드에 편입.
4. 차량 시스템/도메인/관점의 상하·직교 관계를 위와 같이 재정의하고 UI에 `ORTHOGONAL AXIS`로 표시.
5. 탈출 장면의 검은 마스크를 제거하고 큰 머리/작은 몸 비율, 분리된 두 고양이, 양손 금괴 자루, 열리는 양문을 적용.
6. 활성 레이싱에서 이전 단계 버튼을 제거하고, 배선 화면에서는 제목과 버튼 영역을 분리.
7. 부두의 해수 영역을 벗어나면 차체가 기울며 침수하고 HV 차단/절연 점검 메시지 후 이어서 하기로 전환.
8. 적색 신호 정차와 READY 재시동(R) 운전 미션을 두 필수 고장 사이에 추가.
9. 확대 폴라로이드의 사진 영역에 중복 흰 테두리가 생기지 않고 프레임 창을 꽉 채우도록 수정.
10. 손=이동/선택/확대, 연필=선 연결, 지우개=선 삭제로 권한 분리.
11. 첨부한 펼친 장갑 손을 투명 64px 커서로 적용.
12. 드래그 중 첨부한 쥔 장갑 손 커서로 전환.
13. 연필 도구에서 연필 PNG 커서 적용.
14. 지우개 도구에서 지우개 PNG 커서 적용.
15. 제어 경로 복원의 이전 단계 버튼과 제목 좌표를 분리.
16. 관점 태그를 도메인·기능명 앞에 크게 배치하고 호버/포커스 도움말을 최상위 레이어에 표시.
17. 제어 경로 복원의 기본 이동 도구도 장갑 손 커서 적용.
18. 삼각 포트를 제거하고 첫 폴라로이드→다음 폴라로이드 클릭으로 연결.
19. 제어 경로 카드에 실제 폴라로이드 프레임, 손 도구 이동, 더블클릭 확대 적용.
20. SW 검증을 단순 일렬 카드에서 분기·폐루프 피드백이 있는 Simulink/flowchart형 실행 모델로 교체.
21. 임베디드 화면을 더 멀리 잡고 입력 센서/실 ECU+I/O/출력 액추에이터 경계를 상시 표기. 중복 하단 테이블 제거.
22. 각 탭에 흩어졌던 t0/t1/Actual/요구·응답을 하단 TC 영역으로 통합.
23. SW→ECU 통합→차량 시스템→차량 시나리오 4단계와 시험 기법/인가값 선택을 추가.
24. 검증 여권 버튼·팝업 제거.
25. 사용자 노출 `체크포인트` 문구를 `이어서 하기`로 교체.
26. D1/D2/D3 상한과 가속을 높이고 일반 차량 충돌 시 상대 속도·반발을 반영.
27. 일반 차량 위치·회전을 프레임 보간해 덜덜거림 제거.
28. 경찰차 속도를 플레이어 속도 기반 68~88km/h로 낮추고 시작 격차를 185m, 수리 후 격차를 105/115m 이상으로 조정.
29. 결승 트리거를 램프 전에 고정해 기존 해적선 바닥 낙하 경로를 차단.
30. 나무 연결판 상승→붉은 EV 도약→측면 카메라→경찰차 부두 정지→해적선 갑판 착지→엔딩의 독립 3D 시퀀스로 교체.

## 실차 구조 근거

- 고전압 배터리는 중앙 바닥, 구동 유닛은 전/후축, 고전압 계통은 하부/측면 보호 경로를 따른다.
- 인버터는 구동 유닛과 통합될 수 있으며 충전·DC/DC·열관리 부하는 단일 직렬선이 아니라 HV 분기 구조를 사용한다.
- 저전압 하네스는 차체 좌/우, 전면, 대시, 도어, 서브프레임 등 여러 독립 하네스와 다수 커넥터로 분기된다.
- 따라서 교육 화면은 `모든 부품이 한 줄로 직렬 연결`된 모형과 `현재 기능의 활성 신호 경로`를 구분해야 한다. V14의 복수 하네스는 실제 네트워크 구조, 강조 케이블은 현재 학습 기능의 추적 경로를 뜻한다.
