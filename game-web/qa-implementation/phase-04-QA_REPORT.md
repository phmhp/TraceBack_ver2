# 단계 4 Chrome QA — STEP03 검증 준비 계약

## 실행 환경

- 대상: `http://127.0.0.1:5173/?qa=WIRING`
- 브라우저: 설치된 Google Chrome, 1054×723
- 사건: 대표 구동 가속 출력 저하

## 확인 장면

- `phase-04-final-intro`: STEP03 최초 진입 팝업
- `phase-04-final-before`: 문제 풀이 전 기존 로직 퍼즐과 조각 보관함
- `phase-04-final-after`: 연결 확인·정상 기준 확정 후 화면
- `phase-04-final-contract`: STEP03이 만든 STEP04 실행 계약 팝업

## 구현·상호작용 검수

- 기존 RefPuzzle의 드래그/클릭 배치, 연결 확인, 예시 입력, 기준 확정 흐름을 보존했다.
- 기준 확정 시 가설 ID/명칭, 목적, 의심 구간, 초기 조건, 입력 시퀀스, 기대값, 관찰점, 동일 조건 비교 설정, 결론 한계를 하나의 타입 계약으로 저장한다.
- STEP04는 저장된 계약을 읽고 상단에 `STEP03 계약`으로 표시하며, 직접 QA 진입 시에만 명시적 fallback을 사용한다.
- 계약은 결과 하나로 근본 원인을 자동 확정하지 않는다는 한계를 화면에 표시한다.

## UI 결함과 조치

- 최초 계약 캡처에서 구형 QA 가설 ID가 최신 메타 가설과 달라 `선택 가설 가설` 중복 문구가 보였다.
- 레거시 사건 가설 목록까지 조회하도록 정규화하고 제목 문장을 수정했다.
- 재캡처에서 전체 6개 계약 필드와 버튼이 팝업 안에 보이며 다른 레이어와 겹치지 않았다.
