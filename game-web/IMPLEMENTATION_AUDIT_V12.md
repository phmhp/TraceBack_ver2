## 교육 구조 검수 — 인지 능력 80~90 수준의 초심자 기준

### 적절해진 부분

1. **관점과 깊이를 분리했다.** Vehicle/System은 운전자 요구와 차량 거동, E/E는 센서·ECU·네트워크·액추에이터, Control Software는 신호 검증·상태·계산·보호·출력으로 구분한다.
2. **도메인과 기능을 분리했다.** 구동/제동 같은 도메인 안에 여러 형제 기능이 있고, 기능이 단순히 앞뒤 순서로 이어지는 것이 아님을 명시한다.
3. **관찰→가설→설계→검증 순서를 사용한다.** 주행 증상, 진단 증거, 원인 가설, 제어 경로, SW/통합/차량 수준 확인으로 이어져 검증적 사고 연습에 적합하다.
4. **구체물에서 추상 개념으로 이동한다.** 페달·핸들·센서 같은 물리 입력을 먼저 보여준 뒤 ECU와 SW 로직으로 내려가므로 초심자의 인지 부담을 낮춘다.
5. **정답 이외의 후보를 남긴다.** 모든 카드를 쓰지 않는다는 규칙과 오류 후보 블록이 있어 단순 분류가 아니라 근거 선택을 요구한다.

### 아직 교육용으로 주의할 부분

1. 한 플레이에서 7개 도메인을 모두 암기시키면 과부하가 크다. 첫 플레이의 필수 관찰은 구동·제동·조향·전원으로 제한하고, 기어·열관리·현가는 자유 탐색으로 두는 편이 좋다.
2. SIL은 생성 코드를 컴파일해 호스트에서 실행해야 정확한 용어다. 현재 브라우저 시각화는 `SIL 학습 모델`이며 실제 SIL 결과라고 부르면 안 된다.
3. HIL은 실제 제어기 하드웨어와 실시간 Plant 시뮬레이터가 연결되어야 한다. 현재 단계는 I/O·하니스·Plant 경계 이해를 위한 교육 시뮬레이션이다.
4. ISO 26262 준수나 실무 검증 완료를 주장할 수준은 아니다. 요구사항 추적, 테스트 케이스·기대값, 커버리지, 타이밍/고장 주입, 결과 리포트가 추가되어야 한다.
5. 자동차 실무에 직접 도움이 되려면 다음 버전에서 각 퍼즐 결과에 `요구사항 ID → 테스트 입력 → 기대값 → 실제값 → 판정 → 최초 불일치 경계`를 저장하는 리포트가 필요하다.

## 기술 용어 기준

- AUTOSAR 관점에서 Application, RTE, BSW와 센서/액추에이터 I/O의 분리는 유효하지만, 차량 시스템→E/E→기능 SW→물리 Plant는 AUTOSAR 계층을 그대로 번역한 것이 아니라 교육용 관점 프레임이다.
- MIL은 제어기와 Plant 모델을 이용한 모델 수준 확인, SIL은 컴파일된 제어 SW를 호스트에서 실행한 확인, HIL은 실제 제어기 하드웨어와 실시간 Plant의 결합으로 설명해야 한다.
- ISO 26262-6은 SW 아키텍처 설계, SW 단위 검증, SW 통합·검증, 임베디드 SW 시험을 구분하므로 게임의 세 탭은 해당 활동을 쉽게 소개하는 입문 구조로 사용한다.
